### 2.3 建议（3）

#### S1 footer 条件注释已过期

- 位置：`flutter_app/lib/widgets/welcome_dialog.dart:89-92`
- 证据：`showConfigureAi` 的注释仍写「为 `false` 时整段不渲染，footer 高度与改动前一致」。但版本行在 footer 的 `Column` 末尾无条件追加（307-319 行），`false` 时 footer 由改动前的 80dp 变为 107.6dp，`true` 时由 136dp 变为 163.6dp；新增测试已按新值断言。
- 风险：后续维护者/测试按旧注释理解条件分支，容易把版本行带来的 27.6dp 增高误判为回归；注释与代码事实不一致。
- 方向：把注释改为「为 `false` 时只隐藏『去配置AI』，footer 仍保留主按钮 + 版本行（约 107.6dp）；`true` 时约 163.6dp」，或删掉注释里的高度承诺。

#### S2 `v` 前缀可能重复

- 位置：`flutter_app/lib/app_version.dart:16`
- 证据：`return 'v$trimmed';` 无条件加前缀，`formatVersionLabel('v1.2.3')` 会得到 `vv1.2.3`。当前 `pubspec.yaml` 为 `0.1.0+1`，正常路径不触发。
- 风险：Android `versionName` 是自由字符串；若未来发版写成 `v1.2.3`，弹窗会显示畸形版本号。`formatVersionLabel` 是公开函数，其他调用方也可能传入带前缀值。
- 方向：先剥离一个已有的 `v`/`V` 前缀再加；或在函数文档和测试中明确禁止带前缀输入并加断言。建议补一条 `'v1.2.3'` 用例固化预期。

#### S3 catch-all 吞掉 `Error`

- 位置：`flutter_app/lib/app_version.dart:38-45`
- 证据：`resolve()` 用 `catch (_)` 捕获所有 `Object`，包括 `Error`（loader 内的类型错误、断言失败等）；异常被静默替换为 `v1.0.0`，不记录日志。
- 风险：编程错误被当作「版本读取失败」吞掉，排查困难；未来重构 loader 时可能长期显示回退值而无人发现。
- 方向：收窄为 `on Exception`（`TimeoutException`、`PlatformException`、`MissingPluginException` 都是 `Exception`）；若坚持「任何失败都不影响弹窗」，至少在 debug 下 `assert` 或输出 debug 日志保留可观测性。该取舍与技术方案 §5.2「所有 `Object` 一律吞掉、不记录日志」有关，建议开发确认。
