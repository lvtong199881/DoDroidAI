# 技术方案：欢迎弹窗右上角关闭按钮

> 需求：qj7pdv9x　平台：Android（Flutter）　阶段：技术方案
> 上游：`PRD.md`（REQ 编号）、`需求卡片.md`（AC 编号）、`设计说明.md`（视觉/几何）
> 代码基线：主仓库 main（`02cff72`），应用根目录 `flutter_app/`，Flutter 3.50.1 / Dart SDK ^3.13.7
> 说明：本文件只定方案，不含实现代码，未改动项目任何源码、配置、资源或测试。

## 1. 方案结论

- 关闭按钮是**欢迎弹窗的固定角标**：32×32dp 圆形、48×48dp 命中，圆心与弹窗卡片矩形右上角重合，右/上各露出 16dp（各 50%）。
- 现有路由与关闭链路**不动**：仍用 `showDialog<WelcomeDismissMethod>`，仍由 `WelcomeController` 记录 `welcome_dismissed`，`closeButton` 只是 `WelcomeDismissMethod` 的新取值。
- 为让「半露出 + 外露部分可点」成立，把 `Dialog` 拆成**透明外壳 + 内层卡片 + 角标**三层：外壳只负责路由/遮罩/居中，卡片负责原有背景、圆角、阴影与裁切，角标作为卡片兄弟节点绘制在裁切之外、层级高于卡片内容。
- 卡片几何与现状逐项对齐：宽 = 屏幕宽 − 40dp、水平边距 20dp、垂直居中、最大高度 80%、圆角 16dp、欢迎图贴边 2:1；因此既有布局、滚动、深浅色、双按钮分支都不需要重排。
- 关闭按钮与「开始使用」「去配置AI」共用同一个 `_close(method)` 入口，天然复用现有 `_closing` 连点保护，只 pop 一次。
- 无欢迎图时内容区顶部预留 56dp（内容 padding 顶部由 20dp 改为 76dp），按钮位置不变，标题与按钮净距 60dp。

## 3. 现状与约束

### 3.1 现有链路（改动前）

1. `lib/screens/chat/chat_screen.dart` 的 `_presentWelcome`：`showDialog<WelcomeDismissMethod>(barrierDismissible: false, useRootNavigator: true)` → `WelcomeDialog(showConfigureAi: ...)`；`closing` 为 null 时宿主映射为 `WelcomeDismissMethod.back`，并计算 `visibleMs`。
2. `lib/widgets/welcome_dialog.dart`：`Dialog(backgroundColor: scheme.surface, elevation: 6, insetPadding: 20/24, shape: 16 圆角, clipBehavior: Clip.antiAlias)` → `ConstrainedBox(maxHeight: 0.8H, key: welcome_dialog_root)` → `Column`：`Flexible(SingleChildScrollView(hero → 标题/副标题))` + 固定 footer（可选「去配置AI」+「开始使用」）。
3. `lib/settings/welcome_contract.dart`：`WelcomeDismissMethod { button, back, configureAi }`，`wire` 为 `button/back/configure_ai`；`WelcomeDismissResult { method, visibleMs }`。
4. `lib/settings/welcome_controller.dart`：先写一次性标记再展示；`presenter` 返回后记 `dismissed`；`configureAi` 触发 `onConfigureAi`；异常记 `render`。
5. `lib/settings/welcome_log.dart`：`welcome_dismissed method=<wire> visible_ms=<int>`，`kDebugMode` 下 `debugPrint`。
6. `lib/l10n/app_strings.dart`：`_values['zh'|'en']` 的扁平 key 表，`t()` 对非 en 回退 zh。

现有测试对弹窗的依赖点：`welcome_dialog_test.dart` 用「`Dialog` 下的第一个 `Material`」当弹窗矩形（`dialogSurfaceRect`），并断言 `Dialog` 的 `clipBehavior/shape/backgroundColor`；第 187 行断言「没有 `Icons.close`」。这些在方案里都要按新结构更新（PRD 已明确要求更新既有「没有关闭按钮」断言）。

### 3.2 Flutter 既有约束（已核对本机 SDK 源码）

- `Dialog` = `AnimatedPadding(insetPadding/viewInsets)` → `Align` → `ConstrainedBox(minWidth: 280)` → `Material(shape, clipBehavior)`。`Material` 会把 child 裁到圆角形状内，因此**按钮不能放在卡片 Material 的 child 里**。
- `Stack`/`Material` 的 `clipBehavior: Clip.none` 允许 child 画到自身边界外；但 `RenderBox` 的命中测试仍以自身尺寸为界，所以角标所在的 `Stack` 必须把 48dp 命中盒完整包进自己的边界（见 §4.3 的几何）。
- `Dialog` 的 `insetPadding` 参与外层可用宽高计算，改用 0 后需由内层自行留出 20dp 水平边距，才能保持卡片宽度不变。

### 3.3 明确不做

- 不改欢迎图/标题/副标题/主按钮/次按钮的文案与样式；不改一次性标记、写标记时机、`runOnce` 单飞、启动入口判定。
- 不新增页面、路由类型、权限、数据库/存储结构、埋点、第三方依赖、图片资源。
- 不做全局无障碍改造；不给其它弹窗加关闭按钮。

## 4. 技术方案

### 4.1 结构总览

```
Dialog(                               // 仍由 showDialog 创建，barrier/route 不变
  insetPadding: EdgeInsets.zero,      // 边距下放到内层，保证卡片宽度仍为 屏宽-40
  backgroundColor: 透明, elevation: 0,
  clipBehavior: Clip.none,
  child: Stack(clipBehavior: Clip.none)          // 尺寸 = 卡片 + 左右20 + 上下24
    ├─ Padding(horizontal: 20, vertical: 24)
    │    └─ Material(key: welcome_dialog_card,   // 可见的「弹窗矩形」
    │         color: scheme.surface, elevation: 6,
    │         shape: 16dp 圆角, clipBehavior: Clip.antiAlias)
    │         └─ ConstrainedBox(key: welcome_dialog_root, maxHeight: 0.8H)
    │              └─ Column( scroll[hero, title, subtitle], footer )   // 逐字保留
    └─ Positioned(top: 0, right: -4)             // 圆心 = 卡片右上角
         └─ Semantics(key: welcome_dialog_close, 48×48, button, label, onTap)
              └─ SizedBox(48×48)
                   └─ Center → 32×32 视觉圆(key: welcome_dialog_close_visual)
```

- **弹窗矩形**（AC 术语）= `welcome_dialog_card` 的 Material 盒子；AC-1/2/6/8 都用它。
- **外壳透明**只承担居中与命中层；可见背景/阴影/圆角/裁切全部下移到卡片，视觉与现状一致。
- **角标是卡片的兄弟节点**，绘制顺序在卡片之后：不被卡片圆角裁切，且高于欢迎图、滚动文字与卡片背景；整条路由又在 barrier 之上，因此也高于遮罩。

### 4.2 为什么选这个结构

| 备选 | 否决原因 |
| --- | --- |
| 把按钮放进卡片 `Stack` 并负偏移 | 卡片 `Material` 的 `Clip.antiAlias` 会裁掉外露的一半；且 `Stack` 的命中测试被卡片尺寸截断，外露部分点不到（直接违反 AC-1/AC-3） |
| `OverlayEntry`/`CompositedTransformFollower` 浮在路由上 | 按钮脱离 `DialogRoute` 的 `Semantics(scopesRoute/explicitChildNodes)` 语义树，TalkBack 聚焦顺序与模态语义都不可控（AC-14 风险）；还要处理主题重建与 entry 生命周期 |
| 改用 `showGeneralDialog` 自绘全屏层 | 新增路由类型、需自行复刻 barrier 颜色/语义/过场，返回键与遮罩行为都要重新验证，违反「不新增路由、旧出口不动」 |
| 全屏 `CustomMultiChildLayout` 精确定位 | 能实现，但为 4dp 命中余量引入自定义布局委托，维护成本高于收益 |
| **透明外壳 + 内层卡片 + 角标兄弟节点（采用）** | 单次布局、无测量回调、无新路由/Overlay；卡片几何与现状一一对应；角标自然位于裁切之外、语义树之内 |

### 4.3 几何定稿

常量（实现为 `welcome_dialog.dart` 顶层 `const`，测试直接引用）：

| 名称 | 值 | 用途 |
| --- | --- | --- |
| `welcomeDialogInset` | 20.0 | 卡片左右边距（= 现状 `insetPadding` 水平值） |
| `welcomeDialogVerticalGutter` | 24.0 | 卡片上下透明缓冲，恰好容纳 48dp 命中盒上半部 |
| `welcomeCloseVisualSize` | 32.0 | 视觉圆直径（含 1dp 描边） |
| `welcomeCloseHitSize` | 48.0 | 命中盒边长 |
| `welcomeDialogMaxHeightFactor` | 0.8 | 沿用现状最大高度 |
| `welcomeNoHeroExtraTop` | 56.0 | 无欢迎图时内容区额外顶部预留（20 → 76） |

推导（卡片宽 = 屏宽 − 40；`Stack` 尺寸 = 卡片 + 40 宽、+48 高；`Dialog` 居中 `Stack`，上下缓冲对称，所以卡片仍垂直居中）：

| 画布 | 卡片矩形 | 角标圆心 | 视觉矩形 | 露出 | 命中盒 | 屏内检查 |
| --- | --- | --- | --- | --- | --- | --- |
| 360×800 | 20,238.5,320,323 | 340,238.5 | 324,222.5,32,32 | 右 16 / 上 16 = 50% | 316,214.5,48,48 | 视觉右边 356 ≤ 360；命中盒右边 364 出屏 4dp（设计已接受） |
| 320×640 | 20,158,280,324 | 300,158 | 284,142,32,32 | 50% | 276,134,48,48 | 视觉右边 316 ≤ 320；命中盒右边 324 出屏 4dp |
| 640×400 | 20,40,600,320 | 620,40 | 604,24,32,32 | 50% | 596,16,48,48 | 视觉右边 636 ≤ 640；命中盒右边 644 出屏 4dp |

- 命中盒顶边正好落在 `Stack` 顶边（`top: 0`），因此 48dp 在**纵向完整可命中**；横向只有屏幕外的 4dp 不可命中，与设计说明 §4.2 / PRD §14 已接受的「可见区域仍可点」一致。
- 角标用 `Positioned(top: 0, right: -4)`：`right: -4` 让 48 盒的右边超出 `Stack` 4dp（即屏幕外 4dp），并使其中心精确落在卡片右边缘；纵向 `top: 0` 使 48 盒顶边与 `Stack` 顶边重合、中心落在卡片上边缘。
- 视觉圆在 48 盒内居中，故视觉矩形自动是「圆心 ±16」，露出比例恒为 50%。
- 320dp 下卡片宽度 = 280（`Dialog` 的 `minWidth: 280` 同时被满足），与设计 F04 的 280/300/316 完全一致。

### 4.4 无欢迎图（AC-8）

- `showHero` 为 false（资源缺失/解码失败折叠）时，内容 `Padding` 顶部取 `76dp`（默认 20 + 额外 56）；标题顶部距卡片顶 76dp，角标视觉底边距卡片顶 16dp，净距 60dp。
- 角标位置只依赖卡片矩形，图片折叠导致卡片高度变化时随布局自动回到卡片右上角，无需任何测量或状态。
- 有图时仍为 20dp，欢迎图/标题/副标题的现有间距不变。

### 4.5 交互与连点

- 角标点击与主按钮、次按钮共用 `_close(WelcomeDismissMethod)`：先判 `_closing`，置位后 `Navigator.pop(method)`；第二次点击直接 return，不重复 pop、不抛异常。
- 关闭时返回 `WelcomeDismissMethod.closeButton`；宿主 `method ?? back` 不会命中 null，控制器按现有链路记录 `method=close_button` 与 `visible_ms`。
- 按压态：按下底色切 `closeFillPressed` 并整体缩至 0.94（圆心不动），抬起/取消复位，约 100ms ease-out；不改变布局与命中盒。
- 主题/语言切换：角标颜色与文案全部来自 `Theme.of(context)` / `AppStrings.of(context)`，随 `WelcomeDialog` 重建即时更新；位置与层不变。

## 5. 接口定稿

### 5.1 关闭方式枚举（`lib/settings/welcome_contract.dart`）

| 项 | 定稿 |
