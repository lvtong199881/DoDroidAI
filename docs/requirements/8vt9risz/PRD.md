## 1. 背景

DoDroidAI 首次启动会展示一次性欢迎弹窗，介绍语音交互、工具执行和本地存储。弹窗目前只有一个「开始使用」按钮。

新安装用户通常没有 AI 配置（除非从系统备份恢复）。点「开始使用」进入首页后，只有发消息时才会被提示「请先在设置中配置 API 地址、Key 和模型」，之后还要走「侧边栏 → 设置 → AI 配置 → + → 填写」多步。欢迎弹窗是首次启动时最确定的引导时机，却没有承接配置入口。

本需求在欢迎弹窗增加「去配置AI」，仅在当前没有可用 AI 配置时出现，点击直达可直接填写的新建配置页。

## 2. 目标

1. 未配置 AI 的用户首次看到欢迎弹窗时，能直接看到「去配置AI」。
2. 点击后落在新建 AI 配置编辑页，Base URL 与主模型已按预设填好，只需填写 API Key。
3. 保存成功后回到首页，新配置立即生效，不再提示未配置。
4. 已配置 AI 的用户、已看过欢迎弹窗的用户，界面与行为不变。

### 2.1 成功判定

- 未配置用户首次看到弹窗时 100% 能看到入口；已配置用户 100% 看不到。
- 点击入口后 100% 到达新建配置编辑页；保存后 100% 回到首页。
- 既有「开始使用」、返回键关闭、一次性展示、首帧后展示均无回归。

## 3. 判定口径与名词

| 名词 | 定义 |
| --- | --- |
| 激活 AI 配置 | 与聊天发送时使用的是同一份「当前生效配置」 |
| 未配置 AI | 不存在激活配置，或激活配置的 `Base URL`、`API Key`、`主模型` 任一字段去除首尾空白后为空 |
| 已配置 AI | 激活配置的 `Base URL`、`API Key`、`主模型` 三个字段去除首尾空白后均非空 |
| AI 配置页 | 本需求语境下特指**新建 AI 配置编辑页**，不是配置列表页 |
| 首次展示欢迎弹窗 | 本地不存在「欢迎弹窗已展示」标记时的展示 |
| 非空 | 去除首尾空白（空格、换行、制表符）后长度大于 0 |

说明：本需求**不做**连通性、额度、模型可用性等网络探测，「配置」只按本地字段完整性判断。判断只看当前激活配置，其他配置即使完整也不影响结论；离线用户与配置字段完整但实际不可用的用户不会因为本需求看到入口。

## 4. 范围

### 4.1 做

- 欢迎弹窗按条件展示第二个按钮「去配置AI」。
- 点击后关闭弹窗并打开新建配置编辑页（带预设）。
- 保存后回首页并让配置生效；未保存返回也回首页。
- 新增关闭方式日志 `configure_ai`。
- 中英双语文案。

### 4.2 明确不做

1. **不补弹、不重复展示欢迎弹窗**：保持现有一次性逻辑；已看过标记存在的用户（含升级用户）不再看到弹窗，即使仍未配置 AI。
2. **不做 AI 配置列表页 / 编辑页的中英化**：英文用户点进去仍是中文页面，另立需求。
3. **不做配置校验**：不请求服务商、不校验 Key 有效性、不检测额度或模型可用性。
4. **不新增线上埋点通道**：沿用现有 debug 日志，release 不上报。
5. **不新增引导页 / 欢迎页**，不改造 AI 配置页的信息结构与交互。
6. **不改变「开始使用」**的文案、主按钮地位与关闭行为。
7. **不做深色模式、字体缩放、折叠屏 / 分屏 / 悬浮窗的专项适配**：沿用现有弹窗的主题与滚动布局，不新增平台验收项（详见 §7.2）。
8. **不修改 AI 配置的存储结构与数据迁移**：无新增字段。
9. **不在首页新增「未配置」横幅或提示**：既有发送拦截提示保持不变。
10. **不修改设置页的「未配置」展示口径**：设置页目前按配置名 `providerName` 是否为空展示，可能与聊天侧判断不一致，属于既有问题，本需求不处理。

## 5. 功能需求

### REQ-1 按 AI 配置状态显示第二按钮

1. 在欢迎弹窗决定展示时，读取当前激活 AI 配置并判断完整性；不使用网络请求。
2. 不存在激活配置 → 视为未配置 → 显示「去配置AI」。
3. 激活配置的 `Base URL`、`API Key`、`主模型` 任一去除首尾空白后为空 → 视为未配置 → 显示按钮。
4. 三项均非空 → 视为已配置 → 不显示按钮。
5. 读取本地配置抛异常（存储异常、JSON 损坏等）→ 按未配置处理 → 显示按钮，弹窗正常展示，不崩溃。
6. 判断在弹窗展示前完成，只判断一次；弹窗展示后不因后台配置变化而增删按钮。
7. 判断不得阻塞首页首帧，也不得因为读取慢而先展示半成品弹窗。
8. 不得为了判断而发起任何网络请求或读取真实凭据内容。

### REQ-2 点击跳转与返回

1. 点击「去配置AI」后，先关闭欢迎弹窗，再打开新建 AI 配置编辑页（新建态，不携带已有配置）。
2. 编辑页需带默认服务商预设：Base URL 与主模型已预填且非空，API Key 为空。
3. 在编辑页填写 API Key 并保存成功后，返回首页；首页发消息时使用刚保存并激活的配置，不再提示未配置。
4. 在编辑页按返回且未保存时，返回首页；欢迎弹窗不恢复显示。
5. 同一时刻只允许一次跳转：快速连点只打开一次编辑页。
6. 打开编辑页失败时，停留首页，记录错误，不崩溃。
7. 本需求不新增任何运行时权限，不申请存储、网络或其它权限。

### REQ-3 两个按钮的布局与层级

1. 未配置时，弹窗底部显示两个按钮：上方为「去配置AI」（次要样式），下方为「开始使用」（保持现有主按钮样式）。
2. 两个按钮均占满内容宽度，纵向排列，不并排、不重叠、不被裁切。
3. 弹窗内容超高时，沿用现有「内容区滚动、按钮区固定在底部」的布局，按钮不随内容滚走。
4. 已配置时不渲染「去配置AI」，也不保留其占位或额外间距；弹窗布局与改动前一致。
5. 次要按钮的具体视觉样式由设计说明定义，但必须与主按钮有明显不同的视觉权重。

### REQ-4 关闭方式与日志

1. 关闭方式新增 `configure_ai`，仅用于「去配置AI」按钮。
2. 点击「去配置AI」时，记录一条 `welcome_dismissed`，`method=configure_ai`，`visible_ms` 为弹窗展示到点击的毫秒数。
3. 点击「开始使用」仍记 `method=button`；系统返回键关闭仍记 `method=back`。
4. 不新增其他日志事件或字段；既有字段含义不变。
5. 日志失败不得阻塞关闭与跳转（沿用现有容错）。

### REQ-5 文案

| 语言 | 按钮文案 |
| --- | --- |
| 简体中文 | 去配置AI |
| English | Set up AI |

1. 应用内语言切换后，按钮文案随界面语言变化，无需重启。
2. 除中文、英文外的系统语言，按现有 `AppStrings` 规则回退中文。
3. 按钮文本本身作为无障碍名称，不额外增加描述。
4. AI 配置页文案不随本需求翻译。

### REQ-6 不改变既有行为

1. 欢迎弹窗仍是一次性：展示前写入「已展示」标记；写标记失败仍继续展示（下次可能重复）。
2. 弹窗仍在首页首帧渲染完成后检查与展示，不阻塞首帧。
3. 弹窗仍为模态：点击遮罩不关闭，系统返回键可关闭。
4. 已配置用户的弹窗布局、按钮样式、关闭方式与改动前一致。
5. 不因本需求给老用户补弹或重复展示。

## 6. 用户流程

### 6.1 主流程：首次启动且未配置 AI

1. 冷启动进入首页，首帧完成后检查「已展示」标记。
2. 无标记 → 读取激活 AI 配置 → 判定未配置 → 展示欢迎弹窗，底部两个按钮。
3. 用户点「去配置AI」→ 弹窗关闭（`configure_ai`）→ 打开新建配置编辑页，预设已填。
4. 用户填写 API Key → 保存成功 → 回到首页，配置生效。
5. 用户发消息 → 发起请求（占位 Key 可能返回鉴权失败，但不再出现未配置提示）。
6. 应用已写入「已展示」标记，下次冷启动不再展示弹窗。

### 6.2 分支：已配置 AI

1. 无「已展示」标记 → 读取配置 → 判定已配置 → 展示欢迎弹窗，仅「开始使用」。
2. 其余行为与改动前一致。

### 6.3 分支：在编辑页返回未保存

1. 点「去配置AI」→ 编辑页 → 系统返回。
2. 回到首页；欢迎弹窗不恢复；下次冷启动也不再展示（标记已写）。

### 6.4 分支：已看过弹窗的老用户 / 升级用户

1. 本地已有「已展示」标记 → 不展示弹窗，不读取 AI 配置做入口判断。
2. 用户仍可通过「设置 → AI 配置」自行配置，路径不变。

## 7. 边界与异常

### 7.1 需求内边界

| 场景 | 处理 |
| --- | --- |
| 无任何 AI 配置 | 按未配置处理，显示按钮（AC-1） |
| 激活配置缺 Base URL / Key / 主模型任一 | 按未配置处理，显示按钮（AC-2 ~ AC-4） |
| 三字段只有空白字符 | 视为空，按未配置处理 |
| 配置 JSON 损坏 / 读取异常 | 按未配置处理，弹窗照常展示，不崩溃（AC-6） |
| 配置读取较慢 | 弹窗只以最终判断结果展示一次，不出现「先单按钮、后补按钮」的闪烁（AC-19） |
| 连续快速点击「去配置AI」 | 只打开一次编辑页（AC-16） |
| 编辑页保存不完整（用户自行清空 Base URL 等） | 允许返回首页；首页仍按既有逻辑提示未配置，本需求不新增拦截 |
| 点击后打开编辑页失败 | 停留首页，记录 `welcome_error` 且 `stage=render`，不崩溃（AC-18） |
| 「已展示」标记写入失败 | 沿用现有逻辑：本次仍展示，下次可能重复；本需求不改变 |
| 弹窗展示期间进程被杀 | 标记已提前写入，下次冷启动不再展示；与现有一致 |
| 已看过弹窗但后来删除了 AI 配置 | 不再展示弹窗；用户可从设置进入配置 |
| 旧版单配置数据 | 沿用现有迁移逻辑，迁移后按同一三字段口径判断，不新增迁移 |

### 7.2 系统条件逐项判断

| 项 | 判断 | 结论 |
| --- | --- | --- |
| 深色模式 | 适用：应用支持深色，弹窗使用主题色 | 不单列平台 AC。新按钮只使用现有主题色，不写死颜色；设计说明需同时给出浅色/深色状态。深色下的视觉问题按设计走查处理，不算本需求的功能验收缺陷 |
| 折叠屏展开/折叠、分屏、悬浮窗 | 本需求不新增布局分支；弹窗已有 `maxHeight=80%` + 内容滚动 | 不适用，不新增验收项；多窗口与折叠形态沿用现有弹窗表现，不保证专项美化 |
| 生命周期 | 切后台回前台弹窗保持；进程被杀后因标记已写不再弹 | 无新增行为，沿用现有；不新增 AC |
| 升级路径 | 无数据迁移；有「已展示」标记的用户不补弹；无标记的升级用户按首次展示一次 | 适用，由 AC-15 覆盖；明确不为了新按钮给老用户补弹 |
| 异常（网络/超时/权限/存储满/渲染失败） | 本需求不联网，本地读取无超时定义；无新增权限；无新增写存储（欢迎标记沿用）；渲染失败沿用控制器兜底 | 配置读取异常 AC-6、打开页面失败 AC-18；网络失败、超时不适用；存储写入失败沿用既有，不新增 AC |
| 权限 | 不新增运行时权限 | 无新增权限文案 |

## 9. 多语言与权限文案

## 10. 监测指标与日志契约

### 10.1 数据契约变更

| 事件 | 变更 | 说明 |
| --- | --- | --- |
| `welcome_dismissed` | `method` 新增取值 `configure_ai` | 仅表示用户点击「去配置AI」关闭弹窗；`button`、`back` 保持原义与原取值 |

- 不新增事件名，不新增字段，不改变 `welcome_check` / `welcome_mark` / `welcome_shown` / `welcome_error` 的字段与含义。
- 日志中不得出现 API Key、Base URL、模型名等配置内容。

### 10.2 指标

| 指标 | 数据来源 | 计算/口径 |
| --- | --- | --- |
| 欢迎弹窗展示量 | `welcome_shown` | 计数，可按 `entry`、`locale` 分组 |
| 「去配置AI」点击量 | `welcome_dismissed` | `method=configure_ai` 的条数 |
| 引导点击率 | `welcome_dismissed` | `configure_ai` 条数 ÷ 全部 `welcome_dismissed` 条数（分母为 0 时不计算） |
| 关闭方式分布 | `welcome_dismissed` | 按 `method`（`button` / `back` / `configure_ai`）分组，用于确认既有按钮与返回键未回归 |
| 弹窗异常量 | `welcome_error` | 按 `stage`（`read` / `write` / `render`）分组；打开配置页失败计入 `render` |

- 现有欢迎日志只在 debug 构建输出到 logcat，本需求沿用；上述指标通过 debug 包日志验证，不构成线上数据分析能力。
- 若后续需要线上转化率，需另立埋点需求（明确不做）。
