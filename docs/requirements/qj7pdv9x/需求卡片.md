# 需求卡片：欢迎弹窗右上角关闭按钮

> 依据：《待提问清单.md》Q1–Q5 的用户选择（均选 A）。详细规则见 `PRD.md`。

## 0. 基本信息

| 项 | 内容 |
| --- | --- |
| 需求名称 | 欢迎弹窗右上角关闭按钮 |
| 平台 | Android（Flutter） |
| 影响模块 | 欢迎弹窗（`lib/widgets/welcome_dialog.dart`）、关闭结果契约与日志（`lib/settings/welcome_contract.dart`、`welcome_log.dart`）、中英文案（`lib/l10n/app_strings.dart`）、欢迎弹窗相关测试 |

## 1. 目标

- 在欢迎弹窗右上角提供一个显式、随时可点的关闭入口，视觉上「卡在弹窗右上角边缘」，约一半露出弹窗外。
- 点击关闭与点击底部「开始使用」等价：关闭弹窗，且沿用现有一次性标记，之后不再展示。
- 关闭方式可度量：新增 `close_button` 日志取值，能区分用户从哪个入口离开。

## 2. 范围

- 仅欢迎弹窗（`WelcomeDialog`）新增一个右上角关闭按钮。
- 按钮位置、露出比例、层级、可点击区域、深浅色可读性、窄屏与无欢迎图时的位置。
- 关闭结果新增 `closeButton` 取值，`welcome_dismissed` 新增 `method=close_button`。
- 新增中英文读屏文案。
- 对应 UI 测试、语义测试与日志断言；更新原有「没有关闭按钮」的断言。
- 保持欢迎图、标题、副标题、底部主按钮、遮罩、系统返回键的现有行为不变。

## 3. 明确不做的事

- 不给其它弹窗（工具确认框、提问面板等）加关闭按钮。
- 不修改欢迎文案、欢迎图、标题/副标题、底部「开始使用」的样式与行为。
- 不改变一次性展示门控（展示前写标记）、启动入口判断、单飞检查。
- 不改遮罩点击不关闭、系统返回键可关闭的现有规则。
- 不做折叠屏 / 分屏 / 悬浮窗的专门布局适配（理由见 PRD「系统条件」）。
- 不做全局无障碍改造；只保证本按钮有可访问名称与按钮角色。
- 不新增 release 埋点、后端上报、数据库或存储结构变更。

## 5. 验收标准

**术语口径**：弹窗矩形 = 弹窗 Material 的可视外接矩形（圆角外的包围盒），不含遮罩；按钮视觉尺寸 = 按钮图形本体与底色的外接矩形，不含阴影与命中扩展。

| 编号 | 覆盖 REQ | 验收标准（当……时，应当……） | 验证方式 |
| --- | --- | --- | --- |
| AC-1 | REQ-1 | 当欢迎弹窗完成首帧渲染时，关闭按钮应当完整显示（可见像素不被弹窗圆角或父级裁切），且按钮中心与弹窗矩形右上角的水平偏差、垂直偏差均 ≤ 1dp。 | Widget 测试测矩形 |
| AC-2 | REQ-1 | 当欢迎弹窗展示时，关闭按钮落在弹窗矩形外的宽度、高度应当分别为按钮视觉宽、高的 45%–55%。 | Widget 测试测矩形 |
| AC-3 | REQ-1 | 当点击关闭按钮露在弹窗矩形之外的部分时，弹窗应当关闭。 | Widget 测试点击弹窗外区域 |
| AC-4 | REQ-2 | 当测量关闭按钮的点击命中区域时，其宽、高应当均 ≥ 48dp。 | Widget 测试测命中盒 |
| AC-5 | REQ-2 | 当分别以浅色、深色主题展示，且按钮下方为欢迎图、滚动内容、弹窗背景或遮罩时，关闭按钮图标与按钮底色的对比度均应当 ≥ 3:1。 | 设计稿色值计算 |
| AC-6 | REQ-2 | 当欢迎弹窗首次展示、内容未滚动时，关闭按钮的外接矩形不应当与标题、副标题、底部主按钮的外接矩形相交（相切不算相交）。 | Widget 测试测矩形 |
| AC-7 | REQ-3 | 当在小屏（如 640×400）或 2 倍系统字号下内容发生滚动时，关闭按钮中心在整个滚动过程中与弹窗右上角的偏差应当 ≤ 1dp，且保持可点击。 | Widget 测试滚动前后对比 |
| AC-8 | REQ-3 | 当欢迎图缺失或加载失败导致图片区折叠时，关闭按钮中心仍应与弹窗右上角重合（偏差 ≤ 1dp），且不与标题、副标题的外接矩形相交。 | Widget 测试注入缺失资源 |
| AC-9 | REQ-3 | 当屏幕逻辑宽度为 320dp 时，关闭按钮的全部可见像素应当位于屏幕可绘制区域内，不被屏幕边缘裁切。 | Widget 测试 320×640 |
| AC-10 | REQ-4 | 当点击关闭按钮一次时，应当直接关闭弹窗（只发生一次路由 pop），不显示任何二次确认界面，关闭后首页可交互。 | Widget 测试 |
| AC-11 | REQ-4 | 当在关闭按钮上连续点击两次时，应当只发生一次关闭，且不出现异常、重复 pop 或黑屏。 | Widget 测试连点 |
| AC-12 | REQ-4 | 当通过关闭按钮关闭后重新冷启动应用时，欢迎弹窗不应当再次展示。 | 手工冷启动 / 集成测试 |
| AC-13 | REQ-5 | 当通过关闭按钮关闭时，debug 日志应当包含 `welcome_dismissed method=close_button visible_ms=<非负整数>`。 | 日志捕获单测 |
| AC-14 | REQ-6 | 当系统读屏聚焦关闭按钮时，应当朗读「关闭」（中文界面）/「Close」（英文界面），且控件角色为按钮。 | 语义测试 + 真机 TalkBack |
| AC-15 | REQ-7 | 当欢迎弹窗展示时，底部「开始使用」按钮应当仍显示在弹窗底部且可点击。 | Widget 测试 |
| AC-16 | REQ-7 | 当点击「开始使用」时，应当关闭弹窗，且日志 method 为 `button`。 | Widget 测试 + 日志 |
| AC-17 | REQ-7 | 当点击弹窗外的遮罩区域时，弹窗不应关闭。 | Widget 测试 |

## 7. 依赖与风险

- 依赖设计阶段产出按钮的视觉尺寸、底色/描边与按压态；本卡片只约束位置、露出比例、可点性、对比度与遮挡。
- 「半露出」与弹窗现有 16dp 圆角裁切存在冲突，实现必须保证外露部分可见且可点（AC-1、AC-3）。
- 「半露出」与 320dp 窄屏存在几何冲突，视觉尺寸需控制在屏幕内（AC-9）；设计取值前需核对。
- 现有测试断言「没有 `Icons.close`」，需改为断言关闭按钮存在；若图标不是 `Icons.close`，应按 Key 定位。
- 按钮固定不滚动（Q5）意味着它覆盖在滚动内容之上，需避免压住标题与副标题（AC-6、AC-8）。
