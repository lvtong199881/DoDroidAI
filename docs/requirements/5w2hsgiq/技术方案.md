## 2. 方案总览

### 2.1 技术路线

1. 在 `welcome_dialog.dart` 内做布局重构，不引入状态管理、路由、网络、图片缓存库或新依赖。
2. 保留现有公开入口、门控检查、欢迎标记写入、`WelcomeLog` 调用和关闭回调；新增一个仅测试使用的可选参数 `heroAssetOverride`，默认 `null`，现有调用源兼容。
3. 用 `Dialog` + `ConstrainedBox` + `Column` + `Flexible` + `SingleChildScrollView` 实现「内容可滚、按钮固定」。
4. 用 `ClipRRect` 与 `Dialog.clipBehavior` 双重保证图片顶部 16dp 圆角，不依赖素材自带透明角。
5. 用 `Image.asset` + `errorBuilder` 做本地资源降级；不新增加载态、占位图或错误文案。
6. 欢迎图放两张主题变体，按 brightness 选择；不按 locale 选择，中英文共用。

### 2.2 目标组件树

```text
Dialog(shape=16dp, clipBehavior=antiAlias, insetPadding 左右20/上下24, barrierDismissible=false)
└─ ConstrainedBox(maxHeight = 屏幕高 × 0.8)
   └─ Column(mainAxisSize.min, crossAxisAlignment.stretch)
      ├─ Flexible(fit: loose)
      │  └─ SingleChildScrollView(key=welcome_dialog_scroll, primary=false)
      │     └─ Column(crossAxisAlignment.stretch)
      │        ├─ ClipRRect(仅顶部圆角16)
      │        │  └─ SizedBox(width=弹窗宽, height=弹窗宽/2)
      │        │     └─ Image.asset(key=welcome_dialog_hero, fit=fitWidth, excludeFromSemantics=true)
      │        └─ Padding(左24/上20/右24/下8)
      │           └─ Column(crossAxisAlignment.stretch)
      │              ├─ Text(主标题, center, key=welcome_dialog_title)
      │              ├─ SizedBox(height=8)
      │              └─ Text(副标题, center, key=welcome_dialog_subtitle)
      └─ Padding(左20/上12/右20/下20)
         └─ SizedBox(width=无限, height=48)
            └─ 现有「开始使用」按钮(key=welcome_dialog_start, onPressed=现有 close)
```

说明：按钮组件类型沿用现有实现（图中以几何盒表示），不强制改成 `FilledButton`；不得改变 `onPressed`、文案、连点保护与日志。

### 3.2 欢迎图组件契约

| 项 | 定稿 |
| --- | --- |
| 组件 | `_WelcomeHero`，放在 `welcome_dialog.dart` 内，不新增公共 widget 文件 |
| 入参 | `String assetPath`（已由上层解析，非空；空路径由上层直接零高） |

| 主题切换 | 传入的 assetPath 变化时重置失败标记，允许换另一套素材重试 |

补充约束：

- 资源按设计源原样复制，不重绘、不压缩、不改色；如后续要优化体积，另开任务并重新验证 AC-4/AC-14。
- 构建期资源缺失会使 `flutter build` 失败，因此两张 PNG 必须与 `pubspec.yaml` 同提交；CI/评审要检查。
- 运行时缺失或解码失败由 `errorBuilder` 处理，不依赖构建期检查。
- 设计说明 5.2 的“源 640×320”与交付物“1280×640”均为 2:1；实现以交付 PNG 1280×640 为准，比例常量 2.0 由资源解码测试守护。

### 3.4 门控与日志契约

| 项 | 定稿 | 本需求是否变更 |
| --- | --- | --- |
| 欢迎标记路径 | 应用支持目录 `welcome/welcome_dialog_shown_v1`；Android 实际为 `files/welcome/welcome_dialog_shown_v1` | 不变 |
| 标记值 | `"1"` 表示已展示；不存在或 `"0"` 展示 | 不变 |
| 标记读取失败 | 按「未展示」处理，记录既有错误日志，展示弹窗 | 不变 |
| 标记写入时机 | 展示前写 `"1"`；写入失败记录既有错误日志后继续展示 | 不变 |
| 老用户升级 | 标记 `"1"` 覆盖安装后不展示；不迁移、不重置 | 不变 |
| 关闭方式 | 「开始使用」按钮或系统返回键；`barrierDismissible = false`；连点保护 | 不变 |
| 生命周期 | 切后台回前台弹窗保持且不叠加；进程被杀后重启不再展示 | 不变 |
| 日志事件 | `WelcomeLog.check / mark / shown / dismissed / error` 的触发时机与字段不变；不新增埋点 | 不变 |
| 图片失败日志 | 不写 `WelcomeLog`；仅 Flutter 运行日志可排查 | 符合 PRD |

事件语义顺序如下；实现必须与现有代码的实际调用顺序一致，不因布局重构调整顺序：

1. `check`：读标记，决定是否展示；
2. `mark`：需要展示时先写 `1`，失败记 error 后继续；
3. `shown`：弹窗展示时记录；
4. `dismissed`：关闭时记录 `method` 与 `visibleMs`。

图片加载失败不得跳过 `shown` / `dismissed`，因为失败发生在弹窗内部渲染阶段，不改变弹窗生命周期。

### 3.6 错误与空值语义

| 场景 | 行为 | 日志 | 用户可见结果 |

## 9. 回滚方案

### 9.1 代码与资源回滚

- 回滚单元：一个功能提交，包含 5 个文件（`welcome_dialog.dart`、`pubspec.yaml`、两张 PNG、测试文件）。开发阶段按此粒度提交，提交信息带需求编号 `5w2hsgiq`；构建前置修复如有，先行单独提交，功能提交只含这 5 个文件。
- 回滚动作：`git revert <功能提交 sha>`；若尚未合并，直接丢弃该提交。资源与 `pubspec.yaml` 声明在同一提交内回退，不会留下悬空 asset。
- 构建前置修复（如 AGP 版本/插件顺序）单独提交，不随功能回滚；只有确认它是故障源时才单独回退。
- 回滚后重跑 `flutter test`、`./gradlew assembleDebug`，安装旧包。

### 9.2 数据与标记

- 无数据迁移、无数据库、无 schema，不需要回滚数据。
- 欢迎标记 `welcome/welcome_dialog_shown_v1` 不回滚、不重置、不删除。已看过新版的用户回滚后仍是 `1`，因此不会再看旧版弹窗；这是可接受结果，因为用户已经看过欢迎弹窗。
- 如果产品要求回滚后重新展示旧版，需要单独发起需求并升级标记版本；本方案不做，避免擅自重置老用户状态。

### 9.3 回滚验证

1. 安装回滚后的 APK，保留应用数据。
2. 标记为 `1` 的用户冷启动进入首页：不出现欢迎弹窗，无崩溃。
3. 删除标记或全新安装：出现旧版欢迎弹窗，按钮可关闭。
4. 检查 `WelcomeLog` 事件仍按旧版时机产生。
5. 检查无 `Unable to load asset`、无红屏、无启动崩溃。

### 9.4 回滚触发条件与时效

- 触发：AC-12/AC-13/AC-14 在候选包上失败且无法当日修复；或出现门控回归（老用户重弹/标记被重置）；或启动崩溃/红屏。
- 时效：回滚提交 + 构建 + 安装验证预计 30 分钟内完成。
- 本需求不引入远程开关；回滚通过版本回退完成。若发布渠道支持分阶段放量，先暂停放量再回滚。
