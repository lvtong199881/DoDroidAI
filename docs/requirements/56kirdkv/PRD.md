## 1. 背景与问题

DoDroidAI 首次启动会展示一次性欢迎弹窗：2:1 贴边欢迎图、居中主标题「欢迎使用 DoDroidAI」、居中副标题「说一句话，让手机替你做事。」，底部是「开始使用」主按钮；未配置 AI 时还会多一个「去配置AI」次要按钮。

AI 配置入口在「设置 → AI 配置」，但欢迎弹窗没有告诉用户「以后随时可以改」。首次启动的用户（尤其是直接从「开始使用」进入首页的用户）可能以为配置是一次性的，或者不知道入口在哪。

本需求在欢迎弹窗主标题与现有副标题之间增加一行说明文字「随时可以在设置里改 AI 配置」，用次要色、13 号字，关闭弹窗时跟标题一起淡出。它只做告知，不新增可点击入口，也不改变现有配置流程。

本需求未提供参照截图。新增说明行的具体间距、字重、行高等视觉细节由设计阶段按现有欢迎弹窗风格补齐；PRD 只约束位置、字号、颜色、对齐、换行与淡出。

## 2. 目标与非目标

### 2.1 目标

- G1：欢迎弹窗每次展示时，都在主标题与现有副标题之间显示说明行；无论用户是否已配置 AI。
- G2：说明行使用 `onSurfaceVariant` 次要色、默认字号 13sp，跟随系统字体缩放；水平居中，窄屏/大字号下自然换行，不截断、不横向溢出。
- G3：关闭弹窗时，说明行与主标题在现有路由过渡中同步淡出，不新增独立动画、不改变关闭时长。
- G4：说明行是纯文本，不可点击，不新增页面、路由、权限、埋点或存储。
- G5：中英文案正确；现有标题、副标题、欢迎图、按钮、关闭方式、一次性门控与日志不回归。

### 2.2 非目标

- 不把说明行做成可点击链接或跳转入口。
- 不按 AI 配置状态改变说明行的显示或文案。
- 不新增 AI 配置引导页、欢迎页或新的配置流程。
- 不修改现有标题、副标题、欢迎图、底部按钮的文案与样式。
- 不修改关闭方式、一次性展示门控、`welcome_*` 日志与本地存储。
- 不新增线上埋点、release 上报、数据库表或文件。
- 不做全应用无障碍改造或专项 TalkBack 全流程验收。
- 不做折叠屏/分屏/悬浮窗专项布局。
- 不修改 AI 配置读取、校验或网络请求逻辑。

## 3. 判定口径与名词

| 名词 | 定义 |
| --- | --- |
| 说明行 | 本需求新增的、位于主标题与现有副标题之间的一行静态文本 |
| 主标题 | 现有 `welcome_dialog_title`，中文「欢迎使用 DoDroidAI」/ 英文「Welcome to DoDroidAI」 |
| 副标题 | 现有 `welcome_dialog_subtitle`，中文「说一句话，让手机替你做事。」/ 英文「Say it, and let your phone do it.」 |
| 标题文案区 | 欢迎弹窗内包含主标题、说明行、副标题的纵向区域，属于可滚动内容 |
| 已配置 / 未配置 AI | 以现有 `WelcomeAiGate.shouldShowConfigureAi()` 的结果为准：返回 `false` 为已配置，返回 `true` 为未配置（含读取异常） |
| 关闭路径 | 现有四个出口：底部「开始使用」、底部「去配置AI」、右上角关闭按钮、系统返回键 |
| 默认系统字号 | 系统字体缩放为 1.0 的状态 |
| 13sp | 默认系统字号下的基准字号；系统字体缩放后按比例放大，不是固定 13 逻辑像素 |
| 次要色 | `colorScheme.onSurfaceVariant`：浅色 `#5B6270` / 深色 `#A6ADBB` |
| 现有淡出 | `showDialog` 默认路由过渡对整个弹窗的淡出；不新增独立动画 |

说明：按用户对 Q1 的选择，说明行紧贴主标题下方、现有副标题上方；现有副标题保留并位于说明行下方；字号顺序为主标题 20sp → 说明行 13sp → 副标题 15sp。这是用户确认的版式，本需求不调整副标题字号来「修正」层级。这里的「紧贴」描述顺序上的相邻关系，不是要求零间距；具体上下间距由设计阶段给出。

## 4. 范围

### 4.1 做

- 在欢迎弹窗标题文案区新增一行说明文字，位置固定为主标题之后、副标题之前。
- 说明行在欢迎弹窗每次展示时都显示；不区分已配置/未配置，不受「去配置AI」按钮显示条件影响。
- 说明行使用 13sp 基准字号、`onSurfaceVariant` 颜色、居中、自然换行；跟随系统字体缩放。
- 说明行属于标题文案区，随标题一起滚动；内容超高时由现有滚动容器承载。
- 关闭弹窗时，说明行与主标题一起走现有整体淡出；不新增动画。
- 新增中英文案；更新欢迎弹窗相关测试。
- 保持现有标题、副标题、欢迎图、按钮、关闭方式、门控、日志与存储不变。

### 4.2 明确不做

1. 不做可点击链接、点击跳转「设置 → AI 配置」或任何新入口；配置入口仍是现有「去配置AI」按钮或侧边栏 → 设置 → AI 配置。
2. 不按 AI 配置状态隐藏、替换或改写说明行；两种状态都显示同一文案。
3. 不新增页面、路由、弹窗、加载态、空态或错误态；说明行是静态文案。
4. 不修改现有标题、副标题、欢迎图、底部按钮的文案、字号、颜色与行为。
5. 不修改关闭方式、一次性展示门控、`welcome_shown` / `welcome_dismissed` / `welcome_error` 的字段与含义。
6. 不新增埋点、release 上报、数据库表、文件或 SharedPreferences 键。
7. 不新增运行时权限，因此没有新增权限文案。
8. 不做全应用无障碍改造；不做专项 TalkBack 全流程验收，仅保证说明行是普通文本、没有按钮语义。
9. 不做折叠屏展开/折叠、分屏、悬浮窗的专项布局；沿用现有弹窗的宽度、最大高度与滚动行为。
10. 不修改 AI 配置读取、完整性判断、校验或网络请求逻辑。
11. 不改变关闭动画的时长与曲线，不新增独立淡出段。
12. 不为了说明行给老用户补弹欢迎弹窗；一次性门控不变。

## 5. 功能清单（REQ）

### 5.1 REQ-1 说明行的位置与显示条件

**描述**：在欢迎弹窗主标题与现有副标题之间新增说明行；只要欢迎弹窗展示，就显示说明行，不区分 AI 配置状态。

**规则**：

1. 说明行位于主标题之后、现有副标题之前；顺序固定，不随语言、字号、配置状态变化。
2. 现有副标题保留，并位于说明行下方；副标题文案与样式不变。
3. 欢迎弹窗每次展示时都显示说明行；不判断 AI 配置状态，不受 `showConfigureAi` 影响。
4. AI 配置读取失败、`shouldShowConfigureAi()` 返回 `true` 时，说明行仍显示。
5. 说明行属于标题文案区，随标题一起滚动；内容超高时不固定在底部、不单独成层。
6. 说明行只出现在欢迎弹窗；不出现在其它弹窗或页面。
7. 不新增显示条件、不读取额外状态、不做动态文案。
8. 欢迎图缺失/折叠时，说明行仍显示，且不被右上角关闭按钮遮挡。

**验收**：AC-1、AC-2、AC-3、AC-4、AC-21。

### 5.2 REQ-2 文案与多语言

**描述**：说明行使用固定的中英文案，沿用现有 `AppStrings` 机制；不做动态内容。

**规则**：

1. 中文文案逐字为 `随时可以在设置里改 AI 配置`，含 `AI` 前后空格，不加句号。
2. 英文文案逐字为 `You can change your AI config anytime in Settings.`，含句号。
3. 沿用 `AppStrings` 的 key-value 表与语言切换机制；不引入新的本地化框架。
4. 非中文/英文系统语言按现有规则回退中文。
5. 文案不含占位符、动态值、用户名、配置内容或链接。
6. 语言切换后，弹窗重建时使用当前语言；不要求重启应用。
7. 说明行不出现中文与英文混排（英文界面不出现中文，中文界面不出现英文，`AI` 除外）。

**验收**：AC-5、AC-6、AC-7。

### 5.3 REQ-3 视觉样式与排版

**描述**：说明行使用 13sp 基准字号、`onSurfaceVariant` 次要色、水平居中；窄屏和大字号下自然换行，不截断、不横向溢出。

**规则**：

1. 默认系统字号下基准字号 13sp；跟随系统字体缩放，不固定为 13 逻辑像素、不设最大缩放上限。
2. 颜色 `onSurfaceVariant`；浅色/深色分别使用主题值；与弹窗背景对比度 ≥ 4.5:1。
3. 水平居中；水平中心与主标题水平中心偏差 ≤ 1dp；文本块宽度与标题文案区一致。
4. 字重 400、行高 1.4；与主标题、副标题的间距由设计阶段给出，但不得与相邻文本或右上角关闭按钮重叠。
5. 自然换行；不省略、不截断、不设最大行数；不出现横向滚动或横向溢出。
6. 320dp 宽度或 2 倍系统字号下，允许换行到多行；内容超高时标题文案区可滚动，底部按钮保持完整可见且可点。
7. 说明行是普通文本：无背景、无边框、无阴影、无图标、无下划线、无链接色。
8. 不单独占固定层；不固定在弹窗顶部或底部。

**验收**：AC-8、AC-9、AC-10、AC-11、AC-12、AC-13。

### 5.4 REQ-4 关闭淡出

**描述**：关闭弹窗时，说明行跟主标题一起，按现有整体淡出过渡消失；不新增独立动画。

**规则**：

1. 关闭弹窗时，说明行与主标题使用同一路由过渡一起淡出；在关闭动画的任意一帧，两者透明度相同。
2. 四个关闭路径（开始使用 / 去配置AI / 右上角关闭 / 系统返回键）行为一致。
3. 不新增 AnimationController、自定义路由过渡、独立淡出段或额外延迟。
4. 关闭总时长与曲线保持改动前一致；`visible_ms` 口径不变。
5. 关闭后说明行不残留在首页或遮罩上；不出现闪烁、跳变或单独消失。
6. 关闭过程中重复触发关闭时，沿用现有路由行为；说明行不新增处理。

**验收**：AC-14、AC-15。

### 5.5 REQ-5 交互、无障碍与既有行为

**描述**：说明行是纯文本，不可点击；不新增权限、埋点或存储；现有欢迎弹窗行为不回归。

**规则**：

1. 说明行是纯文本，不响应点击、长按、双击；不新增可点击命中区域或手势、不新增按钮语义。
2. 读屏按布局顺序朗读「主标题 → 说明行 → 副标题」；说明行不合并进标题，也不单独声明为按钮。
3. 不新增运行时权限；不申请存储、网络、麦克风等权限。
4. 现有标题、副标题、欢迎图、底部按钮、关闭方式、门控、日志、存储不变。
5. 现有测试中与标题/副标题位置、弹窗高度、滚动相关的断言如受影响，按新布局更新；不得放宽既有行为断言。
6. 不新增埋点、日志字段、数据库表或文件；`welcome_shown` / `welcome_dismissed` / `welcome_error` 口径不变。
7. 不修改 `WelcomeAiGate` 或 AI 配置读取逻辑；说明行不依赖配置读取结果。
8. 不修改欢迎标记的读写时机与失败处理。

**验收**：AC-16、AC-17、AC-18、AC-19、AC-20。

## 6. 用户流程

### 6.1 首次展示（未配置 AI）

1. 冷启动，首帧后检查欢迎标记。
2. 无标记 → 读取 AI 配置 → 未配置 → 展示欢迎弹窗。
3. 弹窗内容顺序：欢迎图 → 主标题 → 说明行 → 副标题 → 底部「去配置AI」+「开始使用」。
4. 说明行始终显示；用户可点「去配置AI」或「开始使用」。
5. 关闭后保持一次性标记（现有逻辑）。

### 6.2 首次展示（已配置 AI）

1. 无标记 → 读取配置 → 已配置 → 展示弹窗。
2. 内容顺序同上，但底部只有「开始使用」。
3. 说明行仍显示。
4. 关闭后不再展示。

### 6.3 关闭

1. 任一关闭路径 → 路由 pop。
2. 说明行与主标题随现有整体过渡淡出。
3. 宿主记录 `welcome_dismissed`，`method` 与改动前一致。
4. 首页可交互。

### 6.4 窄屏 / 大字号 / 英文

1. 320dp 或 2 倍字号 → 说明行自然换行，内容区可滚动，底部按钮固定可见。
2. 英文 → 显示英文文案；其它语言 → 回退中文。
3. 不出现横向溢出、截断或省略号。

### 6.5 配置读取失败 / 无欢迎图

1. 配置读取失败 → `shouldShowConfigureAi()` 返回 `true` → 显示「去配置AI」；说明行仍显示。
2. 欢迎图缺失/加载失败 → 图片区折叠；说明行仍显示；右上角关闭按钮不遮挡说明行。

## 7. 边界与异常

### 7.1 需求内边界

| 场景 | 处理 | 覆盖 |
| --- | --- | --- |
| 屏幕逻辑宽度 320dp | 说明行自然换行；不省略、不截断；弹窗不横向溢出；内容超高时标题文案区可滚动 | AC-11 |
| 系统字体缩放 2 倍 | 说明行按 26sp 渲染；允许换行到多行；内容区滚动；底部按钮完整可见且可点 | AC-10、AC-12 |
| 英文文案较长 | 自然换行，不截断；320dp 下允许 3 行及以上 | AC-6、AC-11 |
| 标题文案区内容超高 | 说明行随主标题一起滚动，相对位置不变；不固定在底部 | AC-2 |
| 欢迎图缺失 / 加载失败 | 图片区折叠；说明行仍显示；不与右上角关闭按钮外接矩形相交 | AC-21 |
| AI 配置读取失败 | 按未配置处理，显示「去配置AI」；说明行仍显示 | AC-4 |
| 「已展示」标记写入失败 | 沿用现有逻辑：本次仍展示，下次可能重复；说明行不受影响 | 现有行为，无新增 AC |
| 弹窗展示中进程被杀 | 标记已在展示前写入，下次冷启动不再展示；无新增恢复逻辑 | AC-19 |
| 快速连续点击弹窗按钮 / 连点 | 沿用现有 `_closing` 连点保护；系统返回键沿用现有路由行为；说明行无交互，不参与关闭 | 现有行为，无新增 AC |
| 渲染失败 | 沿用现有 `welcome_error stage=render`；不重试、不二次展示；说明行不改变该分支 | 现有行为，无新增 AC |
| 无网络 | 说明行是本地静态文案，不依赖网络 | 现有行为，无新增 AC |
| 权限拒绝 | 本需求不新增权限，不适用 | 不适用 |
| 非中英系统语言 | 按 `AppStrings` 现有规则回退中文 | AC-7 |
| 深色模式 | 使用 `onSurfaceVariant` 深色值；对比度 ≥ 4.5:1 | AC-9 |
| 折叠屏 / 分屏 / 悬浮窗 | 不做专项布局；沿用现有弹窗宽度、最大高度与滚动 | 不适用，见 §7.2 |
| 老版本升级 | 无数据迁移；已有「已展示」标记的用户不补弹；无标记用户按首次展示一次 | AC-19 |
| 首次启动 vs 二次启动 | 门控不变；二次启动有标记则不展示 | AC-19 |
| AI 配置读取较慢 / 挂起 | 沿用现有「展示前只判定一次」的链路，说明行不新增等待、加载态或超时 | 现有行为，无新增 AC |

### 7.2 系统条件逐项判断

| 项 | 判断 | 结论 |
| --- | --- | --- |
| 深色模式 | 适用：应用支持深色主题，说明行使用主题 token | 使用 `onSurfaceVariant` 深色值 `#A6ADBB`，与弹窗背景对比度 ≥ 4.5:1；AC-9 覆盖。不做单独深色版式 |
| 折叠屏展开/折叠、分屏、悬浮窗 | 不适用：本需求只增加一行随宽度换行的文字，不新增断点或形态布局 | 不专项适配，不列为本需求验收项；沿用现有弹窗的宽度、最大高度与滚动。若后续要求专项验收，另立需求 |
| 生命周期 | 切后台回前台：弹窗路由保持；进程被杀：标记已在展示前写入，下次不再展示 | 无新增行为，沿用现有；不新增 AC |
| 升级路径 | 无数据库/存储迁移；有「已展示」标记的用户不补弹；无标记用户首次展示时包含说明行 | 适用，由 AC-19 覆盖；不为说明行补弹 |
| 异常：网络失败/超时 | 不适用：说明行为本地静态文案，不发起网络请求 | 无新增 AC |
| 异常：权限拒绝 | 不适用：不新增运行时权限 | 无新增 AC |
| 异常：存储满 | 本需求不新增写存储；欢迎标记写入失败沿用现有逻辑 | 现有行为，无新增 AC |
| 异常：渲染失败 | 沿用现有 `welcome_error stage=render`；不重试、不二次展示 | 现有行为，无新增 AC |
| 异常：AI 配置读取失败 | 说明行不依赖配置读取；失败时仍显示，按钮按现有逻辑显示「去配置AI」 | AC-4 覆盖 |
| 字体缩放 | 适用：用户选择跟随系统字体缩放 | 默认 13sp，2 倍缩放下 26sp；AC-10、AC-12 覆盖 |
| 无障碍读屏 | 部分适用：说明行是普通文本，使用默认语义；不做全应用改造或专项 TalkBack 全流程验收 | 不新增按钮语义；AC-16 覆盖；读屏顺序按布局自然顺序，不单列平台 AC |
| 多语言 | 适用：应用支持中英文 | 中英文案由 AC-5、AC-6 覆盖；非中英回退中文由 AC-7 覆盖 |

## 8. 验收标准

| AC-2 | REQ-1 | 当标题文案区内容超出弹窗最大高度并滚动时，说明行应当与主标题同步移动，滚动前后两者纵向间距变化 ≤ 1dp，且说明行不固定在弹窗底部。 | Widget 测试滚动 |
| AC-3 | REQ-1 | 当欢迎弹窗展示时，无论 `WelcomeAiGate.shouldShowConfigureAi()` 返回 `true` 还是 `false`，说明行都应当显示。 | Widget 测试注入两种 gate 结果 |
| AC-4 | REQ-1 | 当 AI 配置读取抛出异常、`shouldShowConfigureAi()` 按未配置处理时，说明行仍应当显示。 | Widget 测试注入抛异常的 loader |
| AC-5 | REQ-2 | 当界面语言为简体中文时，说明行应当逐字显示「随时可以在设置里改 AI 配置」，不添加句号、前后空格或其它字符。 | Widget 测试文本 |
| AC-6 | REQ-2 | 当界面语言为英文时，说明行应当逐字显示 `You can change your AI config anytime in Settings.`。 | Widget 测试 en locale |
| AC-7 | REQ-2 | 当界面语言不是中文或英文时，说明行应当按现有 `AppStrings` 回退规则显示中文文案。 | Widget 测试 fr locale |
| AC-8 | REQ-3 | 当系统字体缩放为默认值 1.0 时，说明行的基准字号应当为 13sp。 | Widget 测试 `TextStyle` |
| AC-9 | REQ-3 | 当分别以浅色、深色主题展示时，说明行文字颜色应当分别为 `onSurfaceVariant` 的浅色值 `#5B6270` / 深色值 `#A6ADBB`，且与弹窗背景的对比度均 ≥ 4.5:1。 | Widget 测试颜色 + 对比度计算 |
| AC-10 | REQ-3 | 当系统字体缩放为 2 倍线性缩放时，说明行的渲染字号应当为 26sp。 | Widget 测试 `textScaler: 2.0` + 截图测量 |

| AC-12 | REQ-3 | 当系统字体缩放为 2 倍时，说明行应当自然换行且不出现省略号或截断，弹窗内容区可滚动，底部按钮保持完整可见且可点击。 | Widget 测试 2 倍字号 + 滚动 + 命中 |
| AC-13 | REQ-3 | 当欢迎弹窗展示时，说明行的水平中心应当与主标题的水平中心重合（偏差 ≤ 1dp）。 | Widget 测试测矩形 |
| AC-14 | REQ-4 | 当通过任一现有方式关闭欢迎弹窗时，说明行应当与主标题在同一路由过渡中一起淡出；在关闭动画的任意一帧，说明行与主标题的透明度应当相同。 | Widget 测试 pump 关闭动画帧 + 读 opacity |
| AC-15 | REQ-4 | 当通过任一现有方式关闭欢迎弹窗时，弹窗从开始关闭到完全消失的时长应当与改动前一致，不因说明行新增独立淡出段或额外延迟。 | Widget 测试对比路由过渡时长 |
| AC-16 | REQ-5 | 当点击或长按说明行时，不应当发生页面跳转、弹窗关闭或其它交互；说明行的语义角色不应当是按钮。 | Widget 测试点击/长按 + 语义树 |
| AC-17 | REQ-5 | 当欢迎弹窗展示时，现有副标题「说一句话，让手机替你做事。」应当仍显示在说明行下方，且文案、字号 15sp、颜色 `onSurfaceVariant` 不变。 | Widget 测试文本/样式/矩形 |
| AC-18 | REQ-5 | 在 debug 构建中，当通过「开始使用」/「去配置AI」/右上角关闭/系统返回键关闭弹窗时，关闭结果与 `welcome_dismissed` 的 `method` 取值应当分别保持 `button` / `configure_ai` / `close_button` / `back` 不变。 | Widget 测试 + 日志捕获 |
| AC-19 | REQ-5 | 当本地已存在「欢迎弹窗已展示」标记时，冷启动不应当再次展示欢迎弹窗；当标记不存在时，应当展示一次且包含说明行。 | 手工冷启动 / 集成测试 |
| AC-20 | REQ-5 | 当未配置 AI 时，弹窗应当仍显示「去配置AI」按钮；当已配置 AI 时，不应当显示该按钮。 | Widget 测试注入两种 gate 结果 |
| AC-21 | REQ-1、REQ-5 | 当欢迎图缺失或加载失败导致图片区折叠时，说明行应当仍显示，且其外接矩形不应当与右上角关闭按钮的外接矩形相交。 | Widget 测试注入缺失资源 + 测矩形 |

## 13. 依赖、风险与开放问题

### 13.1 依赖

- 现有欢迎弹窗结构（欢迎图、标题、副标题、底部按钮、滚动容器、右上角关闭按钮）。
- 现有 `AppStrings` 中英文案机制与回退规则。
- 现有主题 token（`onSurfaceVariant` 浅色/深色值）。
- 现有 `showDialog` 路由过渡（整体淡出）。
- 现有欢迎门控、`WelcomeAiGate`、`welcome_*` 日志与测试。

### 13.2 风险

1. 说明行按用户选择紧贴主标题，字号顺序为 20/13/15；副标题比说明行大，若间距处理不当会显得层级跳跃。需设计阶段用间距和对齐弱化，但不得改动副标题字号或顺序。
2. 13sp 在 320dp 窄屏、2 倍字号下会换行到多行，可能把底部按钮推入滚动区；现有「内容滚动、按钮固定」结构必须保持，AC-11、AC-12 覆盖。
3. 未配置用户会同时看到说明行和「去配置AI」按钮；文案需避免让用户误以为必须先配置或按钮多余。说明行只陈述「以后可改」，不替代按钮。
4. 关闭淡出依赖现有 `showDialog` 路由过渡；若后续 Flutter/设计改动关闭动画，AC-14、AC-15 需重新核对。
5. 现有测试若对标题/副标题位置、弹窗高度做精确断言，新增一行会导致失败；应更新为包含说明行的新布局，不得放宽既有行为断言。
6. 说明行不可点击，用户若想立即改配置仍需走「去配置AI」或设置页；这是用户 Q2 的明确选择，不作为缺陷。

### 13.3 开放问题

无。7 项待提问均已由用户明确回答（均选 A）。
