# 设计说明：欢迎弹窗右上角关闭按钮

> 需求：qj7pdv9x　平台：Android（Flutter）　阶段：设计
> 设计源：`design/layouts.json` → `design/svg/*.svg`（8 帧）；几何量测：`design/boxes.json`；预览：`design-images/*.png`
> 说明：本文件只做设计，不含代码、接口与 PRD 改动。

## 1. 设计结论（一句话版）

在欢迎弹窗右上角放一个 **32×32dp 的圆形关闭按钮**，圆心与弹窗矩形右上角**精确重合**，
从而水平、垂直各露出 **16dp（各 50%）**；按钮绘制在弹窗裁切之外（层级高于欢迎图/文字/遮罩），
外露部分同样可点；点击命中区 **48×48dp**。浅色主题为白底 + 深色 X，深色主题为
`#262B36` 底 + 浅色 X，两者图标与底色对比度分别为 **17.44:1 / 11.56:1**，不依赖按钮下方
是欢迎图、滚动内容、弹窗背景还是遮罩。无欢迎图时内容区顶部预留 **56dp**，标题不被压住。

## 4. 关闭按钮组件规格

### 4.1 几何

| 项 | 规格 | 依据 |
| --- | --- | --- |
| 视觉尺寸 | **32×32dp** 圆形（rx=16） | 320dp 窄屏留给屏幕边缘 4dp 安全距离 |
| 位置 | 圆心 = 弹窗可视外接矩形右上角，偏移 `(0, 0)` | AC-1 偏差 ≤1dp，本稿为 0 |
| 露出比例 | 右、上各 16dp = 视觉宽/高的 **50% / 50%** | AC-2 要求 45%–55% |
| 描边 | 1dp，内侧贴边（外径 32dp 含描边） | 与 `surface` 分离 |
| X 图标 | 可视 11×11dp，线宽 2dp，圆头；居中 | 「关闭」图形语义 |
| 命中区 | **48×48dp**，与视觉同心 | AC-4 ≥48dp |
| 层级 | 弹窗裁切之外的最上层；高于欢迎图、滚动内容、文字、遮罩 | AC-1 / AC-3、PRD REQ-1.4 |
| 与内容关系 | 不进入滚动区；固定钉在弹窗角 | Q5-A、AC-7 |

### 4.2 320dp 窄屏核对（AC-9）

- 屏幕 320dp，弹窗宽 `320 - 20×2 = 280dp`，右边缘在 `x=300dp`。
- 关闭按钮视觉 x = `284 → 316dp`，右边缘距屏幕 **4dp**，完整可见，无裁切。
- 命中盒 x = `276 → 324dp`，右侧越出屏幕 4dp；这是 PRD §14 风险表已接受的情况
  （「以可见区域仍可点为准；视觉完整在屏幕内由 AC-9 保证」）。实现时命中盒仍需
  48×48dp，越出部分不可见但可见部分必须可点。

### 4.3 交互态

| 状态 | 表现 | 帧 |
| --- | --- | --- |
| 默认 | 白/深灰底 + 1dp 描边 + 2dp 阴影 | F01–F07 |
| 按压 | 底色切 `closeFillPressed`，整体缩至 **0.94**（≈30.08dp），阴影降为 60%，约 100ms ease-out | F08 |
| 抬起/取消 | 回默认态，不改变位置 | — |
| 聚焦（TalkBack） | 由系统焦点框承担，不自绘额外高亮；可访问名称「关闭 / Close」，角色按钮 | AC-14 |
| 禁用/加载 | 无。按钮始终可用；欢迎弹窗为本地资源，不存在需要禁用的加载态 | PRD §6.4 |

按压态仍以圆心为锚缩小，露出比例保持 50%（boxes.json：30.08dp，露出 15.04dp = 50%）。

### 4.4 无欢迎图（AC-8）

图片资源缺失/解码失败时图片区整块折叠，弹窗内容顶部预留 **56dp**：

- 关闭按钮位置不变（仍钉在弹窗右上角，仍半露出）。
- 标题顶部距弹窗顶 76dp；关闭按钮视觉底边距弹窗顶 16dp，两者净距 **60dp**，
  标题、副标题均不与按钮相交（F06）。

### 4.5 滚动（AC-7）

按钮不进入 `SingleChildScrollView`，固定在弹窗角。F05 取 640×400、2 倍字号、
滚到 210dp 处：关闭按钮中心仍在 `(620, 40)`，与弹窗右上角偏差 0；标题/副标题从按钮
下方经过，这是固定浮层的预期行为（PRD §9「系统字体缩放」已明确不作为遮挡缺陷）。

## 8. 对比度计算（AC-5，WCAG 非文本对比度）

| 组合 | 色值 | 对比度 | 判定 |
| --- | --- | --- | --- |
| 浅色图标 / 按钮底 | `#171A1F` on `#FFFFFF` | **17.44:1** | ≥3:1 ✅ |
| 浅色按压图标 / 按压底 | `#171A1F` on `#F1F3F7` | 15.70:1 | ✅ |
| 深色图标 / 按钮底 | `#E6E8EC` on `#262B36` | **11.56:1** | ✅ |
| 深色按压图标 / 按压底 | `#E6E8EC` on `#1E222B` | 12.98:1 | ✅ |

对照度不因按钮下方是欢迎图（浅/深两套）、滚动文字、弹窗表面或遮罩而变化，因为
按钮自带不透明底色；描边与阴影只负责与周围表面分离，不参与图标可读性判定。
浅色描边 `#C6CBD4` 与白底为 1.63:1、深色描边 `#3A404C` 与 `#262B36` 为 1.36:1，
属于装饰性边界，已用阴影补足轮廓；若开发希望更强的边界，可把描边换成
`onSurfaceVariant`（浅 `#5B6270` / 深 `#A6ADBB`），但本稿不改变系统色板。

## 9. 与现有设计规范的差异 / 字体降级

1. **仓库没有独立的 `MOBILE-UI.md` 设计规范文件**。本稿颜色、字号、间距直接取自
   `lib/theme/app_theme.dart` 与 `welcome_dialog.dart` 的现有实现；未发明新的全局色板。
   `closeFill/closeBorder/closeIcon` 均为语义色映射，不是新增主题色。
2. **新增组件级数值**（不属于全局 token）：关闭按钮 32dp / 命中 48dp / 1dp 描边 /
   16dp 图标 / 2dp 线宽 / 阴影 18%（深 50%）/ 按压 0.94 / 无图顶部 56dp。
   这些是实现本需求必须新增的组件规格，已全部写入 `layouts.json` 的 designTokens。
3. **字体降级**：出图环境使用 `Microsoft YaHei`（`designTokens.fonts.preview.stack`），

   核对现有弹窗的视觉与色值，未把截图当底图，也未读取其它需求目录。

## 10. 设计决策记录

- **为什么是 32dp**：320dp 屏上弹窗右边缘在 300dp，32dp 按钮圆心钉角后右边缘 316dp，
  留 4dp；36dp 只剩 2dp、40dp 会贴边/裁切，均不满足 AC-9 的稳妥性。32dp 同时大于
  Material 图标按钮的最小视觉尺寸，配合 48dp 命中盒不影响可点性。
- **为什么不用品牌蓝**：浅色欢迎图右上角本身有一个蓝色对勾圆形，蓝色按钮叠在同一区域
  会与主视觉混淆；中性表面色 + 深/浅 X 在两套欢迎图和遮罩上都能保持高对比。
- **为什么是纯图标**：PRD 只要求可访问名称；可见文案会额外占位并破坏「卡角」轮廓。
  读屏名称由 `welcomeClose` 文案提供（中文「关闭」/ 英文「Close」）。
- **56dp 顶部预留**：大于 48dp 命中盒（24dp 半径）+ 标题 20dp 内边距的安全组合，
  给按钮与标题留 60dp 净距；比 48dp 更从容，避免大字号/字体差异下贴边。
- **按压缩放到 0.94**：在 32dp 小尺寸上仍能感知反馈，同时圆心不动，不改变「卡角」
  位置；不使用 ripple 外扩，避免低层圆角处出现方形水波。

## 11. 加载/错误/未覆盖项判断

- **加载态舍弃**：无网络请求、无异步内容；欢迎图由本地 asset 提供，失败即折叠。
- **错误态保留 F06**：图片缺失/解码失败 → 图片区折叠 + 56dp 预留；渲染异常沿现有
  `welcome_error stage=render` 处理，不弹窗、无 UI 可画。
- **未覆盖**：折叠屏/分屏/悬浮窗（PRD 明确不适用）；系统返回键、遮罩点击（行为不变，
  无新视觉）；「连点保护」无视觉差异（第一次点击后按钮随弹窗退出，不需要 disabled 态）。
- **深色/浅色切换**：按钮颜色全部走主题语义色，随主题即时切换，位置不变。
