## 2. 验收方法

- 只读 PRD、需求卡片、设计说明、`design/`、`ui-screenshots/` 与 debug 包；**未读源码、未读测试报告与评审结论、未构建、未跑单元测试、不评价代码风格**。
- 亲手安装、清数据、构造两种 AI 配置状态、切换语言 / 主题 / 字号 / 宽度，逐状态截图 + `uiautomator dump` + `logcat` 取证。
- 所有装包、启动、dump、截图、录屏等可能挂住的命令均包 `Invoke-WithTimeout`（装包 240s，启动/轮询 60~150s，点按 15~30s）；等状态一律轮询，不用固定长睡眠。未出现命令超时或设备失联。
- 像素测量：用截图逐行扫描文字色块，取文字主色、行带高度与水平范围；用 WCAG 公式复算对比度。

## 7. 范围外观察与口径待确认

这些不是本需求引入、也不在 PRD 验收范围内的问题，单独列出供人拍板：

1. **首页 320dp + 2 倍字号溢出**：截图 `42` / `ui-screenshots/welcome/home-320dp-2x-overflow.png` 显示首页输入区被「OVERFLOWED BY 42 PIXELS」标记横向溢出。PRD 明确首页不在本需求范围、也不做折叠屏/全应用适配；本需求的说明行在弹窗内显示正常。建议另立首页响应式缺陷。
2. **「跟随系统」英文时首页中英混排**：系统 en-US 且应用语言未显式选择时，首页出现「Send a message to start」与「按住说话 / 深度思考 / 智能搜索」混排；欢迎弹窗整体为英文。属既有本地化硬编码问题，不影响本需求「说明行跟随界面语言」的判定。
3. **Android 14 非线性字体缩放**：2× 时说明行≈26sp 已达标，但 20sp 标题实际放大低于线性 2×。这是平台字体缩放策略，不是说明行实现问题；若要求全应用严格线性缩放，需另立平台适配。
4. **繁體中文下的说明行**：应用内选择「繁體中文」后，弹窗标题与说明行仍显示简体中文（`36` / `fallback-zh-hant.png`）。这与现有 AppStrings 只有中/英两套文案、非英回退中文的行为一致，PRD 未定义繁体文案；是否补繁体属新需求。
