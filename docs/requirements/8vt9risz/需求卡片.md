# 需求卡片：欢迎弹窗新增「去配置AI」按钮

| 项 | 内容 |
| --- | --- |
| 需求编号 | 8vt9risz |
| 需求名称 | 欢迎弹窗新增「去配置AI」按钮 |
| 产品 | DoDroidAI（Flutter Android，包名 com.mohanlv.dodroidai） |
| 优先级 | P1（新用户首次配置的引导入口） |
| 文档状态 | 待评审 |
| 更新日期 | 2026-11-26 |

## 1. 一句话目标

让首次看到欢迎弹窗、且尚未配置 AI 的用户，一次点击就能进入新建 AI 配置页完成配置；已配置 AI 的用户与此前版本行为完全一致。

## 2. 背景与问题

欢迎弹窗目前只有一个「开始使用」按钮。新安装用户必然没有 AI 配置，点「开始使用」进入首页后，发消息才被提示「请先在设置中配置 API 地址、Key 和模型」，需要再走「侧边栏 → 设置 → AI 配置 → + → 填写」多步。欢迎弹窗是首次启动时唯一确定能触达用户的界面，却没有承接配置引导。

## 3. 目标与成功判定

1. 未配置 AI 的用户首次看到欢迎弹窗时，能直接看到并点击「去配置AI」。
2. 点击后直接落在可填写的新建配置页，且已带好 Base URL 与主模型预设，用户只需填 API Key。
3. 保存后回到首页即可发起对话，不再被提示未配置。
4. 已配置 AI 的用户、已看过欢迎弹窗的用户，界面与行为不发生任何变化。

## 4. 范围

### 4.1 本需求做

- 欢迎弹窗按「激活 AI 配置是否完整」条件显示第二个按钮「去配置AI」。
- 点击后关闭弹窗并打开新建 AI 配置编辑页（带默认服务商预设）。
- 保存成功后返回首页并让新配置立即生效；未保存返回也回首页，弹窗不恢复。
- 新增关闭方式日志取值 `configure_ai`，不改变既有 `button` / `back`。
- 中英文案：中文「去配置AI」，英文「Set up AI」。

### 4.2 明确不做（用户已确认）

| 不做的事 | 理由 |
| --- | --- |
| 不补弹、不重复展示欢迎弹窗 | 用户确认保持现有一次性逻辑；老用户与已看过用户不再出现弹窗 |
| 不把 AI 配置列表页 / 编辑页做中英化 | 用户确认不在本需求范围，另立需求；英文用户点进去仍是中文页面 |
| 不做 AI 配置的连通性、额度、模型可用性校验 | 用户确认「配置」只按字段完整性判断，不做网络探测 |
| 不新增线上埋点或上报通道 | 用户只确认新增 `method=configure_ai`；沿用现有 debug 日志 |
| 不新增引导页、不改造 AI 配置页的信息结构 | 目标页复用现有新建配置编辑页 |
| 不改变「开始使用」的文案与行为 | 该按钮仍是主按钮，仍可直接关闭弹窗进入首页 |
| 不做深色模式、字体缩放、折叠屏 / 分屏 / 悬浮窗的专项适配 | 均为应用既有平台能力，本需求只复用现有弹窗布局与主题，不新增平台验收项 |
| 不修改 AI 配置的存储结构与数据迁移 | 无新增字段，无迁移 |
| 不在首页新增「未配置」横幅或提示 | 既有发送拦截提示保持不变 |

## 5. 关键定义

- **未配置 AI**：不存在激活 AI 配置，或激活配置的 `Base URL`、`API Key`、`主模型` 任一字段去除首尾空白后为空。以聊天侧「激活配置是否可用」为准，只看激活配置（其他配置即使完整也不影响结论），不做网络请求。
- **已配置 AI**：激活配置上述三个字段去除首尾空白后均非空。
- **AI 配置页（本需求语境）**：新建 AI 配置的编辑页（新建态），不是配置列表页。
- **首次展示欢迎弹窗**：本地不存在「欢迎弹窗已展示」标记时的展示。

## 6. 功能点与验收标准

### 6.1 功能点

| 编号 | 功能点 |
| --- | --- |
| REQ-1 | 欢迎弹窗按「激活 AI 配置是否完整」决定是否显示「去配置AI」；未配置或读取失败时显示，已配置时不显示 |
| REQ-2 | 点击「去配置AI」关闭弹窗并打开带预设的新建配置页；保存回首页且配置生效，未保存返回也回首页 |
| REQ-3 | 未配置时两个按钮纵向排列、全宽，「开始使用」保持主按钮，「去配置AI」为上方次要按钮 |
| REQ-4 | 点击「去配置AI」以 `method=configure_ai` 记录关闭，既有 `button` / `back` 不变 |
| REQ-5 | 按钮文案中英双语：中文「去配置AI」，英文「Set up AI」 |
| REQ-6 | 不改变欢迎弹窗既有的一次性展示、首帧后展示、遮罩行为与已配置用户的布局 |

### 6.2 验收标准

| 编号 | 覆盖 REQ | 验收标准 |
| --- | --- | --- |
| AC-1 | REQ-1 | 当本次判定为首次展示欢迎弹窗且本地不存在任何 AI 配置时，弹窗应当显示「去配置AI」按钮。 |
| AC-2 | REQ-1 | 当激活 AI 配置的 Base URL 去除首尾空白后为空时，欢迎弹窗应当显示「去配置AI」按钮。 |
| AC-3 | REQ-1 | 当激活 AI 配置的 API Key 去除首尾空白后为空时，欢迎弹窗应当显示「去配置AI」按钮。 |
| AC-4 | REQ-1 | 当激活 AI 配置的主模型去除首尾空白后为空时，欢迎弹窗应当显示「去配置AI」按钮。 |
| AC-5 | REQ-1、REQ-6 | 当激活 AI 配置的 Base URL、API Key、主模型去除首尾空白后均非空时，欢迎弹窗应当只显示「开始使用」一个按钮，不显示「去配置AI」，也不留下空白占位。 |
| AC-6 | REQ-1 | 当读取本地 AI 配置抛出异常时，欢迎弹窗应当按未配置处理并显示「去配置AI」按钮。 |
| AC-7 | REQ-2 | 当点击「去配置AI」时，应当关闭欢迎弹窗并打开新建 AI 配置编辑页。 |
| AC-8 | REQ-2 | 当通过「去配置AI」打开新建配置编辑页时，Base URL 与主模型应当已预填且非空，API Key 应当为空。 |
| AC-9 | REQ-2 | 当在编辑页保留预设值、填写 API Key 并保存成功时，应当返回首页，且随后发送消息不再出现「请先在设置中配置 API 地址、Key 和模型」提示。 |
| AC-10 | REQ-2 | 当在编辑页按返回且未保存时，应当返回首页，且本次会话不再显示欢迎弹窗。 |
| AC-11 | REQ-3 | 当弹窗同时显示两个按钮时，两个按钮应当纵向排列、各自占满内容宽度，「去配置AI」位于「开始使用」上方且使用次要按钮样式（与主按钮样式不同，按设计说明判定），两者不重叠、不被裁切。 |
| AC-12 | REQ-4 | 在 debug 构建中，当用户关闭欢迎弹窗时，`welcome_dismissed` 的 `method` 应当与关闭方式一致：开始使用=`button`、系统返回=`back`、去配置AI=`configure_ai`。 |
| AC-13 | REQ-5 | 当界面语言为中文时，「去配置AI」按钮文案应当显示为「去配置AI」。 |
| AC-14 | REQ-5 | 当界面语言为英文时，「去配置AI」按钮文案应当显示为「Set up AI」。 |
| AC-15 | REQ-6 | 当本地已存在欢迎弹窗「已展示」标记时（含从旧版本升级的用户），即使未配置 AI，冷启动也不应当再次显示欢迎弹窗。 |
| AC-16 | REQ-2 | 当快速连续点击「去配置AI」两次时，应当只打开一次新建配置编辑页。 |
| AC-17 | REQ-6 | 当冷启动进入首页时，首页内容应当先完成首帧渲染，欢迎弹窗及其按钮在首帧之后才出现。 |
| AC-18 | REQ-2 | 在 debug 构建中，当点击「去配置AI」后打开配置页失败时，应当停留在首页并记录一条 `welcome_error` 且 `stage=render`，应用不发生崩溃。 |
| AC-19 | REQ-1 | 当欢迎弹窗首次出现时，其按钮状态应当已经与 AI 配置判断结果一致，不出现先单按钮后补按钮的闪烁。 |

## 7. 测试账号与数据

本需求不涉及账号体系，不需要测试账号。

| 数据场景 | 构造方式（来源） | 预期 |
| --- | --- | --- |
| 全新、未配置 | `adb shell pm clear com.mohanlv.dodroidai` 后冷启动（会同时清空欢迎标记与全部本地数据） | 弹窗双按钮 |
| 已配置完整 | 设置 → AI 配置 → + → 选预设 → API Key 填占位值 `sk-placeholder-not-real` → 保存并激活；再重置「已展示」标记后冷启动（否则首次启动时弹窗已消耗） | 弹窗单按钮 |
| 激活配置缺 Base URL | 新建时选「自定义」，Base URL 留空，API Key 填 `sk-placeholder-not-real`，主模型填 `test-model`，保存并激活；重置「已展示」标记后冷启动 | 弹窗双按钮 |
| 缺 API Key / 缺主模型 | UI 不允许保存空值，由单元测试注入 `AiConfig(apiKey: '', …)` / `AiConfig(mainModel: '', …)` 覆盖 | 弹窗双按钮 |
| 配置读取失败 / JSON 损坏 | 单元测试注入抛异常的配置读取实现；或 debug 包用 `run-as` 把 `shared_prefs/FlutterSharedPreferences.xml` 中配置改成非法 JSON | 弹窗双按钮，不崩溃 |
| 已看过弹窗 | 正常走完一次弹窗后重启；或 debug 包执行 `adb shell run-as com.mohanlv.dodroidai sh -c "mkdir -p files/welcome && echo -n 1 > files/welcome/welcome_dialog_shown_v1"` | 不再显示弹窗 |
| 升级用户 | 安装旧版本（含欢迎弹窗）→ 看过弹窗 → `adb install -r -d <新 debug 包>`；没有旧包时用上一行的写标记方式模拟 | 不再显示弹窗 |
| 语言 | 设置 → 语言，切换「简体中文」/「English」 | 文案分别为中文 / 英文 |
| 主题 | 设置 → 外观，切换浅色 / 深色（仅设计走查用，不是功能验收项） | 按钮可见、文案不丢 |

- 所有 API Key 一律使用占位值，**不使用任何真实凭据**，也不要写入本文档。
- 日志查看：debug 包 `adb logcat` 过滤 `[welcome]`。
- 上表数据均由测试阶段在 debug 包内构造，不依赖线上账号或后端环境。

## 8. 依赖与风险

- 依赖现有 `AiConfigStore`（激活配置读取）、现有新建配置编辑页与欢迎弹窗框架，无新增后端与权限。
- 风险：欢迎弹窗只在首次展示，功能曝光天然有限；用户已确认不补弹，接受该限制。
- 风险：设置页对「未配置」的展示口径（配置名 `providerName` 是否为空）与聊天侧口径不一致，本需求不修改设置页，可能仍出现两处观感不一致；已记录为已知问题，不在本需求处理。
