# 待提问清单：8vt9risz

> 需求：给 DoDroidAI 的欢迎弹窗增加第二个按钮「去配置AI」，点击跳转 AI 配置页；按钮仅在当前 APP 尚未配置 AI 时出现。

## 一、已核实的事实（读现有实现得出，供判断参考）

1. 欢迎弹窗是一次性的：启动后由首页检查本地「已看过」标记，展示前先写标记，同进程只检查一次；遮罩不可点关闭，系统返回键可关闭。
2. 弹窗目前只有一个全宽主按钮「开始使用」，关闭方式只记录 `button` / `back` 两种。
3. 弹窗文案已做中英双语（`AppStrings`，key 形如 `welcomeStart`）。
4. AI 配置是「多配置 + 一个激活配置」；聊天只读激活配置，发送前用 `baseUrl`、`apiKey`、`mainModel` 三者非空判断是否可用，不满足时提示「请先在设置中配置 API 地址、Key 和模型」。
5. 设置页「AI 配置」进入的是配置列表页（可新建/复制/删除/设为激活）；列表为空时只显示「暂无配置，点右上角 + 新建」。设置页对「未配置」的展示口径是配置名是否为空，与聊天侧口径不一致。
6. 配置列表页与编辑页的文案目前是中文硬编码，未做多语言。

## 二、待提问清单

### Q1.「还没配置 AI」以哪一层为准？

- **问题**：现在存在三种「没配好」的情况：① 一条配置都没有；② 有配置但没有激活的；③ 激活配置缺 Base URL、API Key 或主模型。以哪个为准决定按钮出不出现。
- **会改变什么**：验收用的数据条件；判定过宽会出现「用户明明能聊天却看到去配置」；判定过窄会让新用户看不到入口。也决定和设置页现有「未配置」文案口径是否对齐。
- **推荐答案**：以「当前激活配置是否完整」为准——激活配置的 Base URL、API Key、主模型三者都非空才算已配置；没有任何配置、或激活配置缺任一项都算未配置。不做网络连通性/额度探测（离线或服务故障不应改变入口）。
- **备选**：A. 只要存在任意一条完整配置就算已配置（即使不是激活的）；B. 只看有没有配置记录，不看字段是否填全。

### Q2.「AI 配置页」具体指哪一页？

- **问题**：现有「AI 配置」入口进的是配置列表页；零配置用户进去只看到「暂无配置，点右上角 + 新建」，还要再点一次「+」。功能描述里的「AI 配置页」可能指列表页，也可能指可直接填写的新建页。
- **会改变什么**：点击后的步数、是否需要改造/新增页面、设计稿范围、验收路径。
- **推荐答案**：直接进入「新建 AI 配置」编辑页（默认带一个服务商预设，如 DeepSeek），保存成功后直接回首页；配置列表页仍只从设置进入。零配置用户从弹窗到能发消息只需「点按钮 → 填 Key → 保存」。
- **备选**：A. 进入现有 AI 配置列表页（与设置入口一致，不新增页面）；B. 仍进列表页，但空列表时自动展开新建表单。

### Q3. 未配置时两个按钮谁主谁次？

- **问题**：弹窗原本只有一个全宽主按钮「开始使用」。新增「去配置AI」后，两个按钮的主次关系、是否并排需要定，否则设计和技术会各自猜。
- **会改变什么**：视觉层级与截图验收；可能改动现有主按钮样式。
- **推荐答案**：「开始使用」保持主按钮（全宽、实心），「去配置AI」作为次要按钮（描边或文字按钮、全宽）放在其上方，两按钮上下排列、不并排。理由：弹窗职责仍是介绍，允许用户先进入首页再看。
- **备选**：A. 未配置时「去配置AI」为主按钮、「开始使用」降为文字按钮；B. 两按钮并排等宽（主次靠样式区分）。

### Q4. 已看过弹窗的老用户（含从旧版本升级、且尚未配置 AI 的用户）要不要补弹？

- **问题**：欢迎弹窗是一次性的，标记在展示前写入。老用户升级后不会再看到弹窗，也就永远看不到新按钮。若希望这类用户也被引导，必须改动现有展示门控。
- **会改变什么**：是否动欢迎弹窗的核心展示逻辑（影响全部用户）、升级路径行为、验收范围。
- **推荐答案**：不改一次性逻辑——只有首次安装或清除数据后的首次启动、且未配置 AI 时才出现；升级用户不补弹。这类用户发送消息时已有「请先在设置中配置」的提示，设置里也有 AI 配置入口。
- **备选**：A. 未配置 AI 时每次冷启动都弹，直到配置完成；B. 仅对「升级且未配置」的用户补弹一次。

### Q5. 英文环境下这个按钮叫什么？

- **问题**：弹窗已做中英双语，新增按钮必须有对应英文文案，否则英文界面会露出中文。
- **会改变什么**：多语言文案验收、英文截图。
- **推荐答案**：中文「去配置AI」，英文「Set up AI」。
- **备选**：A. 「Configure AI」；B. 「Go to AI settings」。

### Q6. 英文用户点进去会落到中文的 AI 配置页，本需求管不管？

- **问题**：AI 配置列表页和编辑页的文案目前全部中文硬编码（含「AI 配置」「暂无配置」「保存」等）。英文环境点「去配置AI」会进入中文页面。
- **会改变什么**：是否把范围扩大到 AI 配置页整体中英化，工作量与验收量都会明显增加。
- **推荐答案**：不在本需求范围。本需求只保证弹窗内按钮文案双语；AI 配置页的本地化另立需求。
- **备选**：A. 本需求一并把 AI 配置列表页与编辑页中英化。

### Q7. 要不要单独统计「去配置AI」的点击？

- **问题**：现有 `welcome_dismissed` 只记录 `button` / `back`。新增入口后，从日志分不出用户是点了「开始使用」还是「去配置AI」，也就看不出这个引导是否有人用。
- **会改变什么**：日志/埋点契约（新增稳定取值）、测试断言、后续看板口径。
- **推荐答案**：新增关闭方式 `method=configure_ai`，点击时打一条 `welcome_dismissed method=configure_ai`；现有 `button` / `back` 取值保持不变。
- **备选**：A. 复用 `button`（不新增取值，无法区分）；B. 不记录关闭方式，另起一条独立点击事件。

## 三、本次不问、按推荐值继续推进的事项（只影响实现细节）

- 本地配置读取失败（存储异常/JSON 损坏）时按「未配置」处理，仍然显示按钮，避免新用户失去入口，并记一条欢迎弹窗读取错误日志。
- 配置页返回首页后不恢复欢迎弹窗；系统返回键仍可关闭弹窗，关闭方式仍记 `back`。
- 按钮出现条件不满足时直接不渲染（不是置灰）。
- 深色模式、字体缩放、横竖屏、折叠屏等平台能力沿用现有弹窗的主题与滚动布局，本需求不新增平台适配验收项。
- 弹窗展示后文案与按钮的加载/布局不得阻塞首页首帧（沿用现有首帧后检查、图片缺失折叠的策略）。
