### 4.3 保存失败（AC-9，P1）

操作：保留预设 → 在 API 密钥填入 `sk-placeholder-not-real` → 点「保存」。

结果：页面停留在「新建配置」，无成功提示/无错误提示；随后返回首页与设置页均显示未配置；`shared_prefs` 下没有生成 AI 配置。

logcat（原样）：

```text
11-26 08:45:02.583 E/flutter ( 7778): [ERROR:flutter/runtime/dart_vm_initializer.cc(40)] Unhandled Exception: Unsupported operation: Cannot add to an unmodifiable list
11-26 08:45:02.583 E/flutter ( 7778): #0      UnmodifiableListMixin.add (dart:_internal/list.dart:112:5)
11-26 08:45:02.583 E/flutter ( 7778): #1      AiConfigStore.saveActive (package:dodroidai/ai/ai_config.dart:286:15)
11-26 08:45:02.583 E/flutter ( 7778): #2      _ApiConfigScreenState._save (package:dodroidai/screens/settings/api_config_screen.dart:216:5)
```

复现范围（同一异常、同一栈）：

1. 欢迎弹窗 →「去配置AI」→ 填 Key → 保存；
2. 设置 → AI 配置 → 右上角「新建配置」→ 选 DeepSeek 预设 → 填 Key → 保存；
3. 设置 → AI 配置 → 新建 → 自定义，手工填 Base URL/Key/主模型 → 保存。

因此该缺陷既阻断本需求 AC-9，也使「已配置用户」状态在全新安装上不可达，连带 AC-2~AC-6 无法构造。参考 [evidence/02-save-crash-log.txt](evidence/02-save-crash-log.txt)、截图 [api-config/06](ui-screenshots/api-config/06-save-failed-config-page-en.png)。

## 6. 缺陷、风险与待确认项

### 6.1 BUG-1（P1，阻断）：保存新 AI 配置抛未捕获异常

- **现象**：新建配置页点保存后报 `Unsupported operation: Cannot add to an unmodifiable list`，无用户提示，停留编辑页，配置不落盘。
- **触发**：欢迎弹窗 → 去配置AI → 保存；设置 → AI 配置 → 新建 → 保存（预设或自定义均可）。
- **影响**：AC-9 失败；目标 3「保存成功后回首页、配置立即生效」不成立；由于无法产生完整配置，AC-2~AC-6 的判定状态也无法构造。
- **证据**：`evidence/02-save-crash-log.txt`、`ui-screenshots/api-config/06-save-failed-config-page-en.png`。
- **备注**：栈落在既有保存方法 `AiConfigStore.saveActive`，设置页入口同样复现，**可能为既有缺陷而非本需求引入**；但它是本需求主流程的必经环节，需开发修复后才能完成 AC-9 与配置态相关验收。

### 6.2 包版本标注不一致（建议）

任务包标注 `app-debug.apk#0.1.0.1（versionCode 5）`，实际文件经 `aapt2` 校验为 **0.1.0.2（versionCode 6）**，与《技术方案》§7.3 的当前有效包一致。本轮按实际文件测试；建议编排层更正交付标注，避免下游按旧版本记录或误装旧包。

### 6.3 `welcome_shown` 的 `locale` 口径待确认

应用内语言切为简体中文、繁體中文后，界面与按钮文案均已是中文，但 `welcome_shown` 仍输出 `locale=en`（系统语言为 en-US）。PRD §10.2 要求指标可按 `locale` 分组；若 `locale` 取系统语言，应用内切换语言的用户会被归到错误分组。REQ-4.4 又要求既有字段含义不变，因此本轮**不判失败**，列为口径待确认：

- 现状：`locale` = 系统语言；
- 影响：应用内语言与系统语言不一致时，展示量/locale 分组偏差；
- 建议：明确 `locale` 是「系统语言」还是「应用语言」；如需改为应用语言，另立埋点口径需求，不在本需求内顺手改。

### 6.4 冷启动 ANR（一次性，未复现）

320dp + 深色 + 连续快速重启的一次冷启动出现系统 ANR（`ANR in com.mohanlv.dodroidai`，144% CPU），点 Wait 后恢复；随后以深色+默认尺寸复测无 ANR，之前 4 次浅色冷启动也无 ANR。发生环境为 debug 包在 x86_64 模拟器上跑 arm64 转译，冷启动 13~17s。暂按环境/性能抖动记录，不计为本需求功能缺陷；建议真机复测冷启动与深色场景。详见 [evidence/06](evidence/06-anr-observation.txt)。

### 6.5 范围外发现（只记录，不处置）

- 设置 → AI 配置 → 新建的既有入口同样保存崩溃（与 BUG-1 同一栈），属既有路径问题，但会放大用户「无法配置 AI」的影响。
- 英文界面下，首页底部语音区仍显示中文（「语音模型未就绪，等待 Wi-Fi 自动下载」「按住说话」等），属既有 i18n 缺口，不在本需求范围（PRD §4.2 明确只做弹窗按钮中英）。
- 深色模式、320dp、繁体回退均已截图留档；深色仅作设计走查，不构成本需求功能验收项。
