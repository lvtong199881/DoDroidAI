### 0.1 一句话方案

保留欢迎弹窗的一次性门控、首帧后展示、主按钮与返回键行为不变；在弹窗展示前用一次本地读取判断激活配置三字段（trim 后）是否完整，据此决定是否渲染上方次要按钮；点击按钮以 `configure_ai` 关闭弹窗并记日志，关闭完成后由首页 push 现有 `ApiConfigScreen` 的新建态（新增 `initialProvider` 入参带入 DeepSeek 预设），保存仍走既有 `saveActive` 与 `reloadConfig`；打开配置页失败按 `welcome_error(stage=render)` 兜底。

## 2. 方案总览

### 2.1 技术路线

1. **判断与展示分离**：`WelcomeAiGate` 只负责「要不要显示第二个按钮」，返回布尔且永不抛异常；`WelcomeDialog` 只负责按传入布尔渲染，不在组件内部读配置，从而保证 AC-19「只有一个确定状态」。
2. **复用现有门控**：`WelcomeController.runOnce` 仍是唯一检查入口；`flagged` 用户不会走到 presenter，因此不会读取 AI 配置，满足 REQ-6.4 与「老用户零变化」。
3. **展示前完成判断**：在 `ChatScreen._presentWelcome` 里 `await` gate，再 `showDialog`；`welcome_shown` 仍由 `onShown` 在 `showDialog` 之后触发；`visibleMs` 从 gate 完成、弹窗开始展示时计时，不含配置读取耗时。
4. **日志先于导航**：控制器在 presenter 返回关闭结果后先记 `welcome_dismissed`，再调用可选的 `onConfigureAi`；这样 `method=configure_ai` 在用户点击的同一时刻落日志，而不是等用户离开配置页。
5. **新建态预设**：不伪造一个「已有配置」传给编辑页（否则会进入编辑态、出现删除/设为激活按钮），而是给 `ApiConfigScreen` 增加 `initialProvider` 入参；仅在 `config == null` 时用它铺默认值，`_isEditing` 仍为 `false`。
6. **最小日志变更**：只增加 `method` 的一个取值，不新增事件、字段、上报通道；不记录配置内容。
7. **默认关闭新 UI**：`WelcomeDialog.showConfigureAi` 默认 `false`，现有调用方与现有 widget 测试不传即保持单按钮，回归面最小。

### 2.2 目标调用链

```text
ChatScreen.initState
  └─ addPostFrameCallback → _checkWelcome()
       ├─ locale = en ? 'en' : 'zh'
       └─ WelcomeController.runOnce(locale, presenter, onConfigureAi)
            ├─ entryResolver.resolve()
            ├─ flagStore.read()
            ├─ flagged == true → welcome_check(skip, flagged) → 结束
            ├─ welcome_check(show, no_flag|read_failed)
            ├─ flagStore.write()（失败记 welcome_mark fail + welcome_error(write)，继续）
            └─ presenter(onShown)  [ChatScreen._presentWelcome]
                 ├─ WelcomeAiGate.shouldShowConfigureAi()
                 │    ├─ loadActive() == null / 三字段有空白 / 抛异常 → true
                 │    └─ 三字段 trim 均非空 → false
                 ├─ startedAt = now
                 ├─ showDialog<WelcomeDismissMethod>(
                 │      WelcomeDialog(showConfigureAi: 判断结果),
                 │      barrierDismissible: false,
                 │      useRootNavigator: true)
                 ├─ onShown() → welcome_shown
                 └─ await closing → WelcomeDismissResult(method, visibleMs)
            ├─ welcome_dismissed(method, visibleMs)
            └─ method == configure_ai → await onConfigureAi()
                 └─ Navigator.of(context, rootNavigator: true).push(
                        ApiConfigScreen(initialProvider: AiProvider.deepseek))
```

异常分支：

- gate 抛异常 → gate 内部吞掉并返回 `true`（AC-6）。
- `showDialog` / presenter 抛异常 → 控制器记 `welcome_error(stage=render)`，不向调用方抛（既有行为）。
- `onConfigureAi` 抛异常 → 控制器在同一个 `try` 内记 `welcome_error(stage=render)`，用户停留首页，不崩溃（AC-18）。
- 日志方法抛异常 → `_safeLog` 吞掉，关闭与导航继续（REQ-4.5）。

### 2.3 关键取舍

| # | 取舍 | 选择 | 理由 | 对应 |
| --- | --- | --- | --- | --- |
| 1 | 配置判断放控制器还是首页 presenter | 放首页 presenter + 独立 gate | 控制器保持纯门控与纯 Dart 可测；AI 配置属于 UI 宿主职责；flagged 用户不会调用 presenter，天然不读配置 | REQ-1、REQ-6.4 |
| 2 | 复用 `AiConfig.isConfigured` 还是新增判定 | 新增 `AiConfig.hasCompleteFields`（三字段 `trim`） | 现有 `isConfigured` 用 `isNotEmpty`，不满足 PRD 的全空白口径；直接改它会顺带改变聊天发送提示，超出本需求 | REQ-1、AC-2~4 |
| 3 | 导航放 presenter 内还是控制器回调 | 控制器先记 `dismissed`，再回调首页导航 | 保证日志时机与「点击即记」；同时让导航异常仍被控制器的 render 兜底捕获 | REQ-2.6、REQ-4.2、AC-18 |
| 4 | 预设用「伪 config」还是新增 `initialProvider` | 新增 `initialProvider`，编辑态仍只认 `config` | 伪造 config 会让新页面变成「编辑配置」并出现删除/设为激活，违背「新建态、不携带已有配置」 | REQ-2.1、AC-8 |
| 5 | 新按钮参数默认值 | 默认 `false` | 现有调用方与既有测试零改动；只有首页在判断后显式传 `true` | REQ-6、AC-5 |
| 6 | 默认服务商 | DeepSeek（PRD H-1） | 用户只确认「带预设」，H-1 已定；DeepSeek 的 Base URL 与主模型均非空，满足 AC-8 | AC-8、H-1 |
| 7 | 是否新增日志/字段 | 不新增 | 只加 `method=configure_ai`；指标口径沿用现有 debug 日志 | REQ-4、PRD §10 |
| 8 | 判断是否加超时/加载态 | 不加 | 本地 `SharedPreferences` 读取，无网络等待；PRD 明确禁止出现「先单按钮后补按钮」的中间态 | REQ-1.6/1.7、AC-19 |
| 9 | 是否改配置页结构 | 不改 | 只加一个可选预设入参与少量测试 Key；信息结构、校验、保存逻辑不变 | REQ-2、PRD §4.2.9 |

## 3. 接口定稿

### 3.1 配置完整性判定（新增）

**文件**：`flutter_app/lib/settings/welcome_ai_gate.dart`（新增）；`flutter_app/lib/ai/ai_config.dart`（新增 getter）。

| 项 | 定稿 |
| --- | --- |
| 类型 | `class WelcomeAiGate` |
| 构造 | `WelcomeAiGate({ActiveAiConfigLoader? loadActive})`；默认 `AiConfigStore().loadActive` |
| 读取函数类型 | `typedef ActiveAiConfigLoader = Future<AiConfig?> Function();` |
| 方法 | `Future<bool> shouldShowConfigureAi()` |
| 返回 `true` | 不存在激活配置；激活配置三字段任一 `trim` 为空；读取过程任意异常 |
| 返回 `false` | 激活配置 `baseUrl.trim()`、`apiKey.trim()`、`mainModel.trim()` 均非空 |
| 空值语义 | `loadActive()` 返回 `null` 按「无配置」处理 |
| 异常语义 | **不向调用方抛**；`catch` 全部异常后返回 `true`，不上报、不打印凭据 |
| 调用次数 | 每次欢迎弹窗展示前调用一次；不缓存到跨进程/跨弹窗 |
| 网络 | 不发起任何网络请求 |
| 日志 | 不新增日志；读取失败不写 `welcome_error`（避免与标记读取的 `stage=read` 混淆） |
| 依赖方向 | `welcome_ai_gate.dart` → `../ai/ai_config.dart`；不反向依赖 chat/settings 页面 |

**`AiConfig` 新增 getter（定稿）**：

```dart
/// PRD 口径：Base URL / API Key / 主模型 去除首尾空白后均非空。
bool get hasCompleteFields =>
    baseUrl.trim().isNotEmpty &&
    apiKey.trim().isNotEmpty &&
    mainModel.trim().isNotEmpty;
```

- 现有 `bool get isConfigured`（`isNotEmpty`）**不改**，聊天发送提示沿用既有行为；本需求只在欢迎入口使用 `hasCompleteFields`。两者在 UI 可产生的数据上等价（保存时已 `trim`），差异只存在于被外部写入的全空白字段，属于异常数据。
- `ApiConfig.isValid` 也不改。

### 3.3 控制器与导航回调契约（修改）

**文件**：`flutter_app/lib/settings/welcome_controller.dart`。

| 项 | 定稿 |
| --- | --- |
| 方法签名 | `Future<void> runOnce({required String locale, required WelcomePresenter presenter, Future<void> Function()? onConfigureAi})` |
| `presenter` | 现有 `Future<WelcomeDismissResult> Function(void Function() onShown)` **不变**；配置判断与弹窗展示都在 presenter 内 |
| `onConfigureAi` | 可空；仅当 `result.method == WelcomeDismissMethod.configureAi` 且非空时调用；调用一次 |
| 调用顺序 | `presenter` 返回 → `dismissed` 日志 → `onConfigureAi()` → 本次 `runOnce` 完成 |
| 是否等待导航 | 等待 `onConfigureAi()` 完成（即等待配置页被 pop）；期间 `_run` 保持同一个 Future，重复调用仍复用，不重复展示 |
| 异常 | `onConfigureAi` 抛异常 → 捕获后记 `welcome_error(stage=render)`，不向调用方抛；用户停留首页 |
| 空回调 | `method=configure_ai` 但 `onConfigureAi == null` 时不做导航、不报错（仅测试/兼容用；首页永远传） |
| 日志失败 | `_safeLog` 吞掉日志异常；`onConfigureAi` 仍执行 |
| `button` / `back` | 不触发 `onConfigureAi`；行为与现状一致 |
| 单飞 | `_run` 语义不变；并发调用复用同一 Future |

**注意**：`visibleMs` 由 presenter 在 `showDialog` 前起算、弹窗 pop 后结算；gate 的 `await` 必须放在 `startedAt` 之前，避免把配置读取耗时算进可见时长。

### 3.4 新建配置页预设契约（修改）

**文件**：`flutter_app/lib/screens/settings/api_config_screen.dart`。

| 项 | 定稿 |
| --- | --- |
| 构造 | `const ApiConfigScreen({super.key, this.config, this.initialProvider});` |
| 新字段 | `final AiProvider? initialProvider;` |

| `config == null && initialProvider == null` | 现有新建态：`custom` + 空字段，行为不变 |

| 标题 | 预设新建仍显示「新建配置」，不出现「删除」「设为激活」 |
| `deepseek` 预设值 | `providerName=DeepSeek`、`baseUrl=https://api.deepseek.com/anthropic`、`mainModel=DeepSeek-V4-Flash`、`apiKey=''`、`apiFormat=anthropicMessages`、`contextWindow=200000` |

**实现方式**：`initState` 内先取 `final seed = widget.config ?? (widget.initialProvider != null ? AiConfig.defaultFor(widget.initialProvider!) : null);`，后续所有 `config?.x` 改为 `seed?.x`；`_isEditing` 仍只看 `widget.config != null`。不得在 `initState` 调 `_applyPreset`（其内部 `setState`），也不得复用 `_applyPreset` 的交互语义。
