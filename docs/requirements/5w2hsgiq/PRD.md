## 1. 背景与目标

DoDroidAI 首次进入首页时会展示一次性欢迎弹窗。当前结构为：

> 主标题 → 导语 → 三组卖点（图标 + 标题 + 描述）→「开始使用」按钮

文字信息多、视觉焦点分散，首屏缺少主视觉。本次改版：

- 在弹窗顶部增加一张欢迎图，作为首屏主视觉；
- 删除中间三组卖点说明，减少文字；
- 主标题与副标题横向居中，形成「欢迎图 → 主标题 → 副标题 → 主按钮」的简洁结构；
- 不改变一次性展示逻辑：老用户升级后不重弹，新安装/清除数据后首次进入首页看到新版。

### 成功标准

- 新用户首次进入首页能看到新版弹窗：顶部欢迎图左右贴弹窗边缘、高度等比；主标题、副标题居中；三组卖点不再出现；「开始使用」可正常关闭。
- 已看过旧版弹窗的老用户升级后不看到新版弹窗，欢迎标记不被重置或迁移。
- 浅色/深色、中文/英文、内容超高、图片资源失败等边界均按本 PRD 与 AC 表现，不出现非预期的溢出、文字裁切、无法关闭或红屏。

## 3. 范围

### 3.1 本次做

- 欢迎弹窗顶部新增欢迎图：位于主标题之上，左右贴弹窗边缘，宽度等于弹窗宽度，高度按原始宽高比等比缩放，顶部两角随弹窗 16dp 圆角裁切。
- 删除原三组卖点：不再渲染麦克风 / 手机 / 锁图标及其标题、描述。
- 主标题、副标题横向居中；副标题沿用现有导语文案。
- 保持一次性门控、关闭方式、按钮行为与既有日志事件不变；老用户升级后不重弹。
- 覆盖深色 / 浅色主题下的图片可辨识性。
- 覆盖中英文文案与布局，确保不截断、不重叠、不越界。
- 覆盖内容超高时的滚动降级、欢迎图资源失败时的可用性降级。

### 3.2 明确不做

- 不改变欢迎弹窗的展示入口、触发时机与检查顺序（仍在首页首帧渲染后检查）。
- 不改变关闭方式：`barrierDismissible` 保持 `false`，只允许「开始使用」按钮和系统返回键关闭；保留连点保护。
- 不重置、不迁移老用户的欢迎标记；不向已看过旧版弹窗的老用户重弹（Q4 用户明确选 A）。
- 不新增权限申请、权限文案、网络请求或远程图片；欢迎图为本地打包资源。
- 不做折叠屏展开 / 折叠、分屏、悬浮窗的专项布局；弹窗按可用宽度自适应，不新增形态专属行为。
- 不做系统字体缩放、无障碍读屏的专项适配（理由见 7.2）。
- 不新增欢迎流程页面、引导步骤、轮播或入场动画。
- 不改欢迎弹窗以外的页面。
- 不为欢迎图新增多语言版本（图中不含需要随语言切换的文字）。

## 5. 功能需求

### REQ-1 顶部欢迎图

- 欢迎图位于弹窗内容最上方，在主标题之上。
- 图片宽度等于弹窗宽度，左右贴弹窗边缘，水平留白 0dp；弹窗本身距屏幕左右各 20dp 的 inset 不变。
- 图片顶部两角随弹窗 16dp 圆角裁切，图片像素不得超出弹窗边界。
- 图片高度按原始宽高比等比缩放，不设固定高度；不得拉伸、压扁或裁切图片内容（圆角裁切除外）。
- 欢迎图为本地打包资源，不发起网络请求；图片内不含需要随语言切换的文字。
- 验收：AC-1、AC-2、AC-3、AC-4、AC-16。

### REQ-2 删除中间三组卖点

- 不再渲染原三组卖点（麦克风 / 手机 / 锁图标 + 标题 + 描述），中文和英文界面均不出现。
- 原导语保留，作为新版副标题。
- 以下文案 key 不再被欢迎弹窗引用：`welcomeFeat1Title` / `welcomeFeat1Desc`、`welcomeFeat2Title` / `welcomeFeat2Desc`、`welcomeFeat3Title` / `welcomeFeat3Desc`。开发可清理；清理前需全局搜索确认无其他页面引用，若仍有引用则保留 key 但不在欢迎弹窗渲染。
- 验收：AC-5。

### REQ-3 主标题横向居中

- 主标题文本在弹窗内容区水平居中；多行时每一行均居中。
- 字号、字重、颜色沿用现有欢迎弹窗主标题样式，不因居中改变。
- 验收：AC-6、AC-15。

### REQ-4 副标题横向居中

- 副标题使用现有导语 `welcomeIntro`，在弹窗内容区水平居中；多行时每一行均居中。
- 字号、颜色沿用现有导语样式（15sp / `onSurfaceVariant`），不新增文案。
- 中文文案：「说一句话，让手机替你做事。」；英文文案：`Say it, and let your phone do it.`
- 验收：AC-7、AC-8、AC-15。

### REQ-5 一次性展示与升级兼容

- 欢迎标记沿用 `welcome/welcome_dialog_shown_v1`（应用支持目录下），内容 `1` 表示已展示。
- 标记为 `1` 时不展示；标记不存在或内容为 `0` 时展示；读取失败按「未展示」处理，记录既有错误日志。
- 展示前写入标记 `1`；写入失败记录既有错误日志后继续展示（下次可能重复，沿用现状）。
- 已看过旧版弹窗、标记为 `1` 的老用户，覆盖安装新版本后首次启动不展示新版弹窗；不迁移、不重置标记。
- 关闭方式保持：点击「开始使用」或按系统返回键关闭；`barrierDismissible` 为 `false`；连点保护保持。
- 生命周期：切后台回前台弹窗保持且不重复叠加；进程在弹窗展示期间被杀、重新启动进入首页时不再展示（标记已在展示前写入）。
- 既有 `WelcomeLog` 的 check / mark / shown / dismissed / error 事件触发时机不变，不新增埋点。
- 验收：AC-9、AC-10、AC-11、AC-17。

### REQ-6 内容超高时的降级

- 弹窗最大高度保持屏幕高度的 80%。
- 当弹窗可用高度不足以完整显示欢迎图、主标题、副标题时，图片与文字区域应可纵向滚动；底部「开始使用」按钮保持固定、可见、可点击。
- 滚动区域初始位置在顶部，从欢迎图开始展示；用户可向下滚动查看主标题和完整副标题。
- 不通过压缩图片、裁切文字或隐藏按钮来强行适配；滚动区域内不出现溢出提示或文字裁切。
- 该降级方式会改变现有「标题固定、仅中部滚动」的行为：空间不足时主标题随内容滚动，主按钮仍固定。取舍理由：主按钮可用性优先于标题始终可见，避免新增图片把标题和按钮挤出弹窗。
- 验收：AC-12。

### REQ-7 欢迎图资源失败时的降级

- 当欢迎图使用本地图片资源，且资源缺失或解码失败时，弹窗仍应展示主标题、副标题和「开始使用」按钮；图片区域留空或显示占位。
- 弹窗必须可以正常关闭；不出现无法关闭的空白弹窗、未捕获异常红屏或阻塞其他交互。
- 图片加载失败不新增专项埋点；调试构建可通过 Flutter 运行日志排查。
- 验收：AC-13。

### REQ-8 深色 / 浅色主题可辨识

- 浅色主题弹窗背景为 `#FFFFFF`，深色主题背景为 `#161920`（沿用现有主题）。
- 欢迎图在两种背景下均应清晰可辨：图片主体轮廓完整，不出现与当前背景同色而导致不可见的区块。
- 标题、副标题继续使用主题 `onSurface` / `onSurfaceVariant`，不因本次布局改动降低对比度。
- 允许设计使用单张自适应素材或深浅两套素材；验收只看两种主题下的可辨识结果。
- 验收：AC-14。

### REQ-9 中英文文案与布局

- 中文：主标题「欢迎使用 DoDroidAI」、副标题「说一句话，让手机替你做事。」、按钮「开始使用」。
- 英文：主标题 `Welcome to DoDroidAI`、副标题 `Say it, and let your phone do it.`、按钮 `Get started`。
- 两种语言下主标题、副标题、按钮不出现文字截断、重叠或超出弹窗边界；副标题可换行并保持居中。
- 欢迎图不含需要随语言切换的文字，中英文共用同一张图；品牌名 `DoDroidAI` 如出现在图中不需要翻译。
- 验收：AC-8、AC-15、AC-16。

## 7. 边界与异常

### 7.1 需求内边界

| 边界条件 | 处理口径 | 对应 AC |
| --- | --- | --- |
| 弹窗可用高度不足以显示欢迎图、标题、副标题 | 图片与文字区域纵向滚动，底部按钮固定可见可点；初始滚动位置在顶部 | AC-12 |
| 欢迎图资源缺失或解码失败 | 图片区域留空或占位，标题、副标题、按钮正常展示且可关闭 | AC-13 |

| 图片源宽高比与显示区域不一致 | 以宽度为基准等比缩放，不拉伸、不裁切（圆角裁切除外） | AC-4 |

### 7.2 平台 / 全局能力判断

| 项 | 判断 | 结论 |
| --- | --- | --- |
| 深色模式 | 适用。应用支持深浅色，主题 surface 分别为 `#FFFFFF` / `#161920` | 新增欢迎图必须两种主题下可辨识 → AC-14；标题、副标题沿用既有主题色 |
| 折叠屏展开 / 折叠、分屏、悬浮窗 | 不适用专项适配。目标设备为普通 Android 手机与模拟器；应用未做多形态专项布局 | 不新增形态专属 AC；弹窗按可用宽度自适应，图片仍贴边、等比，超高按 AC-12 滚动 |
| 生命周期（切后台回前台、进程被杀） | 适用。欢迎标记在展示前写入；切后台回前台弹窗保持且不重复；进程被杀后重启不会重弹 | 本需求不改变门控，生命周期行为纳入 AC-17 |
| 升级路径 | 适用。老用户旧标记 `1` 保持有效，不迁移、不重置 | 老用户覆盖安装后不重弹 → AC-10 |
| 异常（网络失败 / 超时） | 不适用。欢迎图为本地打包资源，无网络请求 | 不新增网络异常 AC |
| 异常（权限拒绝） | 不适用。本需求不申请任何运行时权限 | 不新增权限异常 AC |
| 异常（存储满） | 仅影响既有欢迎标记写入 | 沿用「记录后继续展示」，不新增 AC |
| 系统字体缩放 | 不在本需求范围。理由：应用未系统性适配字体缩放；本需求不新增专项 AC | 布局在可用高度不足时按 AC-12 滚动；不单独验证字体缩放 |
| 无障碍读屏 | 不在本需求范围。理由：应用未系统性适配读屏；欢迎图为装饰性主视觉，不承载必须朗读的信息 | 不新增读屏专项 AC；图片作为装饰性元素，不要求提供朗读文案；标题、副标题、按钮的既有文本内容不变 |

### 7.3 异常文案

- 欢迎图加载失败不向用户展示技术错误或英文异常信息；图片区域留空或占位即可。
- 本需求不新增权限文案、网络错误文案或存储错误文案。

## 9. 监测指标

本需求不新增埋点，沿用现有 `WelcomeLog` 事件。验收时用调试构建日志核对事件仍按原时机产生。

| 指标 | 口径 | 数据来源 |
| --- | --- | --- |
| 弹窗展示次数 | 每次新版欢迎弹窗展示计 1 次，可按 entry / locale 分组 | `WelcomeLog.shown`（既有 `welcome_shown` 事件） |
| 关闭方式分布 | 统计按钮关闭与系统返回关闭的占比 | `WelcomeLog.dismissed`（method 字段） |
| 弹窗可见时长 | 从展示到关闭的毫秒数，用于观察新版内容是否被快速关闭 | `WelcomeLog.dismissed`（visibleMs 字段） |
| 欢迎标记写入 | 标记写入成功 / 失败次数 | `WelcomeLog.mark`（success / error） |
| 门控检查 | 展示 / 不展示及原因（无标记、已标记、读取失败） | `WelcomeLog.check`（show / reason / entry / locale） |
| 异常 | 读取、写入、渲染阶段异常 | `WelcomeLog.error`（stage） |

验收观察：

- 新用户首次进入首页应产生 `welcome_shown`，关闭时应产生 `welcome_dismissed`，method 与操作一致。
- 老用户携带旧标记升级后不应产生 `welcome_shown`。
- 欢迎图资源失败时，弹窗仍应产生 `welcome_shown`，关闭时仍应产生 `welcome_dismissed`；不因图片失败中断事件。
- 图片资源失败不新增专项埋点；其可用性由 AC-13 验证，异常排查使用 Flutter 运行日志，不承诺写入既有 `WelcomeLog`。

## 10. 歧义扫描

| 类型 | 发现 | 处理 |
| --- | --- | --- |
| 互相矛盾 | 现有实现「标题固定、仅中部滚动」；新增图片置顶后若继续固定标题，图片可能把标题和按钮挤出弹窗 | 优先级定为「主按钮可用 > 标题始终可见」：空间不足时图片 + 标题 + 副标题一起滚动，按钮固定；写入 REQ-6 / AC-12 |
| 无法判定 | 「副标题」在现有代码中没有同名控件，只有标题下的导语 | 按 Q2-A，将 `welcomeIntro` 作为副标题；AC-8 锁定中英文文案，AC-7 锁定居中 |
| 无法判定 | 「宽度撑满弹窗」可理解为贴边或内容区内撑满 | 按 Q3-A，贴边铺满，水平留白 0dp；AC-2 锁定 |
| 无法判定 | 「横向居中」没有测量口径 | 定义为文本块水平中心与弹窗内容区中心偏差 ≤1dp；多行逐行居中；AC-6 / AC-7 锁定 |
| 缺边界 | 三组卖点的删除范围用户未回答 | 按 Q1 推荐值转为假设 A1：整组删除；AC-5 锁定图标、标题、描述均不出现 |
| 缺边界 | 小屏 / 横屏 / 可用高度不足时内容超高 | 定义为图片与文字可滚动、按钮固定；AC-12 |
| 缺边界 | 欢迎图资源缺失或解码失败 | 定义为留空 / 占位、其余内容可用且可关闭；AC-13 |
| 缺边界 | 老用户升级后是否重弹 | 按 Q4-A，不重弹、不迁移标记；AC-10 |
| 缺边界 | 生命周期：切后台回前台、弹窗展示期间进程被杀 | 定义为弹窗保持且不重复叠加；进程被杀后因标记已写入不再展示；AC-17 |
| 缺边界 | 欢迎标记读取 / 写入失败 | 沿用现状：读失败按未展示、写失败记录后继续展示；不新增 AC |
| 平台能力 | 深色模式 | 应用支持深浅色，新增图片纳入 AC-14；标题 / 副标题沿用主题色 |
| 平台能力 | 折叠屏 / 分屏 / 悬浮窗 | 明确不做专项适配，理由：应用未做多形态专项布局；弹窗按可用宽度自适应 |
| 平台能力 | 系统字体缩放、无障碍读屏 | 明确不做专项适配，理由：应用未系统性适配；本需求只保证布局在可用高度不足时滚动（AC-12），读屏不要求为装饰图提供朗读文案 |
| 悬空引用 | 无页面 / 接口 / 字段 / 权限引用缺失 | `welcomeTitle` / `welcomeIntro` / `welcomeStart` / 欢迎标记路径 / `WelcomeLog` 均在现有代码中存在；无新增页面、接口、权限；欢迎图资源路径由设计阶段产出，PRD 不引用具体路径 |

扫描结论：

- 无未解决的互相矛盾；标题可见性与按钮可用性的取舍已明确写入 REQ-6。
- 无法判定项均已通过用户回答或可测量口径补齐。
- 需求内边界均已转为可判定的 AC；平台 / 全局能力已逐项写明适用范围或明确不做。
- 无悬空页面、接口、字段、权限引用。
