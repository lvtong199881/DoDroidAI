### 3.3 建议（可改可不改，记录即可）

#### R-01 硬编码的 `right: -4` 把几何关系写死，建议由常量推导

- 位置：`flutter_app/lib/widgets/welcome_dialog.dart:244-246`
- 证据：`right: -4` 由 `welcomeCloseHitSize / 2 - welcomeDialogInset`（24 − 20）推导而来，代码里直接写死。当前 20dp 内边距下圆心正好落在卡片右边缘；若后续设计把卡片内边距改成 24dp、或把命中盒改成 44/52dp，这个 `-4` 不会跟着变，圆心会偏离卡片右上角，50% 露出也会失真。
- 风险：几何常量与实现脱钩；测试只覆盖当前 20dp 卡片，改常量时不一定能立刻发现。
- 改法：改为 `right: -(welcomeCloseHitSize / 2 - welcomeDialogInset)`，或新增 `welcomeCloseRightOffset` 命名常量并注释推导；同时保留“圆心 = 卡片右上角”的几何断言。

#### R-02 AC-4 只量了 48dp 渲染盒，没有覆盖“实际可点宽度”

- 位置：`flutter_app/test/welcome_dialog_test.dart:646-650`
- 证据：测试断言 `closeHitRect.width == 48`，但角标 `Positioned(right: -4)` 使命中盒右边缘在 360dp 屏幕上到 364dp，右侧 4dp 在屏幕外；在 `DialogRoute` 的 `SafeArea` 有水平内边距时，这 4dp 还可能落在屏幕内但超出外层 `Stack`，同样不可命中。实际可点宽度约为 44dp（320dp 屏同理）。
- 风险：AC-4 的“命中区 ≥48dp”在测试里只被渲染盒尺寸覆盖，没有被真实命中测试覆盖；以后如果把按钮继续外移，测试仍会通过。技术方案 §4.3 已接受这 4dp 出屏，因此这不是要求实现改布局，而是测试口径需要说清楚。
- 改法：补一条在屏幕最右侧可见像素附近的点击用例（例如 `Offset(screenWidth - 1, card.top)`），或对 `closeHitRect` 与屏幕/Stack 矩形求交后断言可见宽度；至少在该测试注释中写明“右侧 4dp 出屏为设计接受项，主要可点区域为 44×48”。

#### R-03 AC-14 只断言了语义动作存在，没有真正走一次语义激活

- 位置：`flutter_app/test/welcome_dialog_test.dart:780-800`
- 证据：测试断言 `label == '关闭'`、`isButton`、`hasAction(SemanticsAction.tap)`，但随后用 `handlePopRoute()` 关闭弹窗，没有执行语义 `tap`。指针点击用例走的是 `GestureDetector.onTap`，与 `Semantics.onTap` 是两条路径；如果 `Semantics.onTap` 接错或漏接，现有测试仍会全绿，而 TalkBack 激活会失效。
- 风险：AC-14“可被读屏激活”没有被自动化覆盖，只能靠真机手工兜底。
- 改法：在语义测试中真正执行一次 `SemanticsAction.tap`（对 `getSemantics(...).id` 调 `performAction`），断言弹窗关闭且结果为 `closeButton`；英文用例可只保留名称断言，避免重复关闭。

#### R-04 AC-12 集成用例与首个用例重复，建议抽公共流程

- 位置：`flutter_app/integration_test/welcome_flow_test.dart:80-114`
- 证据：新用例与文件开头 `36-78` 的“清标记 → pump → 等弹窗 → 关闭 → 读标记 → 新 ProviderScope 不再弹 → 清理”几乎逐行重复，只差“点开始使用”和“点角标”。同时 `81` 行调用了 `SharedPreferences.setMockInitialValues({})`，但欢迎标记实际是 `FileWelcomeFlagStore` 的文件，不是 SharedPreferences；该调用对被测目标没有作用，容易让读者误以为标记走的是 SharedPreferences。
- 风险：两套启动/清理逻辑将来容易改一漏一；无关的 SharedPreferences mock 会掩盖真实插件行为。
- 改法：抽出 `Future<void> runWelcomeFlow(WidgetTester tester, {required Finder dismissTarget})`，两个用例分别传 `find.byKey(_startKey)` 和 `find.byKey(welcomeDialogCloseKey)`；删除文件标记场景下的 `SharedPreferences.setMockInitialValues`，或注释说明它服务于其它 app 设置。

#### R-05 `pumpAndSettle(Duration)` 的第一个参数不是超时

- 位置：`flutter_app/integration_test/welcome_flow_test.dart:90,108`（旧用例 `46,71` 也是同样写法）
- 证据：`WidgetTester.pumpAndSettle([Duration duration = 100ms, EnginePhase phase, Duration timeout = 10min])` 的第一个位置参数是**每次 pump 的步长**，不是超时；`pumpAndSettle(const Duration(seconds: 1))` 会以 1 秒为步长反复 pump，真正的超时仍是默认 10 分钟。新用例沿用了旧写法。
- 风险：测试意图（“最多等 1/2 秒”）与行为不一致；在带周期动画或定时器的场景里，读代码的人会误判等待上限。
- 改法：若只是想推进一帧，用 `await tester.pump(const Duration(seconds: 1))`；若要限时，用 `pumpAndSettle(timeout: const Duration(seconds: 1))`；若只是等稳定，直接 `pumpAndSettle()`。

#### R-06 两处几何注释容易误读，建议补全

- 位置：`flutter_app/lib/widgets/welcome_dialog.dart:13-14`、`242-243`
- 证据：`welcomeDialogInset` 的注释是“（= 屏宽 − 卡片宽 的一半）”，缺少括号，可能被读成 `屏宽 − 卡片宽/2`；`Positioned` 上方注释写“右边超出 Stack 4dp，即屏幕右侧外 4dp”，但 `DialogRoute` 会在 `Dialog` 外包 `SafeArea`，有水平安全区时 `Stack` 宽度不等于屏幕宽度，这 4dp 可能在屏幕内但超出 `Stack`。
- 风险：后续维护者按错误口径调整常量或判断可点范围。
- 改法：把注释写成 `= (屏宽 − 卡片宽) / 2` 或直接写“卡片左右各 20dp”；把“屏幕右侧外 4dp”改成“超出 Stack 4dp；窄屏/安全区下以可见像素为准”。
