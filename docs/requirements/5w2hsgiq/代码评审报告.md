#### R-01（建议）标题/副标题文案断言不足

- **位置**：`flutter_app/test/welcome_dialog_test.dart:123-132`（`expectCentered`）、`:153-154`、`:220-221`。
- **证据**：`expectCentered` 只断言 `Text.textAlign` 和控件矩形中心，未读取 `Text.data`；中文用例只按 `_titleKey` / `_subtitleKey` 查找控件，未与 `strings.t('welcomeTitle')` / `strings.t('welcomeIntro')` 绑定；英文用例按全文 `find.text(...)` 断言，也未按 Key 区分标题与副标题。
- **风险**：如果两个 Key 对应的 l10n key 被互换，或标题误用副标题文案，两个用例仍会通过；用户会看到标题/副标题内容错位，而单测无法发现。
- **方向**：给 `expectCentered` 增加 `expectedText` 参数，或在用例中分别断言 `tester.widget<Text>(find.byKey(_titleKey)).data == strings.t('welcomeTitle')`、`...(_subtitleKey)).data == strings.t('welcomeIntro')`；英文用例同样按 Key 断言，不只按全文查找。

#### R-02（建议）缺失资源用例依赖固定 200ms 真实等待

- **位置**：`flutter_app/test/welcome_dialog_test.dart:248-251`。
- **证据**：`tester.runAsync` 内固定 `Future.delayed(200ms)`，随后 `pumpAndSettle`；没有确认 `AssetImage` 的加载失败已经投递到 `errorBuilder`，也没有上限/重试。
- **风险**：慢 CI、冷缓存或杀软扫描时 200ms 可能不够，`find.byKey(_heroKey)` 仍存在，用例偶发失败；快机器上又会白等 200ms。
- **方向**：改为有上限的轮询（例如每次 `runAsync` 等 50ms，再 `pump`，最多 2s，hero 消失即停），或注入可同步失败的 `ImageProvider` / `AssetBundle`，从根本上移除对真实 IO 时序的依赖；超时断言里输出当前 hero 是否存在，便于定位。

#### R-03（建议）主题切换与失败重置缺少自动化覆盖

- **位置**：`flutter_app/test/welcome_dialog_test.dart:235-239`（只覆盖启动时深色选图）；`flutter_app/lib/widgets/welcome_dialog.dart:47-52`（`heroAssetOverride` 短路主题选图）、`:60-61`（`_failedHeroAsset` 重置判定）。
- **证据**：`openWelcome` 固定 `themeMode: ThemeMode.light`，用例期间没有触发 brightness 变化；`heroAssetOverride` 是单一固定路径，非空时直接返回，无法同时模拟“浅色失败、深色成功”的两套素材，因此切换时失败标记重置这一分支没有测试守护。
- **风险**：后续若有人把 `_resolveHeroAsset` 改成只读一次，或改动 `_failedHeroAsset` 的重置条件，单测不会发现；弹窗打开期间切主题可能显示错误素材，或一直保持折叠。
- **方向**：增加一个不注入 override 的用例，用 `ValueNotifier<ThemeMode>`/重建 `MaterialApp` 在弹窗打开后切换 light→dark→light，断言 `heroAssetName` 随之切换；若还要覆盖失败重置，可用按路径抛错的 fake `AssetBundle` 让浅色失败、深色成功，再切主题断言 hero 恢复，无需扩大生产 API。
