### R1（应修）集成测试硬编码中文，英文系统设备上必失败

- 位置：`flutter_app/integration_test/welcome_flow_test.dart:51`
- 证据：
  - 同一条用例上一行（`:50`）已用 `welcomeDialogAiHintKey` 做与语言无关的断言，`:51` 又写死中文 `'随时可以在设置里改 AI 配置'`。
  - 该用例通过 `SharedPreferences.setMockInitialValues({})` 清掉语言偏好（`:37`），`LocaleController` 初始为 `null`（`lib/settings/app_settings.dart:38-48`），`MaterialApp` 直接使用设备 locale（`lib/app.dart:17,24,31`）。
  - `AppStrings` 对 `en` 返回英文（`lib/l10n/app_strings.dart:152`）。因此真机/模拟器为 en-US 时，弹窗渲染英文，`find.text(中文)` 必然 `findsNothing`。
- 风险：集成测试在默认 en-US 模拟器或英文真机上稳定失败，测试阶段会被误判为「说明行没显示」的功能缺陷；该断言与 `welcome_copy_test.dart` / `app_strings_test.dart` 的逐字断言重复。
- 改法（任选其一，推荐第 1 或第 2）：
  1. 删除 `:51` 的字面量断言，保留 `:50` 的 key 断言；文案逐字已由 `welcome_copy_test.dart`、`app_strings_test.dart` 锁定。
  2. 按当前 locale 解析期望值，例如：
     ```dart
     final dialogContext = tester.element(find.byType(WelcomeDialog));
     final hint = AppStrings(Localizations.localeOf(dialogContext)).t('welcomeAiHint');
     expect(find.text(hint), findsOneWidget);
     ```
  3. 在 `pumpWidget` 前把语言偏好固定为 `zh`（写入 `locale` prefs 或 override `localeProvider`），但会削弱该用例对真实语言环境的覆盖。

### S1（建议）类级文档未同步说明行

- 位置：`flutter_app/lib/widgets/welcome_dialog.dart:69-73`
- 证据：类注释仍写「贴边欢迎图、居中主标题与副标题、固定底部按钮」，未提及本次新增的说明行。
- 风险：类注释是 `WelcomeDialog` 的结构契约，后续维护者容易漏掉标题区的第三个文本节点。
- 方向：把「居中主标题与副标题」改为「居中主标题、说明行与副标题」，其余不变。

### S2（建议）断言框架默认 150ms 路由时长，与 Flutter 实现耦合

- 位置：`flutter_app/test/welcome_dialog_test.dart:1318-1324`
- 证据：`showDialog` 未传时长，`route.transitionDuration == 150ms` 来自 Flutter `DialogRoute` 的默认值（`material/dialog.dart`）；本仓库没有在任何地方声明或控制这个值。
- 风险：Flutter 升级调整默认过渡时长时，该断言会失败，但产品行为没有任何回归；测试失败原因会误导排查方向。
- 方向：保留同一 `FadeTransition` 祖先的身份断言（这是「与主标题共享淡出」的真正契约），删除两条 150ms 断言；若 150ms 是产品契约，则在宿主 `showDialog` 显式传 `animationStyle`（或自定义 route）把值变成应用自己的契约，再断言。

### S3（建议）英文 320dp 下说明行换行/滚动未覆盖

- 位置：`flutter_app/test/welcome_dialog_test.dart:1215-1237`（AC-11 仅中文）、`:1239-1258`（AC-12 仅 360dp 2x 中文）
- 证据：英文文案 50 字符，约为中文说明行的 3.5 倍；320dp 内容宽 232dp 时至少换行成 2–3 行，而现有新增用例没有覆盖「英文 + 最小宽度」组合。
- 风险：§10 的 R2（换行变多把内容挤出可视区）在小屏英文下没有被直接验证；即使当前 `SingleChildScrollView` 能兜底，后续误把说明行挪进 footer 也不会被这组用例发现。
- 方向：补一条 320×640 + `en` 用例（可再叠加 2x），断言无 overflow 异常、说明行高度大于单行行高（确实换行）、主按钮完整可见可点。
