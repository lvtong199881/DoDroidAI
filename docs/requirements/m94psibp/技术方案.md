## 4. 方案总览

**唯一功能改动**：把主按钮的 `child` 从纯 `Text` 改为一个居中的行内组合——`ExcludeSemantics(Icon(Icons.arrow_forward, size: 20, color: onPrimary))` + `SizedBox(width: 8)` + `Flexible(Text(strings.t('welcomeStart')))`；`FilledButton` 本身、`key`、`style`、`onPressed`、`_closing` 保护全部保持不变。

行为与布局要点：

1. **水平**：`FilledButton` 默认 `alignment: Alignment.center`，行内组合按内容宽度居中。单行时「图标 + 8 + 文字」整组居中（中文 1x 组宽约 88dp，与设计 F01 的 88dp 量测一致）；文字换行时行宽占满按钮内容宽，图标贴内容左缘、文字左对齐，符合设计 F08 的换行形态。
2. **垂直**：行内 `crossAxisAlignment` 默认 `center`；图标中心与文字盒中心重合。单行时文字盒高 = 15×1.2 = 18dp，行高由 20dp 图标决定，文字在 20dp 行内居中，图标中心 = 文字中线；多行时图标随文字块整体居中（AC-3 只要求不截断/不重叠）。
3. **不缩放**：`Icon.size` 固定 20dp；Flutter `Icon` 默认不随 `textScaler` 缩放（不设置 `applyTextScaling`）。文字仍按系统字号缩放并允许换行，按钮高度可增加（PRD A-3）。
4. **不加手势**：图标不是独立可点击控件，点击命中由按钮的 `InkWell` 统一处理，因此点图标 = 点按钮，仍走 `_close(WelcomeDismissMethod.button)`。
5. **不加语义**：图标不设 `semanticLabel`，并用 `ExcludeSemantics` 显式包住；按钮的可访问名称只由 `Text` 提供，保持「开始使用 / Get started」。
6. **不改基线**：不设置按钮 padding、不换 `FilledButton.icon`、不改 `minimumSize`、不改 footer 结构，避免 AC-10 出现非预期差异。设计说明 §6.6 的「建议固定 padding」不采纳（见 §9）。

**被否掉的替代方案**：

- `FilledButton.icon`：会引入组件默认的图标尺寸、间距、padding 与布局分支，1x 下按钮高度/内容宽度可能变化，直接威胁 AC-10；且图标与 label 的语义合并行为需要额外验证，不如在现有 `child` 内显式构造可控。
- `Stack` / `Positioned` 把图标钉在文字左侧：脱离行内流式布局，2x/换行时容易与文字重叠或越界，无法自然满足 AC-3。
- `Text.rich` / `WidgetSpan`：会把图标混进文本排版，`find.text`、语义与换行行为都更难控制，且没有收益。
- 图片资源或自绘 `CustomPaint`：违反「不引入外部图标素材」；Material `arrow_forward` 已随包提供。
- 只改 `IconTheme`：无法新增图标节点，且不能保证 20dp/8dp 的精确几何。

## 8. 影响面

### 8.1 受影响的既有功能

- **主按钮**：内容区新增 20dp 图标与 8dp 间距；1x 下按钮高度仍由 48dp 最小高决定，宽度仍为全宽；文字因整组居中右移约 `(20+8)/2 = 14dp`（设计说明 §5.1 已明确该副作用）。这是「新增箭头」的必然结果，AC-10 只约束文案与弹窗宽高，不约束文字 x 坐标。
- **2x 字体/320dp**：相对同字号下不加图标，文字可用宽度少 28dp（图标 20 + 间距 8），英文可能提前换行或按钮增高；PRD A-3/§7 明确允许，按钮仍须完整在弹窗内、内容不截断/不重叠。注意 Material 3 按钮的水平 padding 会随字号缩放（1x 约 24dp、2x 约 12dp），因此 320dp+2x 英文不一定像设计 F08 那样变两行/100dp 高，可能仍单行、按钮 48dp；两种结果都满足 AC-3，测试不得断言固定 100dp 或固定行数。
- **右上角关闭角标、可选「去配置AI」、欢迎图、标题/导语、滚动区**：不触碰，行为与布局不变。
- **一次性展示、首次/二次启动、升级路径**：不触碰 `welcome_flag_store` 与 `WelcomeController`，行为不变。
- **日志**：不新增/不修改事件与字段；主按钮路径仍为 `welcome_dismissed method=button`，返回键仍 `method=back`，`configureAi`/`closeButton` 路径不受影响。
- **无障碍**：按钮可访问名称不变；新增图标必须不产生独立节点（否则 AC-8 失败）。这是本需求唯一需要特别防范的「隐性行为变化」。

### 8.2 调用方与被调用方

- 调用方：`chat_screen.dart::_presentWelcome` 只构造 `WelcomeDialog(showConfigureAi: ...)`，不感知按钮内部结构，无需改动。
- 结果消费方：`WelcomeController` 只消费 `WelcomeDismissResult.method/visibleMs`，无需改动。
- 测试调用方：`welcome_dialog_test.dart`、`welcome_app_test.dart`、`integration_test/welcome_flow_test.dart` 通过 `find.byType(FilledButton)` / `find.text` / `find.byKey` 定位，新增图标不改变这些定位结果；如后续新增对子结构的断言，只调整测试，不改产品代码。

### 8.3 数据、配置与迁移

- 无数据库、无表/字段、无 API、无持久化 flag 变更；无需数据迁移。
- 无新增权限、无新增依赖、无新增资源、无新增文案 key、无新增环境变量。
- `pubspec.yaml` 的 `uses-material-design: true` 已满足 `arrow_forward` 字体随包；不需要改构建配置。

### 8.4 测试与验收影响

- 既有测试：`test/` 下 25 个 Dart 文件（含 support）预计全部通过；`welcome_dialog_test.dart` 中「文字不设 maxLines/ellipsis」「320dp 窄屏」「2x 字号小屏」「连点只关闭一次」「英文文案」等用例继续有效。
- 需要新增的测试见 §7 T3～T5；不改既有断言的语义，避免「用测试迁就实现」。
- AC-1/AC-2/AC-3 的验证方式原写「uiautomator 结构树」；Flutter 的 `Icon` 不是原生 View，且 REQ-3 要求图标不进语义树，uiautomator 看不到图标节点。验收口径调整为：图标存在/尺寸/间距/颜色以 Flutter widget test + 截图量测为准；uiautomator 仅用于按钮/弹窗 bounds 辅助（见 §9 第 12 条、§11）。

### 8.5 发布与回滚影响

- 纯 UI 改动，无数据/契约变更，回滚成本低（见 §10）。
- debug 构建日志仅用于验收；release 不输出 `DebugWelcomeLog` 属预期，不影响线上。
