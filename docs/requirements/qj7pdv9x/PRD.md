# PRD：欢迎弹窗右上角关闭按钮

## 0. 文档信息

| 项 | 内容 |
| --- | --- |
| 需求名称 | 欢迎弹窗右上角关闭按钮 |
| 平台 | Android（Flutter） |
| 版本 | v1.0（定稿） |
| 依据 | 用户原始需求 + 《待提问清单.md》Q1–Q5 的用户回答（均选 A） |
| 关联文档 | `需求卡片.md`（验收标准编号来源）、`待提问清单.md` |

## 1. 背景与问题

DoDroidAI 在首次启动时展示一次性欢迎弹窗（`WelcomeDialog`）：2:1 贴边欢迎图、居中标题与副标题、底部固定「开始使用」按钮，展示前即写入「已展示」标记，之后不再出现。

现有关闭方式只有底部「开始使用」和系统返回键，弹窗右上角没有显式关闭入口。用户如果不想看完整介绍，只能去找底部按钮或按返回键，不符合系统弹窗的常见操作习惯。本需求在弹窗右上角增加一个「卡在边缘」的关闭按钮，让用户随时可以退出欢迎流程。

## 2. 目标与非目标

### 2.1 目标

- G1：欢迎弹窗右上角有一个显式关闭按钮，视觉上卡在弹窗右上角，约一半露出弹窗外。
- G2：点击关闭与点击「开始使用」等价，关闭后不再展示；不改变欢迎内容与现有门控。
- G3：关闭入口可度量：新增 `close_button` 关闭方式，能与主按钮、返回键区分。
- G4：在浅色/深色、320dp 窄屏、小屏滚动、2 倍字号、欢迎图缺失、读屏、连点等边界下都可见、可点、只关一次。

### 2.2 非目标

- 不改欢迎弹窗的文案、欢迎图、标题/副标题、底部主按钮的样式与行为。
- 不改一次性展示门控、启动入口判断、单飞检查。
- 不给其它弹窗或页面加关闭按钮。
- 不做全局无障碍、折叠屏/分屏专门适配或线上埋点体系。

## 3. 用户与场景

| 场景 | 用户诉求 | 本需求对应 |
| --- | --- | --- |
| 首次启动，用户想直接开始使用 | 不用看完介绍，随手关掉 | 点右上角 X，立即回首页 |
| 小屏或大字号，内容需要滚动 | 滚到一半也想退出 | X 钉在弹窗右上角，不随内容滚动 |
| 欢迎图加载失败 | 仍要能退出 | 图片区折叠，X 保持原位，不压标题 |
| 窄屏 320dp | 按钮不能被屏幕裁掉 | X 完整位于屏幕内 |
| 深色模式 | X 在深色欢迎图上仍看得清 | 按钮有独立底色，对比度 ≥ 3:1 |
| 读屏用户 | 知道这是关闭按钮 | 读屏朗读「关闭 / Close」，角色为按钮 |
| 误触连点 | 不要重复关闭或黑屏 | 只关闭一次 |

## 4. 范围

**本需求包含：**

- `WelcomeDialog` 右上角新增关闭按钮：位置、露出比例、层级、可点击区域、深浅色可读性、窄屏/滚动/无图边界。
- 关闭结果新增 `closeButton` 取值；`welcome_dismissed` 日志新增 `method=close_button`。
- 中英文可访问名称。
- 更新现有「没有右上角关闭按钮」的测试断言，新增位置、点击、连点、日志、语义相关测试。
- 回归底部主按钮、遮罩、系统返回键与欢迎内容布局。

**不在本需求：** 见 §5。

## 5. 明确不做的事

| 不做的事 | 理由 |
| --- | --- |
| 给工具确认框、提问面板等其它弹窗加关闭按钮 | 用户只要求欢迎弹窗；其它弹窗的关闭习惯另行评估。 |
| 修改欢迎图、标题、副标题、底部「开始使用」 | 本需求只增加关闭入口，不改内容与主行动。 |
| 修改一次性展示门控、标记写入时机、启动入口判断 | 关闭方式不改变是否展示的判定。 |
| 修改遮罩点击不关闭、系统返回键可关闭 | 现有行为保留，新增入口不动旧入口。 |
| 折叠屏展开/折叠、分屏、悬浮窗的专门布局 | 应用现有页面没有针对这些形态的专门适配；本需求只增加一个随弹窗几何定位的按钮，不新增断点或特殊布局。 |
| 全局无障碍改造 | 只保证本按钮有可访问名称与按钮角色，不承诺全应用读屏适配。 |
| 新增 release 埋点、后端上报、数据库或存储结构 | 现有欢迎日志只在 debug 输出；本需求沿用，不做线上统计。 |
| 修改应用图标、启动背景、主题色板 | 与本需求无关。 |

## 6. 功能清单（REQ）

### 6.1 REQ-1 关闭按钮的位置与层级

**描述**：欢迎弹窗右上角新增一个关闭按钮，视觉上卡在弹窗右上角边缘，约一半露出弹窗外；露出部分与内侧部分一样可点。

**规则**：

1. 「弹窗矩形」指弹窗 Material 的可视外接矩形（圆角外的包围盒），不含遮罩。
2. 按钮几何中心与弹窗矩形的右上角重合，水平、垂直偏差均 ≤ 1dp。
3. 按钮落在弹窗矩形外的宽度、高度分别为按钮视觉宽、高的 45%–55%（即约一半在外）；视觉尺寸不含阴影，含图形本体与底色。
4. 按钮完整渲染，不被弹窗圆角、父级裁切或遮罩遮挡；露在弹窗外的部分同样可点击。
5. 按钮层级在欢迎图与文字内容之上；正常加载的欢迎图不得盖住按钮。
6. 关闭图形应表达「关闭」语义（×）；具体图形、底色、描边、阴影、按压态由设计阶段给出。

**验收**：AC-1、AC-2、AC-3。

### 6.2 REQ-2 尺寸、可点击区域与可读性

**描述**：按钮视觉大小可小于点击区域；按钮必须在两套主题与两套欢迎图上都清晰可辨，且不遮挡关键内容。

**规则**：

1. 点击命中区域的宽、高均 ≥ 48dp。
2. 按钮必须有独立底色或等效处理，使图标与按钮底色的对比度 ≥ 3:1；该对比度不因按钮下方是欢迎图、滚动内容、弹窗背景还是遮罩而失效。
3. 在初始展示、内容未滚动时，按钮外接矩形不得与标题、副标题、底部主按钮的外接矩形相交（相切不算相交）。
4. 视觉尺寸由设计给出，但必须同时满足 320dp 窄屏完整可见（见 REQ-3）。

**验收**：AC-4、AC-5、AC-6。

### 6.3 REQ-3 固定定位、滚动与窄屏/无图边界

**描述**：关闭按钮是弹窗的固定层，不进入滚动内容；在任何滚动位置、无欢迎图、窄屏下都保持可点。

**规则**：

1. 按钮固定在弹窗右上角，不随欢迎图/文字一起滚动；内容滚到任意位置，按钮中心与弹窗右上角的偏差均 ≤ 1dp。
2. 欢迎图资源缺失、加载失败或解码失败导致图片区折叠时，按钮仍在弹窗右上角原位，保持同样的卡边效果。
3. 无欢迎图时，内容区顶部为按钮预留空间，标题、副标题不被按钮覆盖。
4. 屏幕逻辑宽度 320dp 时，按钮全部可见像素位于屏幕可绘制区域内，不被屏幕边缘裁切。
5. 以上调整不得让弹窗出现横向溢出、纵向溢出或原有内容不可滚动。

**验收**：AC-7、AC-8、AC-9。

### 6.4 REQ-4 点击关闭行为

**描述**：点击关闭按钮直接退出欢迎流程，与「开始使用」等价，不弹二次确认。

**规则**：

1. 点击一次即关闭弹窗，只发生一次路由 pop，不显示确认框，关闭后首页可交互。
2. 关闭结果返回 `closeButton`，由宿主按现有链路记录关闭方式与可见时长。
3. 一次性语义不变：展示前已写入「已展示」标记，点击关闭后不再展示；不新增「本次已关闭」状态。
4. 连点保护：第一次点击后忽略后续点击，不重复 pop、不抛异常、不黑屏。
5. 欢迎内容、滚动位置、语言、主题等不因关闭动作发生额外变化。

**验收**：AC-10、AC-11、AC-12。

### 6.5 REQ-5 关闭方式数据契约与日志

**描述**：关闭方式新增独立取值，现有日志字段与事件名保持不变。

**规则**：

1. `WelcomeDismissMethod` 新增 `closeButton`，wire 值为 `close_button`；`button`、`back` 不变。
2. 通过关闭按钮关闭时输出：
   `[welcome] welcome_dismissed method=close_button visible_ms=<非负整数>`
3. 不新增独立事件、不新增字段、不改 `visible_ms` 的口径（弹窗展示到关闭的毫秒数）。
4. 不新增数据库表、文件或存储结构；一次性标记的路径与写入时机不变。
5. 日志仍由现有 `DebugWelcomeLog` 输出，仅在 debug 构建可见；本需求不新增 release 埋点。

**验收**：AC-13；既有方法回归见 AC-16、AC-18。

### 6.6 REQ-6 多语言与无障碍

**描述**：关闭按钮没有可见文案时也必须能被读屏识别；中英文使用各自文案。

**规则**：

1. 可访问名称：中文「关闭」，英文「Close」。
2. 控件语义角色为按钮，可被读屏聚焦并激活；激活行为与点击一致。
3. 若设计增加可见文字或长按提示，复用同一文案，不另造词。
4. 不新增系统权限，不新增权限申请文案。

**验收**：AC-14。

### 6.7 REQ-7 既有行为不回归

**描述**：新增按钮不能改变欢迎弹窗原有的三个出口与内容布局。

**规则**：

1. 底部「开始使用」仍显示在弹窗底部、可点击；点击后关闭并记录 `method=button`。
2. 点击遮罩仍不关闭弹窗。
3. 系统返回键仍关闭弹窗；无返回值时宿主记为 `method=back`。
4. 欢迎图、标题、副标题、滚动行为、浅色 `#FFFFFF` / 深色 `#161920` 背景不变。

**验收**：AC-15、AC-16、AC-17、AC-18。

## 7. 交互流程

1. 冷启动，欢迎检查判定需要展示 → 写入一次性标记 → push 欢迎弹窗 → 记录 `welcome_shown`。
2. 弹窗首帧渲染：欢迎图、标题、副标题、底部主按钮、右上角关闭按钮同时可见；关闭按钮钉在弹窗右上角，约一半露出。
3. 用户点击关闭按钮（含露在弹窗外的部分）→ 命中保护置位 → 路由 pop(`closeButton`)。
4. 宿主收到关闭结果 → 记录 `welcome_dismissed method=close_button visible_ms=…` → 首页可交互。
5. 其它出口不变：
   - 点「开始使用」→ pop(`button`) → `method=button`。
   - 按系统返回键 → pop(null) → 宿主映射为 `back`。
   - 点遮罩 → 不关闭。
6. 不新增页面、路由、弹窗或跳转。

| 场景 | 期望行为 | 覆盖 |

## 9. 系统条件（逐项判断）

| 项 | 是否适用 | 结论 |
| --- | --- | --- |
| 深色模式 | 适用 | 应用支持深色主题。按钮需在浅色、深色两套欢迎图上都清晰可辨，给 AC-5；视觉色值由设计阶段给出，不硬编码只适配单主题。 |
| 折叠屏展开/折叠/分屏/悬浮窗 | 不适用 | 应用现有页面没有针对这些形态的专门布局；本需求只增加一个随弹窗几何定位的按钮，不新增断点、特殊布局或分屏行为。已在 §5「明确不做的事」记录。 |
| 生命周期：切后台回前台 | 适用 | 沿用现有路由行为，弹窗保持打开，按钮位置与可点性不变；不新增状态。 |
| 生命周期：进程被杀后恢复 | 适用 | 一次性标记在展示前写入，因此下次冷启动不再展示；本需求不新增恢复逻辑。 |
| 首次启动 vs 二次启动 | 适用 | 仍由现有一次性标记决定；本需求不改判定。首次展示时带新按钮，二次启动不展示。 |
| 升级路径 | 不适用 | 无数据库版本、存储结构或数据模型变更，不需要迁移。老用户若已写过标记，升级后不会看到欢迎弹窗，也就看不到新按钮；未写过标记的用户升级后首次启动看到新弹窗。 |
| 异常：网络失败/超时 | 不适用 | 欢迎弹窗是本地资源与本地标记，不依赖网络；网络状态不影响按钮。 |
| 异常：权限拒绝 | 不适用 | 本需求不新增任何系统权限。 |
| 异常：渲染失败 | 适用 | 沿用现有 `welcome_error stage=render` 记录，不重试、不二次展示；关闭按钮不改变该分支。 |
| 系统字体缩放 | 适用（仅回归） | 弹窗本来就支持内容滚动；按钮是图标，不随字号放大。大字号下按钮位置固定、可点，滚动区域不溢出（AC-7）；滚动过程中文字可从按钮下方经过，这是固定浮层的预期行为，不作为遮挡缺陷。 |
| 无障碍读屏 | 部分适用 | 仅为本按钮提供可访问名称与按钮角色（AC-14）；不做全应用读屏改造，已在 §5 记录。 |

## 11. 监测与日志

### 11.1 日志契约

延续现有 `[welcome]` 结构化日志，事件名与字段保持稳定，唯一变化是 `welcome_dismissed.method` 增加一个取值。

| 事件 | 字段 | 取值 | 变化 |
| --- | --- | --- | --- |
| `welcome_check` | result / reason / entry / locale | show/skip；no_flag/flagged/read_failed；cold_start/widget/notification/shortcut/other；zh/en | 不变 |
| `welcome_mark` | result / error | success/fail | 不变 |
| `welcome_shown` | entry / locale | 同上 | 不变 |
| `welcome_dismissed` | method / visible_ms | button、back、**close_button**；visible_ms 为非负整数 | **新增 close_button** |
| `welcome_error` | stage / error | read/write/render | 不变 |

- 关闭按钮必须产生 `welcome_dismissed method=close_button visible_ms=<非负整数>`。
- 不新增独立事件。
- 日志仅在 debug 构建输出（现有 `DebugWelcomeLog` 使用 `kDebugMode`）；本需求不新增 release 埋点或后端上报。

### 11.2 监测指标

以下指标用于 debug 测试与本地诊断，不作为线上统计口径。

| 编号 | 指标 | 计算方式 | 数据来源 | 用途 |
| --- | --- | --- | --- | --- |
| M-1 | X 关闭占比 | `method=close_button` 条数 ÷ 全部 `welcome_dismissed` 条数 | `welcome_dismissed` | 判断新入口是否被使用 |
| M-2 | X 关闭耗时 | `method=close_button` 的 `visible_ms` 中位数与 P90 | `welcome_dismissed` | 发现点击后未及时关闭的异常 |
| M-3 | 展示-关闭一致性 | 同一进程内 `welcome_shown` 与 `welcome_dismissed` 条数应相等 | `welcome_shown`、`welcome_dismissed` | 发现弹窗卡住或关闭未记录 |
| M-4 | 欢迎渲染异常 | `welcome_error stage=render` 条数 | `welcome_error` | 回归现有渲染异常率 |

验证方式：debug 包 logcat 过滤 `[welcome]`；单测捕获 `WelcomeLog` 调用。

## 13. 采用假设

| 编号 | 假设 | 依据 / 影响 |
| --- | --- | --- |
| A-1 | 按钮为关闭语义图标（×），纯图标或带可见文字均可；可访问名称固定为「关闭 / Close」 | 需求只说「关闭按钮」，图形细节归设计；语义名称归需求。 |
| A-2 | 视觉尺寸、底色、描边、阴影、按压态由设计阶段按新页面产出 | 无参照截图；本 PRD 只约束位置、露出比例、可点性、对比度、遮挡。 |
| A-3 | 点击命中区域 ≥ 48dp，视觉尺寸可小于 48dp | Material 常规；窄屏下保证屏幕内完整可见。 |
| A-4 | 按钮带独立底色或等效处理，图标与底色对比度 ≥ 3:1 | 保证在欢迎图与滚动内容之上都可辨。 |
| A-5 | 无欢迎图时内容顶部预留间距的具体数值由设计/实现确定，约束是不与标题相交 | 由 AC-8 判定，不写死间距。 |
| A-6 | 按钮固定在弹窗层，不进入滚动内容 | 用户 Q5 选择 A。 |
| A-7 | 关闭按钮只新增关闭方式，不触发「开始使用」以外的业务动作 | 现有弹窗仅有 pop，无后续动作。 |
| A-8 | 日志沿用现有 debug 输出，不做 release 埋点 | 现有 `DebugWelcomeLog` 的约束。 |
| A-9 | 按钮的可访问名称加入现有中英文案表，不新增语言 | 应用当前仅支持 zh/en。 |
| A-10 | 弹窗现有居中、最大高度 80%、圆角、水平内边距原则上不变 | 本需求只加按钮；若为容纳按钮必须微调，需在设计说明中记录并回归现有布局测试。 |

## 14. 依赖与风险

| 类型 | 内容 | 应对 |
| --- | --- | --- |
| 依赖 | 设计阶段给出按钮视觉尺寸、底色/描边与按压态 | 设计说明需同时满足 AC-4、AC-5、AC-9；尺寸取值前核对 320dp 几何。 |
| 风险 | 弹窗现有 16dp 圆角与裁切会切掉外露的一半，导致「卡边」看不到或点不到 | AC-1、AC-3 明确要求外露部分完整可见、可点；实现需保证按钮位于裁切之外或等效处理。 |
| 风险 | 半露出按钮在 320dp 屏幕上可能越出屏幕 | AC-9 约束视觉尺寸；设计取值需留出屏幕边距。 |
| 风险 | 固定按钮覆盖在滚动内容上，可能压住标题或副标题 | 初始展示（AC-6）与无欢迎图（AC-8）用矩形不相交判定；滚动过程中允许文字从按钮下方经过，但按钮位置与可点性不变（AC-7）。 |
| 风险 | 现有测试断言「没有关闭按钮」，改代码后会失败 | 明确更新该断言，并新增位置/连点/日志/语义测试。 |
| 风险 | 图标不是 `Icons.close` 时测试定位失效 | 测试用稳定的 Key 定位，不依赖具体图标资源。 |
| 风险 | 320dp 下 48dp 命中区可能部分超出屏幕 | 以可见区域仍可点为准；视觉完整在屏幕内由 AC-9 保证。 |

## 15. 歧义扫描

### 15.1 扫描结论

| 类型 | 发现 | 处理 |
| --- | --- | --- |
| 互相矛盾 | 「约一半露出弹窗外」与弹窗现有圆角裁切冲突，外露部分可能不可见、不可点 | 以「卡边」效果优先：AC-1 要求完整渲染，AC-3 要求外露部分可点；实现必须绕开裁切。 |
| 互相矛盾 | 「约一半露出」与「320dp 屏幕内完整可见」存在几何冲突 | 以窄屏完整可见为硬约束（AC-9）；视觉尺寸由设计在满足 45%–55% 露出的前提下取值。 |
| 无法判定 | 「卡在边缘」没有数值口径 | 量化为：中心与弹窗右上角偏差 ≤ 1dp；外露宽/高各为 45%–55%（AC-1、AC-2）。 |
| 无法判定 | 「清晰可辨」没有阈值 | 量化为图标与按钮底色对比度 ≥ 3:1（AC-5），按 WCAG 非文本对比度计算。 |
| 无法判定 | 「立即关闭」没有判定方式 | 量化为一次点击只发生一次路由 pop、不出现二次确认、关闭后首页可交互（AC-10）。 |
| 缺边界 | 欢迎图缺失/失败、内容滚动、2 倍字号、320dp 窄屏、连点、英文、返回键、遮罩、存储读写失败、渲染失败、进程被杀 | 逐条写入 §8；适用本需求的给 AC-7/8/9/11/14/17/18，不适用的写明沿用现有行为。 |
| 缺边界 | 按钮下方从欢迎图变成滚动内容时对比度是否仍成立 | 写入 REQ-2：独立底色需保证对比度不因下方内容变化而失效；AC-5 覆盖两种主题。 |
| 悬空引用 | `closeButton` / `close_button` 未定义 | 在 REQ-5 明确定义枚举取值、wire 值与日志格式；AC-13 验证。 |
| 悬空引用 | `welcomeClose` 文案未定义 | 在 §10.1 定义中文「关闭」、英文「Close」；AC-14 验证。 |
| 悬空引用 | `welcome_dismissed` 事件、`welcome_shown`、`welcome_error` 是否存在 | 均为现有日志事件，已在 §11.1 对齐；无新增事件。 |
| 悬空引用 | 是否引入新页面、接口、权限、字段 | 没有：不新增页面/接口/权限/数据库字段；`visible_ms` 沿用现口径。 |

### 15.2 结论

- Q1–Q5 均已由用户拍板（全部选 A），无未回答项，也没有把回答改回推荐值。
- 扫描后不存在未解决的矛盾、无法判定项或悬空引用；剩余未定项仅限设计阶段的视觉参数，已列入假设 A-1～A-5。
- 本需求不引入新的平台能力承诺；折叠屏/分屏与全局无障碍已明确不做并写明理由。
