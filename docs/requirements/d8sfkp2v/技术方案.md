## 1. 方案概述

在现有一次性欢迎弹窗的固定 footer 内、主按钮「开始使用」下方新增一行纯展示文本：

- 文本为 `v` + `PackageInfo.version`（Android `versionName`，不含 buildNumber），正常构建显示 `v0.1.0`。
- 读取失败、空值、空白或读取超时统一回退 `v1.0.0`，不弹错误、不阻塞弹窗。
- 版本号在 `showDialog` **之前**解析完成，以字符串参数注入 `WelcomeDialog`，保证弹窗首帧即显示完整版本号（AC-9），弹窗内部不做异步读取。
- 版本行放在现有 footer 的按钮列中：主按钮 → 8dp → 版本行 → 20dp 底内边距；不进入可滚动内容区。
- 样式：14sp / w400 / 行高 1.4 / `colorScheme.onSurfaceVariant`，跟随系统字体缩放，单行、超宽末尾省略。
- 不新增动画节点、不拦截手势、不新增翻译、不新增权限、不改一次性标记与日志契约。

核心取舍：

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 版本号何时读 | 展示前由宿主读取并注入 | AC-9 要求弹窗完全出现时已就绪；`FutureBuilder` 会先出一帧空白 |
| 读取失败边界 | resolver 内 catch-all + 500ms 超时，统一回退 | 「不阻塞弹窗」需要对平台通道异常和挂起都兜底 |
| 版本读取位置 | 新增独立 resolver，不动「关于」页 | 可注入、可单测；PRD 明确「关于」页不在范围 |
| 版本行样式 | 落地设计 token `AppTypography.version`（14 / w400 / 1.4）+ `onSurfaceVariant` | 对齐设计说明 §6.2；只新增一个 `TextStyle` 常量，不改其他主题配置 |
| 关闭淡出 | 不碰 `showDialog` / `DialogRoute` | 版本行天然在路由的同一个 `FadeTransition` 之下，满足 AC-11/AC-12 |

## 4. 总体设计

### 4.1 数据流

```text
ChatScreen.initState
  └─ 首帧后 _checkWelcome()
       └─ WelcomeController.runOnce()          // 单飞，未改
            ├─ 读 welcome_dialog_shown_v1      // 已展示则直接 return（不读版本）
            ├─ 写标记
            └─ _presentWelcome()
                 ├─ WelcomeAiGate.shouldShowConfigureAi()   ┐ 并行
                 └─ AppVersionResolver.resolve()            ┘
                      ├─ PackageInfo.fromPlatform().version
                      ├─ 成功：'v' + version；空值/异常/超时：'v1.0.0'
                      └─ 永不抛出，返回值非空
                 └─ showDialog(
                      builder: (_) => WelcomeDialog(
                        showConfigureAi: ...,
                        versionLabel: <已就绪字符串>,
                      ),
                    )
                      └─ footer Column
                           ├─ FilledButton('开始使用')
                           ├─ SizedBox(height: 8)
                           └─ Text(versionLabel)   // 纯展示，随路由整体淡出
```

### 4.2 为什么不在弹窗内部异步读

`FutureBuilder` / `initState` 内 `await` 都会让弹窗先出现一帧空文本或占位，直接违反 AC-9。将读取提前到 `showDialog` 前，弹窗构建时字符串已确定，`WelcomeDialog` 保持纯同步渲染，也便于单测直接注入任意版本。

### 4.3 版本读取与展示解耦

- `AppVersionResolver` 只负责「读 + 格式化 + 兜底」，不依赖 Flutter UI。
- `WelcomeDialog` 只负责「展示传入的字符串」，不碰 `package_info_plus`。
- 两处都可独立单测；读取失败不会让弹窗构建抛异常。

## 5. 接口定稿

### 5.1 版本格式化（纯函数）

文件：`flutter_app/lib/app_version.dart`（新增）

```dart
/// 读取失败、空值、空白时的统一回退值，与「关于」页回退值 1.0.0 对齐。
const String fallbackAppVersionLabel = 'v1.0.0';

/// 将原始 versionName 格式化为展示文本。
///
/// - 入参为 null、空串或纯空白：返回 [fallbackAppVersionLabel]；
/// - 其余情况：返回 'v' + 去除首尾空白后的原值；
/// - 不拼接 buildNumber，不做本地化，不补零。
String formatVersionLabel(String? versionName);
```

空值语义：`null` / `''` / `'   '` → `v1.0.0`；`'0.1.0'` → `v0.1.0`。函数同步、纯、无副作用、不抛异常。

### 5.2 版本读取器

```dart
/// 返回原始 versionName（不带 'v' 前缀、不含 buildNumber）。
/// 允许返回 null；允许抛异常；允许永不完成（由 timeout 兜底）。
typedef AppVersionLoader = Future<String?> Function();

class AppVersionResolver {
  const AppVersionResolver({
    AppVersionLoader? loader,
    this.timeout = const Duration(milliseconds: 500),
  }) : _loader = loader;

  final AppVersionLoader? _loader;
  final Duration timeout;

  /// 永远成功完成：返回非空、以 'v' 开头的展示字符串。
  Future<String> resolve();
}
```

契约：

| 项 | 定稿 |
| --- | --- |
| 默认 loader | `(await PackageInfo.fromPlatform()).version`（只取 version，不取 buildNumber） |
| 返回值 | 非空 `String`，正常 `v<versionName>`；异常路径 `v1.0.0` |
| 异常 | 所有 `Object`（含 `MissingPluginException`、`PlatformException`、同步 throw）一律吞掉并回退；不记录日志、不弹提示 |
| 超时 | 500ms；`TimeoutException` 同样回退；超时后底层 future 的后续结果不再使用 |
| 并发 | 无状态；重复调用各自读取，不缓存；本需求每次启动最多调用一次 |
| 线程 | Flutter 主 isolate；仅一次平台通道读取，无文件/网络 I/O |
| 空值 | `null` / `''` / 纯空白 → `v1.0.0` |
| 前缀 | loader 按 Android 约定返回原始 versionName（不带 `v` 前缀）；resolver 统一加小写 `v` |

### 5.4 `WelcomeDialog` 构造接口

文件：`flutter_app/lib/widgets/welcome_dialog.dart`（修改）

```dart
/// 版本行文本（已格式化、非空），由调用方在展示前解析。
```

空值语义：`versionLabel` 为必填；生产路径由 `AppVersionResolver` 保证非空；`build` 内加 `assert(widget.versionLabel.isNotEmpty)` 作为开发期兜底。`WelcomeDialog` 不再做第二次回退，避免两个回退源。

### 5.5 宿主调用契约

`ChatScreen._presentWelcome` 内：

```dart
final showConfigureAiFuture =
    ref.read(welcomeAiGateProvider).shouldShowConfigureAi();
final versionLabelFuture = ref.read(appVersionProvider).resolve();

final showConfigureAi = await showConfigureAiFuture;
final versionLabel = await versionLabelFuture;
if (!mounted) {
  throw StateError('首页已销毁，跳过欢迎弹窗');
}

final startedAt = DateTime.now();
final closing = showDialog<WelcomeDismissMethod>(
  context: context,
  barrierDismissible: false,
  useRootNavigator: true,
  builder: (_) => WelcomeDialog(
    showConfigureAi: showConfigureAi,
    versionLabel: versionLabel,
  ),
);
onShown();
```

- 两个读取并行，正常路径不额外串行等待。
- `startedAt` 仍在 `showDialog` 前，`visible_ms` 不包含版本读取耗时。
- `welcome_shown` 仍在 push 后调用，字段与时机不变。
- resolver 不抛异常，因此不会触发 `WelcomeController` 的 `welcome_error(render)`。
- 已看过弹窗的用户不会走到 `_presentWelcome`，不会产生任何版本读取。

### 5.6 版本行布局与样式契约

| 项 | 定稿 |
| --- | --- |
| 位置 | footer `Column` 最后一个子节点，`SingleChildScrollView` 之外 |
| 顺序（未配置 AI） | 去配置AI（48）→ 8 → 开始使用（48）→ 8 → 版本行 → 20 |
| 顺序（已配置 AI） | 开始使用（48）→ 8 → 版本行 → 20 |
| 宽度 | 由 `Column.crossAxisAlignment.stretch` 撑满 footer 内容区 = 卡片宽 − 40dp |
| 对齐 | `textAlign: TextAlign.center`，单行 |
| 字号 / 字重 / 行高 | 14sp / `FontWeight.w400` / `height: 1.4` |
| 样式来源 | `AppTypography.version`（只含字号/字重/行高） + `copyWith(color: scheme.onSurfaceVariant)` |
| 颜色 | `Theme.of(context).colorScheme.onSurfaceVariant`（浅 `#5B6270` / 深 `#A6ADBB`） |
| 缩放 | 不包 `textScaler` / `MediaQuery.withClampedTextScaling`；系统 2.0 → 28sp，行盒 39.2dp |
| 溢出 | `maxLines: 1`、`overflow: TextOverflow.ellipsis`、`softWrap: false` |
| 交互 | 无手势、无按钮语义、无 `InkWell`、无 `Semantics(button: true)` |
| 动效 | 无独立动效；随 `DialogRoute` 的 `FadeTransition` 整体淡出 |

排版 token（放入 `flutter_app/lib/theme/app_theme.dart`，只被版本行使用）：

```dart
class AppTypography {
  static const TextStyle version = TextStyle(
    fontSize: 14,
    fontWeight: FontWeight.w400,
    height: 1.4,
  );
}
```

版本行使用 `AppTypography.version.copyWith(color: scheme.onSurfaceVariant)`；token 只承载字号/字重/行高，颜色仍由 `ColorScheme` 的 `onSurfaceVariant` 提供，不新增固定色值。

1x 几何结果：

| 形态 | footer 高度 | 主按钮底边到卡片底边 | 版本行底边到卡片底边 | 版本行顶边到主按钮底边 |
| --- | --- | --- | --- | --- |
| 已配置 AI | 12 + 48 + 8 + 19.6 + 20 = **107.6dp** | 47.6dp | 20dp | 8dp |
| 未配置 AI | 12 + 48 + 8 + 48 + 8 + 19.6 + 20 = **163.6dp** | 47.6dp | 20dp | 8dp |

2.0 倍字号（按钮仍为 48dp 高时）：行盒 39.2dp，footer 分别为 **127.2dp / 183.2dp**。1x 的 163.6 / 107.6 与 2x 的 183.2 均与设计稿一致；卡片高度在 1x 下增加 27.6dp（设计稿 406.6dp / 350.6dp）。

卡片由 `Dialog` 垂直居中，1x 下高度 +27.6dp 会使整卡上移约 13.8dp；这是既有居中行为，无需额外代码，设计稿整卡重绘与此一致。无欢迎图时沿用现有 `welcomeNoHeroExtraTop = 56` 顶部让位，版本行不改变该分支。

### 回滚方案

1. 开发/评审阶段：丢弃对应提交即可，无数据、配置、资源变更。
2. 合并后：`git revert <commit>` 恢复 `WelcomeDialog` 旧构造、`ChatScreen` 旧 presenter、删除 `app_version.dart` 与 provider；无数据库 / SharedPreferences / 标记迁移需要回滚。
3. 重新构建并安装：`flutter build apk --debug` → `adb -s <deviceId> install -r -d -t build/app/outputs/flutter-apk/app-debug.apk`（降级安装需 `-d`）。
4. 回滚验收：footer 恢复 136 / 80dp，弹窗底部无版本文本，欢迎弹窗仍只弹一次，「关于」页版本显示不变。
5. 已发布场景：无服务端开关；直接发补丁包移除版本行即可。一次性标记未改动，回滚不会让老用户重新看到弹窗。
