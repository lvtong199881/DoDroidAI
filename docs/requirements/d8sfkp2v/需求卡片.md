# 需求卡片：欢迎弹窗底部版本号

- 需求编号：d8sfkp2v
- 文档版本：v1.0（定稿）
- 关联文档：`PRD.md`、`待提问清单.md`
- 一句话目标：在一次性欢迎弹窗底部增加一行居中的真实版本号（如 `v0.1.0`），14sp、次要文字色，关闭时与主标题共享弹窗整体淡出。

## 1. 范围

### 1.1 本次做

- 在 `flutter_app/lib/widgets/welcome_dialog.dart` 的欢迎弹窗底部固定 footer 内增加一行版本号。
- 版本号取应用真实 `versionName`，显示为 `v` + 版本号，例如 `v0.1.0`；不显示 buildNumber。
- 版本行水平居中，14sp 基准字号，字重 w400，行高 1.4，颜色为 `onSurfaceVariant`，跟随系统字体缩放。
- 版本行位于主按钮「开始使用」下方、卡片最底部；未配置 AI 时「去配置AI」按钮存在与否都不影响版本行位置。
- 弹窗关闭时，版本行与主标题共享同一个路由淡出，不新增独立动画。
- 版本行是纯展示文本：不响应点击/长按，不是按钮；读屏可读出完整版本号。
- 保持欢迎弹窗一次性语义：不重置已展示标记，老用户升级后不再展示。

### 1.2 明确不做

- 不改「关于」页的版本显示逻辑或回退值；两处同源，但「关于」页不在本次改动范围。
- 不把版本号加到设置页、侧边栏、聊天页或其他入口。
- 不改欢迎弹窗的展示时机、一次性标记、单飞逻辑或日志契约；不重置老用户标记。
- 不新增点击/长按版本号跳转「关于」页、复制或其他交互。
- 不新增运行时权限，不新增需要翻译的文案（版本号语言无关）。
- 不改造欢迎弹窗其他内容、间距、按钮、欢迎图、关闭角标或动效；不新增独立的标题淡出动画。
- 不做折叠屏/分屏/悬浮窗的专项布局适配；沿用现有「最大高度 80% + 内容滚动 + footer 固定」策略，只保证版本行不被裁切、不与按钮重叠。
- 不做版本号管理或发版流程；本次不把 `pubspec.yaml` 的版本升到 `1.0.0`。

### 1.3 已确认的用户决策

| 问题 | 用户决定 |
| --- | --- |
| 版本号来源 | 读取应用真实版本，显示 `v0.1.0`；与「关于」页版本值一致（关于页格式为「版本 0.1.0」，欢迎弹窗带 `v` 前缀）。不固定写死 `v1.0.0`。 |
| 版本行位置 | 主按钮下方、卡片最底部，固定在 footer。 |
| 次要色 | `onSurfaceVariant`，与现有说明行/副标题一致。 |
| 字号缩放 | 跟随系统，基准 14sp，2 倍时 28sp。 |
| 老用户升级 | 不重置标记，老用户升级后不再展示欢迎弹窗。 |

## 3. 验收标准

| 编号 | 覆盖 REQ | 验收标准 | 验证方式 |
| --- | --- | --- | --- |
| AC-1 | REQ-1 | 当欢迎弹窗展示时，版本行文本应当为 `v` + 应用 `versionName`（不含 buildNumber）；在 version 为 `0.1.0+1` 的构建上应当显示 `v0.1.0`。 | 单测注入版本；真机截图 |
| AC-2 | REQ-1、REQ-7 | 当应用版本读取失败或返回空字符串时，版本行应当显示 `v1.0.0`，且弹窗其余内容、按钮和关闭能力不受影响。 | 单测注入异常/空值 |
| AC-3 | REQ-1、REQ-4 | 当应用语言为中文或英文时，版本行文本应当相同（同一版本号），不出现空文本、占位符或翻译缺失。 | 单测 zh/en |
| AC-4 | REQ-2 | 当欢迎弹窗展示时，版本行应当水平居中并位于主按钮下方；版本行顶边与主按钮底边的间距应当为 8dp（±1dp），版本行底边与卡片内容区底边的间距应当为 20dp（±1dp）。 | 单测测量矩形 |
| AC-5 | REQ-2 | 当 `showConfigureAi=true`（footer 同时有「去配置AI」和「开始使用」）时，版本行应当仍位于主按钮下方最底部，且与两个按钮均不重叠。 | 单测/真机未配置 AI |
| AC-6 | REQ-3 | 当系统字体缩放为 1.0 时，版本行应当为 14sp、字重 w400、行高 1.4，颜色为当前主题的 `onSurfaceVariant`（浅色 `#5B6270` / 深色 `#A6ADBB`）。 | 单测读取 TextStyle/Color |
| AC-7 | REQ-3 | 当系统字体缩放为 2.0 时，版本行渲染字号应当为 28sp，且保持单行、不横向溢出卡片。 | 单测 2 倍 textScaler |
| AC-8 | REQ-3 | 当版本号文本宽度超过可用宽度时，版本行应当单行末尾省略，不换行、不撑破卡片。 | 单测注入超长版本 |
| AC-9 | REQ-4 | 当欢迎弹窗完全出现时，版本行应当已经显示完整版本号，不出现先空白后补的中间帧。 | 单测首帧/路由过渡结束帧 |
| AC-10 | REQ-2、REQ-4 | 当弹窗内容因小高度或大字号滚动时，版本行应当保持固定在卡片底部可见，不随内容滚出。 | 单测滚动 |
| AC-11 | REQ-5 | 当点击「开始使用」关闭弹窗时，版本行与主标题应当共享同一 `FadeTransition`，动画中途两者透明度相等；`WelcomeDialog` 内不新增 `FadeTransition` 节点，关闭总时长与改动前一致。 | 单测过渡与透明度 |
| AC-12 | REQ-5 | 当点击关闭角标、按系统返回键或点击「去配置AI」关闭弹窗时，版本行应当与主标题同步淡出，关闭后不残留版本文本。 | 单测四种关闭方式 |
| AC-13 | REQ-6 | 当读屏聚焦版本行时，应当读出与版本行文本完全一致的字符串，且不报告为按钮或可点击。 | 单测 Semantics |
| AC-14 | REQ-6 | 当点击或长按版本行时，应当不触发任何操作，欢迎弹窗保持打开。 | 单测 tap/longPress |
| AC-15 | REQ-2、REQ-4 | 当屏幕为逻辑像素 640×400 且系统字体缩放为 2.0 时，版本行应当完整可见、单行、不与主按钮重叠、不被卡片圆角裁切；内容区可滚动。 | 单测 640×400/2x |
| AC-16 | REQ-7 | 当应用已存在 `welcome/welcome_dialog_shown_v1` 标记时，启动后应当不展示欢迎弹窗，版本行不可见。 | 单测/真机已有标记 |
| AC-17 | REQ-7 | 当全新安装或清除应用数据后首次启动时，欢迎弹窗应当展示，并在底部显示版本行。 | 真机全新安装/清数据 |

## 5. 依赖与风险

- 依赖：`package_info_plus` 已在 `flutter_app/pubspec.yaml` 中，无新增第三方依赖。
- 风险：现有欢迎弹窗测试对 footer 高度（未配置 136dp / 已配置 80dp）和「主按钮贴底 20dp」有精确断言；新增版本行后这些断言必须同步更新，属于预期变更，不是回归。
- 风险：版本号读取是异步的；若在弹窗展示后才完成，会出现空白后补，需在展示前就绪（AC-9）。
- 风险：固定 footer 增高会压缩小高度/大字号下的滚动区；需验证 AC-15，确保按钮和版本行都可见。
- 无后端、无数据迁移、无新增权限风险。
