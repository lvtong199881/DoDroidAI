# PRD：欢迎弹窗底部版本号

- 需求编号：d8sfkp2v

- 状态：已定稿，可进入设计与技术方案
- 关联文档：`需求卡片.md`、`待提问清单.md`
- 平台：Android（Flutter 实现，`flutter_app/`）

## 1. 背景与目标

### 1.1 背景

DoDroidAI 首次启动时会展示一次性欢迎弹窗，当前弹窗底部只有「去配置AI」（未配置时）和「开始使用」按钮，没有任何版本信息。用户反馈问题或测试同学截图时，需要额外进入「设置 → 关于」才能确认版本；欢迎弹窗作为首次打开就能看到的界面，适合放一行不打断操作的版本号。

当前实现事实：

- 欢迎弹窗在首页首帧后检查并展示，只展示一次；已展示标记为应用私有目录下的 `welcome/welcome_dialog_shown_v1`。
- 弹窗底部是固定 footer，内容超高时只有上半部分滚动，footer 固定。
- 关闭时由 `DialogRoute` 对整个弹窗统一淡出；标题、说明行、副标题共享同一个 `FadeTransition`，弹窗内不新增淡出节点。
- 「关于」页用 `package_info_plus` 读取安装包版本；当前 `flutter_app/pubspec.yaml` 的版本为 `0.1.0+1`。

### 1.2 目标

- 在欢迎弹窗底部增加一行居中的版本号，让用户在首次打开时就能看到当前版本。
- 版本号与应用真实版本同源，发版后自动更新，不需要每次改代码。
- 视觉上与现有弹窗的次要文字一致，不新增独立动画、不新增交互、不改变关闭体验。
- 不改变欢迎弹窗的一次性语义，不打扰已看过弹窗的老用户。

### 1.3 非目标

- 不做版本管理、发版流程或 `pubspec.yaml` 版本号调整。
- 不改造「关于」页或其他页面的版本展示。
- 不新增点击/长按版本号跳转、复制、分享等交互。
- 不改造欢迎弹窗的其他内容、布局、图片、关闭角标或动效。

## 2. 范围

### 2.1 本次做

- 在 `flutter_app/lib/widgets/welcome_dialog.dart` 的欢迎弹窗底部固定 footer 内增加一行版本号。
- 版本号取应用真实 `versionName`，显示为 `v` + 版本号，例如 `v0.1.0`；不显示 buildNumber。
- 版本行水平居中，14sp 基准字号，字重 w400，行高 1.4，颜色为 `onSurfaceVariant`，跟随系统字体缩放。
- 版本行位于主按钮「开始使用」下方、卡片内容区最底部；未配置 AI 时「去配置AI」按钮存在与否都不影响版本行位置。
- 弹窗关闭时，版本行与主标题共享同一个路由淡出，不新增独立动画。
- 版本行是纯展示文本：不响应点击/长按，不是按钮；读屏可读出完整版本号。
- 保持欢迎弹窗一次性语义：不重置已展示标记，老用户升级后不再展示。

### 2.2 明确不做

- 不改「关于」页的版本显示逻辑或回退值；两处同源，但「关于」页不在本次改动范围。
- 不把版本号加到设置页、侧边栏、聊天页或其他入口。
- 不改欢迎弹窗的展示时机、一次性标记、单飞逻辑或日志契约；不重置老用户标记。
- 不新增点击/长按版本号跳转「关于」页、复制或其他交互。
- 不新增运行时权限，不新增需要翻译的文案（版本号语言无关）。
- 不改造欢迎弹窗其他内容、间距、按钮、欢迎图、关闭角标或动效；不新增独立的标题淡出动画。
- 不做折叠屏/分屏/悬浮窗的专项布局适配；沿用现有「最大高度 80% + 内容滚动 + footer 固定」策略，只保证版本行不被裁切、不与按钮重叠。
- 不做版本号管理或发版流程；本次不把 `pubspec.yaml` 的版本升到 `1.0.0`。
- 不新增埋点或结构化日志事件；复用现有欢迎弹窗日志观察整体展示与关闭。

## 4. 功能需求

### REQ-1 版本号内容与来源

- 版本号取应用真实 `versionName`（Android `versionName` / `PackageInfo.version`），不取 buildNumber。
- 显示格式为 `v` + 版本号，例如 `v0.1.0`；`v` 小写，版本号原样保留。
- 正常构建（`pubspec.yaml` 的 `0.1.0+1`）显示 `v0.1.0`。
- 版本读取失败或返回空字符串时，回退显示 `v1.0.0`（与「关于」页现有回退值一致），不阻塞弹窗展示或关闭。
- 版本号文本语言无关：中文、英文环境显示同一字符串，不新增翻译。
- 版本行在弹窗完全出现时已经就绪，不允许先显示空白、下一帧再补。

验收：AC-1、AC-2、AC-3、AC-9。

### REQ-2 位置与布局

- 版本行位于主按钮「开始使用」下方、卡片内容区最底部。
- 版本行属于固定 footer，不放进可滚动内容区；内容超高滚动时版本行保持可见。
- 水平居中；宽度撑满 footer 内容区（卡片宽度减去左右各 20dp 内边距）。
- 与主按钮的垂直间距为 8dp；版本行下方保留 20dp（沿用 footer 现有下内边距）。
- 未配置 AI 时，footer 顺序为：`去配置AI` → 8dp → `开始使用` → 8dp → `版本行` → 20dp；已配置 AI 时去掉第一个按钮和其后的 8dp，其余不变。
- 版本行与两个按钮均不重叠，不被卡片圆角裁切。

验收：AC-4、AC-5、AC-10、AC-15。

### REQ-3 字体与颜色

- 基准字号 14sp，字重 w400，行高 1.4。
- 跟随系统字体缩放：系统 1.0 时 14sp，系统 2.0 时 28sp；不设置固定 `textScaler`，不设缩放上限。
- 颜色取当前主题 `colorScheme.onSurfaceVariant`：浅色 `#5B6270`，深色 `#A6ADBB`。
- 单行显示；版本号文本超过可用宽度时末尾省略，不换行、不撑破卡片。
- 不新增字体资源、不新增图片资源、不使用固定色值绕过主题。

验收：AC-6、AC-7、AC-8。

### REQ-4 展示条件

- 欢迎弹窗展示时即显示版本行；与 AI 是否配置无关。
- 浅色/深色主题都显示；中文/英文语言都显示，文本相同。
- 弹窗内容因小高度或大字号滚动时，版本行固定在 footer 可见。
- 弹窗完全出现时版本行已经显示完整版本号（见 REQ-1）。
- 不改变欢迎弹窗的展示条件：仍只在首次安装/首次启动（或清除数据后）展示；老用户升级后不展示。

验收：AC-3、AC-9、AC-10、AC-15、AC-16、AC-17。

### REQ-5 关闭淡出

- 任一种关闭方式（「开始使用」、关闭角标、系统返回键、「去配置AI」）下，版本行与主标题共享同一整体淡出，动画中途两者透明度始终相等。
- 不新增独立的标题淡出或内容淡出动画；关闭总时长与改动前一致。
- 关闭后不残留版本文本；重复点击关闭沿用现有 `_closing` 防重，只关闭一次。

验收：AC-11、AC-12。

### REQ-6 非交互与无障碍

- 版本行是纯展示文本：不响应点击、长按、双击；不是按钮，不进入可点击语义。
- 读屏聚焦版本行时，读出与版本行文本完全一致的字符串（如 `v0.1.0`），不报告为按钮或可点击。
- 不新增运行时权限，不新增权限说明文案。

验收：AC-13、AC-14。

### REQ-7 兼容与升级

- 不重置、不改名 `welcome/welcome_dialog_shown_v1` 标记；不新增数据迁移。
- 已存在标记的老用户升级后不展示欢迎弹窗，版本行不可见。
- 全新安装或清除应用数据后首次启动，欢迎弹窗展示并显示版本行。
- 版本读取失败不阻塞弹窗、不影响关闭、不影响现有欢迎弹窗日志。
- 不改变生命周期行为：仍在首页首帧后检查一次；切后台回前台不重复弹；进程被杀后按已写标记决定是否展示。

验收：AC-2、AC-16、AC-17。

## 5. 视觉与交互规格

### 5.1 布局示意

```text
┌──────────────────────────────────┐
│  欢迎图（可选，2:1）              │
│                                  │
│        欢迎使用 DoDroidAI         │
│    随时可以在设置里改 AI 配置      │
│    说一句话，让手机替你做事。      │
│                                  │
│  ┌────────────────────────────┐  │
│  │        去配置AI（可选）      │  │
│  └────────────────────────────┘  │
│  ┌────────────────────────────┐  │
│  │      → 开始使用             │  │
│  └────────────────────────────┘  │
│              v0.1.0              │
└──────────────────────────────────┘
```

- 版本行在卡片内容区水平居中，位于最底部；版本行上方 8dp 处是主按钮，下方 20dp 是卡片内边距。
- 版本行不进入上半部分滚动区；内容超高时只滚动标题/说明/副标题/欢迎图。

### 5.2 规格表

| 项 | 规格 |
| --- | --- |
| 文本 | `v` + 应用 `versionName`，如 `v0.1.0`；不含 buildNumber。 |
| 位置 | 主按钮下方、卡片内容区最底部，固定 footer 内。 |
| 对齐 | 水平居中；宽度撑满 footer 内容区。 |
| 字号 | 14sp（基准），跟随系统字体缩放；2 倍时 28sp。 |
| 字重 | w400。 |
| 行高 | 1.4。 |
| 颜色 | `colorScheme.onSurfaceVariant`：浅色 `#5B6270` / 深色 `#A6ADBB`。 |
| 行数 | 单行；超宽末尾省略，不换行。 |
| 与主按钮间距 | 8dp（±1dp）。 |
| 与卡片内容区底部间距 | 20dp（±1dp）。 |
| 交互 | 无点击、无长按、无跳转、无复制。 |
| 读屏 | 普通文本语义，读出完整版本号，不是按钮。 |
| 动效 | 无独立动效；关闭时随 `DialogRoute` 与主标题共享整体淡出。 |

### 5.3 两种 footer 形态

- `showConfigureAi=true`（未配置 AI）：`去配置AI`（48dp）→ 8dp → `开始使用`（48dp）→ 8dp → 版本行 → 20dp。
- `showConfigureAi=false`（已配置 AI）：`开始使用`（48dp）→ 8dp → 版本行 → 20dp。
- 两种形态下版本行都必须在主按钮下方、最底部；footer 总高度会增加约 28dp（8dp 间距 + 约 20dp 文本高度，随字号缩放变化）。

### 5.4 关闭动效

- 沿用 `showDialog` 的整体淡出：版本行属于弹窗内容，关闭时与标题保持同一透明度。
- 不新增独立的透明度/淡出动画或自定义关闭动画；不改变关闭总时长。
- 四种关闭方式表现一致；关闭后版本行随弹窗一起消失，不残留。

| 渲染异常 | 版本行是普通文本，无图片/网络/复杂布局；若发生渲染异常，按现有弹窗 render 异常处理，不影响下次启动。 | 无独立 AC，沿用现有 |

### 7.2 系统条件逐项判断

| 项 | 是否适用 | 结论 |
| --- | --- | --- |
| 深色模式 | 适用 | 应用支持深浅色；版本行用 `colorScheme.onSurfaceVariant`，浅色 `#5B6270` / 深色 `#A6ADBB`；AC-6 覆盖。 |
| 折叠屏展开/折叠/分屏/悬浮窗 | 不专项适配 | 欢迎弹窗是一次性启动弹窗，现有「最大高度 80% + 内容滚动 + footer 固定」已覆盖小高度；本次只加一行固定文本，不引入新的形态布局。明确不做专项适配；AC-15 只保证 640×400/2 倍字号下不重叠、不裁切。 |
| 生命周期 | 适用（不改变） | 仍在首页首帧后检查一次；切后台回前台不重复弹；进程被杀后按已写标记决定；版本读取不写状态。AC-16/AC-17 覆盖首次/二次启动。 |
| 升级路径 | 适用 | 不重置 `welcome/welcome_dialog_shown_v1`；老用户升级后不展示欢迎弹窗；无数据库/存储迁移。AC-16 覆盖。 |
| 异常 | 适用 | 版本读取失败/空值回退 `v1.0.0`，不阻塞弹窗；无网络不影响（本地读取）；无新增权限；无新增写存储；欢迎图/渲染异常沿用现有弹窗处理。AC-2 覆盖版本读取失败。 |

### 7.3 平台能力范围说明

- **深色模式**：在范围内。版本行使用主题 token，不新增固定色值，AC-6 给出浅/深色具体值。
- **系统字体缩放**：在范围内。用户已确认跟随系统；基准 14sp，2 倍 28sp，不设上限，AC-7/AC-15 覆盖。
- **无障碍读屏**：在范围内。版本行作为普通文本进入语义树，读出完整版本号，不是按钮，AC-13 覆盖。
- **折叠屏/分屏/悬浮窗**：不在本需求范围。理由：欢迎弹窗为一次性启动弹窗，现有响应式策略已覆盖小高度；本次只增加一行固定文本，不做形态专项适配。该决定已写入「明确不做的事」。
- **屏幕旋转**：不专项适配，沿用现有响应式布局；版本行随 footer 重建，间距不变。理由：本次只增加一行固定文本，不改变弹窗的响应式策略。
- **权限**：无新增权限，不涉及权限文案。

## 9. 监测指标

本需求不新增埋点或结构化日志事件。版本行是纯展示，没有点击、转化或独立曝光路径；沿用现有欢迎弹窗日志观察整体展示与关闭。

| 指标 | 口径 | 数据来源 | 说明 |
| --- | --- | --- | --- |
| 欢迎弹窗展示量 | `welcome_shown` 事件计数，按 `entry`、`locale` 分组 | 现有 `welcome_shown`（`[welcome] welcome_shown entry=... locale=...`） | 本需求不改变字段和时机。 |
| 关闭方式分布 | `welcome_dismissed` 按 `method` 分组计数；`visible_ms` 观察停留时长 | 现有 `welcome_dismissed`（`method` / `visible_ms`） | 本需求不改变字段和时机。 |

- 版本读取失败是异常路径，不设独立产品指标，也不新增结构化事件；实现需保证失败不阻塞弹窗（AC-2），如需排障可输出 debug 日志。
- 监测不采集版本号以外的用户内容；不新增个人信息字段。
- 如果后续需要单独观测版本回退率，再评估是否扩展 `WelcomeLog` 契约，不在本需求范围。

## 12. 依赖、风险与测试数据

### 12.1 依赖

- `package_info_plus` 已在 `flutter_app/pubspec.yaml` 中，无新增第三方依赖。
- 无后端接口、无数据库变更、无新增权限。

### 12.2 风险

- **现有测试断言会变**：现有欢迎弹窗测试对 footer 高度（未配置 136dp / 已配置 80dp）和「主按钮贴底 20dp」有精确断言；新增版本行后这些断言必须同步更新，属于预期变更，不是回归。
- **异步读取**：版本号读取是异步的；若在弹窗展示后才完成，会出现空白后补（AC-9）。实现需在展示前就绪。
- **小高度/大字号**：固定 footer 增高会压缩滚动区；需验证 640×400/2 倍字号下按钮和版本行都完整可见（AC-15）。
- **超长版本号**：未来版本号可能带 beta/rc 后缀，需保证单行省略不撑破卡片（AC-8）。
- **与「关于」页一致性**：正常路径两处都取 `PackageInfo.version`；失败路径两处都回退 `1.0.0`，显示格式分别为 `v1.0.0` 和 `版本 1.0.0`，语义一致。

### 12.3 测试数据

完整测试账号与数据见《需求卡片.md》第 4 节。摘要：

- 不需要账号；无后端、无网络依赖。
