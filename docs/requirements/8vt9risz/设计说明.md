## 2. 设计结论

在欢迎弹窗底部按钮区新增一个**次要按钮**，位置在「开始使用」上方，纵向排列：

**欢迎图（贴边 2:1）→ 主标题（居中）→ 副标题（居中）→「去配置AI」（描边次要按钮）→「开始使用」（实心主按钮）**

- 两个按钮都占满内容宽度（360dp 画布下 280dp / 320dp 画布下 240dp），高 48dp，胶囊形，间距 **8dp**。
- 「开始使用」保持现有 `FilledButton`：实心 `primary`、`onPrimary` 文字、15sp / w600，不改文案与行为。
- 「去配置AI」为 `OutlinedButton` 次要样式：透明底、1dp `outline` 描边、`primary` 文字、15sp / w600、`StadiumBorder`；与主按钮在**填充 / 描边 / 文字色**三个维度同时区分，视觉权重明显更低。
- 未配置时弹窗高 379（原 323 + 按钮 48 + 间距 8 + 不新增 padding），仍远低于屏高 80% 上限。
- 已配置时**不渲染**该按钮，也不保留占位与额外间距：footer 内边距与按钮位置与改动前完全一致（F02）。
- 不新增页面、不改 AI 配置编辑页；点击后的目标页复用现有新建配置编辑页（PRD H-8）。

**必备状态**：正常态 F01、空态 F06 + F08、超长文案 / 多语言 F04 + F05、极端数据 F07，均为独立 frame，不拼图。

**加载态：舍弃。** PRD REQ-1 要求「判断在弹窗展示前完成、只判断一次、不出现先单按钮后补按钮」；读取慢时按最终结果一次性展示。也就是说界面上不存在「加载中」的中间态，单独出 loading 帧反而会诱导开发实现一个 PRD 明确禁止的闪烁过程。

**错误态：保留降级画面，不另出帧。**
- 配置读取异常 → 按未配置处理，画面与 F01 完全相同（AC-6），无独立视觉。

- 欢迎图缺失 / 解码失败 → F06，这是唯一有视觉差异的异常路径。

**未出的系统条件**：字体缩放、折叠屏 / 分屏 / 悬浮窗、深浅切换动画、按压 / 焦点态。PRD §4.2 / §7.2 明确不做专项适配，且均为 Material 3 默认行为，静态稿不单列。

## 6. 与现有设计规范的差异

1. **新增的次要按钮样式**：项目现有 `OutlinedButton` 只在 AI 配置页用于「删除」（`foregroundColor/side = error`），没有通用的次要按钮样式。本需求定义「透明底 + `outline` 1dp 描边 + `primary` 文字 + 胶囊」为弹窗次要按钮；颜色、字号、圆角、高度全部复用主题 token，**未引入新色值或新字号**。开发需在按钮上显式设置 `side` 与 `foregroundColor`，不能依赖 `OutlinedButton` 默认样式（默认描边为 `outline`、文字为 `primary`，与本稿一致，仍建议显式写死以防主题演进）。
2. **新增 8dp 按钮间距**：主题没有「按钮之间」的 spacing token，按 4dp 网格取 8，与标题→副标题的 8dp 一致；未使用 10/12 等非网格值。
3. **字体降级**：出图环境用 `'Segoe UI'` / `'Microsoft YaHei'` 近似，Android 真机为 Roboto / Noto Sans CJK（或厂商字体）。字号、字重、行高按 token 固定；PNG 的断行位置仅供预览，真机断行以系统字体为准。F05 的英文副标题在当前字体下为 2 行，若真机排成 1 行，弹窗高度会少 21dp，按钮仍固定在底部，不构成缺陷。
4. **深色不是本需求的平台验收项**：PRD §4.2 不做深色专项适配，但 §7.2 要求设计给出浅 / 深两态，故出 F03；只验证「按钮可见、描边与文字可辨」，不新增深色 AC。
5. **不做大字号 / 折叠屏 / 分屏帧**：PRD 明确不新增这些平台验收项，弹窗沿用 `maxHeight=80%` + 内容滚动；F07 已用最极端的 640×400 视口证明「按钮固定、不裁切」在超高时成立。
6. **背景为占位**：无 `docs/ui-screenshots/`，F01–F07 的背景是规范底色 + 54% 遮罩，只用于呈现弹窗层级关系，**不代表首页真实内容**；本需求不改首页。
7. **欢迎图复用既有素材**：需求只新增按钮，不新增主视觉；hero 与既有弹窗完全一致，未重画、未改色，避免引入与本需求无关的视觉变更。
8. **不设计 AI 配置编辑页**：PRD H-8 明确目标页复用现有页面，本稿不含该页；点击后的预设（Base URL / 主模型）属于既有页面能力，不在设计范围。

## 8. 自查与出图说明

- **几何**：`design/boxes.json` 由渲染器量出，8 帧均无内容盒超出画布或父容器；两按钮的盒（280×48 / 240×48 / 560×48）互不重叠，间距 8；F07 的 hero 标记 `clipped: true` 是因为它按设计进入滚动视口（视口 184），不是溢出缺陷；footer 完整落在弹窗内。
- **帧独立性**：每个「页面 × 状态」一个 SVG / PNG，未拼图；F01–F08 与 `layouts.json` 一一对应。
- **改动区域**：老页面（既有欢迎弹窗），`changeScope = component`；改动区 = 弹窗底部按钮区 / 图片降级 / 滚动视口，背景为占位。F08 为「无弹窗」整帧占位。
- **重跑记录**：改动帧结构、按钮样式、间距后均重新执行渲染 + 栅格化，当前 `design/svg`、`design/boxes.json`、`design-images` 为同一次输入的最新产物。
- **出图工具说明（重要）**：本回合的 `<skillAssets>` 未提供绝对路径，且在可访问目录中未找到设计卡指定的 `svggen.cjs` / `svg2png.cjs`（`Get-ChildItem` 全盘常见目录均无结果）。为不中断交付，在需求目录 `.render/` 下复刻了同一条管线：
  - `.render/svggen.cjs`：读取 `design/layouts.json`，按 designTokens 自动排版，输出 `design/svg/*.svg` + `design/boxes.json`；坐标全部由脚本计算，**没有手写任何设计坐标**；支持 `variants` 自动派生（F03/F04/F05 只写主帧树）。
  - `.render/svg2png.cjs`：用 `@resvg/resvg-js` 对同一份 SVG 做栅格化（scale=3、整帧背景），替代沙箱内无法启动的 Chrome 无头模式。
  - 两者均不写入项目源码 / 配置；若编排要求必须使用自带脚本，请在提供 `<skillAssets>` 路径后重跑同一份 `layouts.json`，预期帧结构与几何不变（本机字体度量可能带来 ±1 行的差异）。
- **未改动项目**：只在需求目录内写 `design/`、`design-images/`、`.render/` 与本说明；主仓库源码、资源、配置均未修改（hero 素材为只读复制）。
