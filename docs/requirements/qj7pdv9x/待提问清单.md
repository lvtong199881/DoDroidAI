# 待提问清单 —— 欢迎弹窗右上角关闭按钮

## 一、背景与现状

- 欢迎弹窗实现在 `flutter_app/lib/widgets/welcome_dialog.dart`：一次性模态，结构为「2:1 贴边欢迎图 → 居中标题/副标题 → 底部固定『开始使用』按钮」；欢迎图加载失败或资源缺失时会整块折叠。
- 现有关闭方式只有底部「开始使用」和系统返回键；遮罩点击不关闭（`barrierDismissible: false`）。
- 一次性门控在展示**之前**就写入「已展示」标记（`WelcomeController`），所以无论用户怎么关闭，本次之后默认都不再展示。
- 关闭日志为 `welcome_dismissed method=button|back`，`method` 是 `welcome_contract.dart` 里声明为稳定的日志契约。
- 现有 UI 测试断言「欢迎弹窗没有右上角关闭按钮（`Icons.close`）」，本需求会改掉这条断言。
- 输入未提供参照截图，按新页面处理：视觉样式（圆形底、颜色、阴影、图标线宽等）由设计阶段产出。本清单只澄清会改变**范围 / 验收 / 数据契约 / 用户可见行为**的疑点。

## 二、待提问

### Q1. 「卡在边缘」具体指哪一种几何位置？

**问题**：右上角关闭按钮和弹窗矩形的关系，需要一句可验收的定义。是圆心压在弹窗角上、露一半在弹窗外，还是整体在弹窗内贴边，还是整个悬在弹窗外？

**会改变什么**：验收标准里按钮与弹窗边界的相对位置；是否允许按钮超出弹窗矩形；弹窗裁切与点击命中区域的实现结构（当前 `Dialog` 使用 `Clip.antiAlias`，超出弹窗的部分会被裁掉，需要另行处理）。

**选项**：
- A. 按钮圆心落在弹窗右上角，约一半露出弹窗外，露出的部分同样可点击。【推荐】
- B. 按钮整体在弹窗内，外侧边缘与弹窗的上边/右边对齐，不露出。
- C. 按钮整体在弹窗外侧，与弹窗边缘留一段间距。

**推荐答案**：A。最贴近「卡在边缘」的字面效果，也能一眼看出是独立于内容的关闭操作。

### Q2. 点 X 关闭后，下次启动还展示欢迎弹窗吗？

**问题**：X 是否与底部「开始使用」等价，关闭即视为用户已看过欢迎内容、永久不再展示？还是只关闭本次、下次冷启动仍出现？

**会改变什么**：用户可见行为；是否要新增「本次会话已关闭」状态；是否要改动现有「展示前写一次性标记」的门控逻辑；验收与回归范围。

**选项**：
- A. 与「开始使用」等价，关闭后不再展示，沿用现有一次性标记。【推荐】
- B. 只关闭本次，下次冷启动仍展示，需要新增会话级「本次已关闭」状态并调整现有标记写入口径。

**推荐答案**：A。现有弹窗本来就是一次性展示，新增关闭按钮不改变门控语义。

### Q3. 点 X 是否算一种独立的关闭方式写进日志？

**问题**：现有 `welcome_dismissed` 只区分 `method=button`（开始使用）和 `method=back`（系统返回）。新增的 X 是否需要单独取值？

**会改变什么**：日志/数据契约（枚举新增或复用）；监测里能否区分「看完主动开始」与「点 X 关闭」；测试与验收的日志断言。

**选项**：
- A. 新增 `method=close_button`，与 `button`、`back` 并列。【推荐】
- B. 归入 `method=button`，不区分关闭入口。
- C. 不动 `welcome_dismissed`，另发一条独立事件。

**推荐答案**：A。加一个取值成本低，后续能看出用户是点 X 还是点主按钮离开。

### Q4. 欢迎图缺失 / 加载失败时，关闭按钮放在哪？

**问题**：欢迎图会整块折叠（现有错误分支），弹窗顶部只剩标题区。此时「卡在弹窗右上角」的按钮应该保持原位、收进弹窗内，还是隐藏？

**会改变什么**：异常状态下的用户可见位置；是否需要为按钮预留内容顶部空间以避免压住标题/副标题；布局实现与对应验收项。

**选项**：
- A. 仍固定在弹窗右上角，保持同样的「卡边」效果，内容区顶部为按钮预留空间，不压住标题。【推荐】
- B. 仍在右上角，但完全收进弹窗内，不做露出效果。
- C. 无欢迎图时隐藏关闭按钮，只保留底部「开始使用」。

**推荐答案**：A。关闭能力不应依赖装饰图是否加载成功。

### Q5. 内容滚动时（小屏 / 2 倍字号），按钮跟着内容滚还是钉住？

**问题**：弹窗内容超高时，欢迎图和文字在滚动区内滚动，底部主按钮固定。右上角 X 应该一直钉在弹窗角上，还是随内容一起滚走？

**会改变什么**：小屏 / 大字号下的用户可见行为；按钮归属滚动区还是弹窗固定层；滚动相关的验收与测试。

**选项**：
- A. 钉在弹窗右上角，不随内容滚动，任何滚动位置都能点到。【推荐】
- B. 随内容滚动，滚出可视区后暂时不可见。

**推荐答案**：A。关闭是兜底操作，不应因滚动而消失。

## 三、由需求与现状直接确定（不单独提问）

- 只改欢迎弹窗，其它弹窗、其它页面不动。
- 保留底部「开始使用」按钮；需求是「增加」一个 X，不替换主按钮。
- 点 X 立即关闭弹窗，不弹二次确认。
- 文案中英双语；图标按钮需要读屏用的「关闭 / Close」。
- 视觉样式（形状、底色、阴影、图标粗细、深浅色处理）由设计阶段按新页面产出，本清单不预设；但需保证在浅色、深色欢迎图上都清晰可辨。

## 四、默认采用（不单独提问，定稿时按此写）

- 按钮触摸目标 ≥ 48dp；视觉图标可以小于该尺寸。
- 连点保护沿用现有 `_closing` 逻辑：一次展示只 pop 一次。
- 系统返回键、遮罩点击、主按钮的现有行为不变。
