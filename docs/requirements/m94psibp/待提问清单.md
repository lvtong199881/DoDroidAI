# 待提问清单（reqId: m94psibp）

> 需求原文：给 DoDroidAI APP 的欢迎弹窗主按钮「开始使用」左侧加一个向右箭头的图标，点击行为不变，仍然关闭弹窗进入主界面。
>
> 本清单只列会改变**范围 / 验收 / 架构 / 数据契约 / 用户可见行为**的疑点。用户未回答的，需求定稿时按「推荐答案」转为采用假设并写入 PRD。
>
> 澄清阶段（回合 A）不产出需求卡片与 PRD。

## 已核对事实（无需回答，仅作为提问背景）

- 目标弹窗为 `flutter_app/lib/widgets/welcome_dialog.dart` 中的一次性欢迎弹窗，当前底部只有一个全宽主按钮，文案 key 为 `welcomeStart`（中文「开始使用」/ 英文「Get started」）。
- 现有关闭路径：主按钮、系统返回键；主按钮回调为 `_close(WelcomeDismissMethod.button)`，只是 `pop` 关闭弹窗，落在弹窗下方的首页上。加图标不改变该回调。
- 应用当前仅支持 `zh` / `en` 两种文案，无 RTL 语言；箭头图标不涉及文案翻译。
- 该弹窗已有「最大字号 / 320dp 窄屏不溢出」的既有设计约束，本次新增图标不得破坏。

## 待提问清单

### Q1 本需求是「只给按钮加箭头」，还是「欢迎弹窗整体按新页面重做」？

- **问题**：输入里注明「没有参照截图，按新页面处理」。这是指仅缺少参考图、设计需为这一处「带箭头的按钮」新出视觉说明，还是要求把欢迎弹窗整体重新设计（结构、文案、配图、按钮样式都可能变）？
- **会改变什么**：需求范围（只改按钮 vs 重做整个弹窗）、验收基准（以现有弹窗为基线 vs 以新设计稿为准）、设计/开发/测试工作量，以及是否需要为本需求新增 REQ。
- **推荐答案**：只加箭头。弹窗结构、标题、导语、三条卖点、配图与关闭逻辑都不变；「按新页面处理」仅表示没有参考截图，设计需为「带箭头的按钮」新出视觉说明。
- **备选**：整体重做欢迎弹窗（范围显著扩大，需要额外的设计稿与验收基准）。

### Q2 箭头放在按钮内部、文字左侧，还是按钮整体左侧（按钮外）？

- **问题**：「主按钮『开始使用』左侧」有两种落法：箭头在按钮内部、紧贴文字左边；或箭头在按钮外部、位于按钮整体左边。
- **会改变什么**：用户可见布局、按钮点击区域（点箭头是否等同点按钮）、验收标准的判定位置、设计稿结构。
- **推荐答案**：放在按钮内部、文字左侧；箭头与文字同属一个点击区域，点击箭头与点击按钮完全等效，仍关闭弹窗。
- **备选**：按钮外左侧（则需另行定义箭头的点击行为与视觉归属）。

### Q3 箭头图标用什么素材/风格？

- **问题**：需求只写「向右箭头」，且没有参考截图或图标素材。使用 Material 图标体系（如实心 `arrow_forward`），还是细线 `chevron_right`，或使用用户指定的素材？尺寸、与文字的间距和颜色是否跟随按钮现有前景色？
- **会改变什么**：用户可见外观、设计说明、截图验收口径；若引入外部素材还涉及资源文件与授权。
- **推荐答案**：使用 Material 图标体系内的右向箭头（`arrow_forward`），不引入外部素材；尺寸、间距、颜色跟随按钮现有文字规格（同色、垂直居中），具体值由设计说明固化。
- **备选**：细线 `chevron_right`；或由用户提供指定素材/设计稿。

### Q4 新增箭头是否要被读屏软件单独朗读？

- **问题**：箭头对 TalkBack 是纯装饰（不单独朗读，按钮的可访问名称仍为「开始使用 / Get started」），还是需要朗读成「向右箭头，开始使用」之类的完整语义？
- **会改变什么**：读屏用户听到的内容、无障碍验收口径、是否需要给图标补充语义标签。
- **推荐答案**：纯装饰，不单独朗读；按钮的可访问名称保持「开始使用 / Get started」不变。
- **备选**：朗读包含箭头语义（需确定具体朗读文案）。
